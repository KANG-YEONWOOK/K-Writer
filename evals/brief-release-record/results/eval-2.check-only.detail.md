# K-Writer 0.5.0 write, brief 스킬 추가와 short 모드 삭제 요약

K-Writer 0.5.0은 글을 쓰는 write 스킬과 자료를 요약하는 brief 스킬을 추가하고 techblog의 short 모드를 삭제했습니다. 두 스킬을 요청한 사용자는 write를 K-Writer의 기본 스킬로, 다른 스킬은 글의 목적, 문체, 구성을 미리 정해 둔 스킬로 설명했습니다. short 모드로 쓰던 짧은 글은 앞으로 brief로 씁니다.

- write는 자료나 주제가 없으면 먼저 요청하고 목적, 분량, 어투 중 요청에 없는 값을 한 번에 묻습니다. write는 본문이 공백 제외 1,500자 이상이면 독립 점검을 모두 subagent에 맡기고, 그보다 짧으면 독자 점검과 한국어 문장 점검만 맡깁니다.
- brief는 분량(한 줄, 한 문단, 자세히)과 어투만 묻고 요약을 대화에 출력합니다. brief를 `-o`와 함께 호출하면 요약을 파일에도 저장합니다.
- short 모드를 삭제하면서 `short.md`, `short` 인자, lint의 `--source`와 `--terms`, 원문 대조 항목 F1~F8을 함께 삭제했습니다.
- core의 어투에 해라체(Plain)와 사용자가 직접 정한 어투를 추가했습니다. 어느 어투의 글이든 합니다체 초안의 종결부만 바꿔서 만듭니다.
- write와 brief는 기준 글 표본이 없어서 lint에서 특정 표현의 빈도를 세는 항목 15개의 기준치를 techblog에서 가져왔습니다.

`lint_ko.py`의 short 모드 코드는 앞에서 정의한 정규식 `INLINE_CODE_RE`와 `URL_RE`를 다시 정의하고 있었습니다. 실행할 때는 뒤의 정의가 사용됐으므로 short 모드 코드를 삭제하면서 앞의 정의를 뒤의 정의와 같게 맞췄습니다. 예시 글, eval 글, 평가 기록의 글 34개에 삭제 전후의 lint를 실행한 출력 68개에서 달라진 부분은 G4.off_tone 항목의 수정 방향 문구 한 줄뿐이었고 항목의 값과 판정은 같았습니다.

스킬 문서를 작성하지 않은 subagent에게 문서만 주고 요청을 실행하게 한 테스트에서 brief 1차 실행은 영어 엔지니어링 노트를 5문장 590자로 요약했습니다. 당시 brief 문서는 기본 독자를 분야 지식이 없을 수 있는 사람으로 정해서 용어마다 설명이 붙었습니다. 독립 점검 단계에서도 독자 점검의 질문마다 설명이 추가돼 요약이 469자에서 630자로 늘었습니다. 기본 독자를 자료가 대상으로 삼은 독자와 같은 수준의 사람으로 바꾸고 분량을 글자 수 범위로 정한 뒤 2차 실행은 4문장 296자였습니다. write 2차 실행의 글에는 "저희"와 해라체가 함께 쓰인 문장이 6개 있어서 조직을 주어로 쓸 때 "우리 팀은"이나 조직 이름을 쓰도록 genre.md, drafting.md, tone.md를 수정했습니다. `revise_ko.py`를 검토한 subagent는 `check`와 `audit`가 `lint_ko.py --short`의 짧은 글 기준을 적용하지 않는 것을 찾았고, 두 명령에 `--short`가 추가됐습니다.

`claude plugin eval`과 dogfood는 실행하지 않았고 새 eval 케이스 4개는 작성만 했습니다. 테스트 실행은 설정마다 한 번만 했고 "저희" 규칙처럼 2차 실행 뒤에 수정한 내용은 다시 실행해 확인하지 않았습니다. write와 brief 문서가 정한 글의 구성과 분량 범위는 측정하지 않고 정했고, techblog에서 가져온 기준치 15개는 기술 블로그 글에서 측정한 값입니다.
