K-Writer는 0.5.0에서 write와 brief 스킬을 추가했고, 이 버전은 단위 테스트를 통과했지만 eval로 품질을 측정하지는 않았습니다. 0.5.0 커밋(99ff1d4, 11월 11일)은 origin/main에 반영돼 있고 작업 트리에 수정한 파일은 없습니다. 오늘 실행한 단위 테스트 210개는 모두 통과했고 `sync_core.py --check`와 `borrow_thresholds.py --check`도 통과했습니다.

0.5.0에서 바꾼 것은 다음과 같습니다.

- write 스킬은 자료나 주제, 목적, 분량, 어투를 사용자에게 받아 글을 쓰고 요청에 없는 값은 글을 쓰기 전에 묻습니다.
- brief 스킬은 분량(한 줄, 한 문단, 자세히)과 어투만 묻고 요약을 대화로 출력하며 `-o`가 있으면 파일에도 저장합니다.
- techblog의 short 모드를 삭제했고 짧은 글 기준은 core의 `rules.json`으로 옮겼습니다. `lint_ko.py`와 `revise_ko.py`가 `--short` 옵션으로 이 기준을 적용합니다.
- 어투에 Plain(해라체)과 사용자가 직접 정한 어투를 추가했습니다.
- write와 brief는 사람 글 표본이 없어서 특정 표현의 빈도를 세는 항목 15개의 기준치를 techblog에서 가져와 사용합니다.

subagent에게 스킬 문서만 주고 실행한 테스트에서 brief의 영어 노트 한 문단 요약은 1차 590자, 2차 296자였고 한 문단의 분량 범위는 150~300자입니다. 1차 요약이 길어진 원인은 기본 독자를 분야 지식이 없는 사람으로 정한 것과 독립 점검이 독자 점검에서 나온 질문마다 설명을 추가한 것이었습니다. 그래서 기본 독자와 독립 점검 방식을 수정했습니다.

아직 확인하지 않은 것과 남은 일은 다음과 같습니다.

- `claude plugin eval`과 dogfood를 실행하지 않았고 새 eval 케이스 4개는 작성만 했습니다.
- 2차 테스트 뒤에 수정한 내용 세 가지는 다시 실행해 확인하지 않았습니다.
- AskUserQuestion으로 설정을 묻는 흐름은 테스트에서 실행하지 못했습니다.
- write와 brief의 구성과 분량 범위는 측정값이 아니라 정한 값입니다.
- lint는 해라체 글에 섞인 반말 종결을 검출하지 못합니다.
- `calibration.md`에는 삭제한 F1~F8 항목의 행이 남아 있습니다.

0.5.0 커밋에는 `.DS_Store`가 포함됐고 커밋 메시지는 이전 커밋의 "K-Writer 0.4.1: ..." 형식과 달리 "fix: 0.5.0"입니다.
