# K-Writer 0.5.0 write, brief 스킬 추가와 short 모드 삭제 요약

K-Writer 0.5.0은 write와 brief 스킬을 추가하고 techblog의 short 모드를 삭제했습니다. 짧은 글은 이제 short 모드 대신 요약 스킬인 brief로 작성합니다. write는 글의 목적, 문체, 구성을 미리 정해 두지 않은 기본 스킬이고 자료나 주제, 목적, 분량, 어투를 사용자에게 받아 글을 씁니다. 두 스킬의 동작은 스킬 문서를 작성하지 않은 subagent에게 스킬 문서만 주고 요청을 실행하게 한 테스트 실행으로만 확인했습니다. claude plugin eval과 dogfood는 실행하지 않았습니다.

- write는 목적, 분량, 어투 중 요청에 없는 값을 한 번에 묻습니다. 본문이 공백 제외 1,500자 이상이면 독립 점검 네 가지를 모두 subagent에게 맡기고 그보다 짧으면 독자 점검과 한국어 문장 점검만 맡깁니다.
- brief는 분량(한 줄, 한 문단, 자세히)과 어투만 묻고 `-o`가 있으면 요약을 파일에도 저장합니다.
- core의 어투에 Plain(해라체)과 사용자가 직접 정한 어투를 추가했습니다. 어느 어투든 합니다체 초안의 종결부만 바꿔 만듭니다.
- write와 brief에는 기준 글 표본이 없어서 특정 표현의 빈도를 세는 항목 15개의 기준치는 techblog의 값을 가져왔습니다. 문장 길이, 문단, 목록 비중 같은 분포 항목은 가져오지 않았습니다.

`lint_ko.py`의 short 모드 코드는 파일 앞부분에서 정의한 정규식 `INLINE_CODE_RE`와 `URL_RE`를 다시 정의하고 있었습니다. short 모드 코드를 삭제하면서 앞부분의 정의를 실행 때 사용되던 short 모드 코드의 정의와 같게 맞췄습니다. 예시 글, eval 글, 평가 기록의 글 34개 파일에 수정 전후 lint를 실행한 출력 68개에서 항목의 값과 판정은 모두 같았습니다. `python -m unittest discover -s tests`로 실행한 테스트 210개도 모두 통과했습니다.

테스트 실행은 1차 실행 뒤 문서를 수정하고 2차 실행을 하는 순서로 했습니다. 영어 엔지니어링 노트를 한 문단으로 요약한 brief의 글은 1차 590자에서 2차 296자로 줄었습니다. 1차 실행 때의 brief 문서는 기본 독자를 techblog처럼 자료 분야의 지식이 없을 수 있는 사람으로 정해서 요약의 용어마다 설명이 붙었습니다. 독립 점검에서도 독자 점검에서 나온 질문마다 설명을 추가해 469자가 630자가 됐습니다. 그래서 기본 독자를 자료가 대상으로 삼은 독자와 같은 수준의 사람으로 바꾸고 분량을 넘기지 않게 글자 수 범위로 정했습니다. write 2차 글에는 "저희"와 Plain 종결이 함께 쓰인 문장이 6개 있었습니다. 조직을 주어로 쓸 때는 "우리 팀은"이나 조직 이름을 쓰도록 genre.md, drafting.md, tone.md를 수정했습니다.

테스트 실행은 자료와 요청의 조합마다 한 번씩만 했고 2차 실행 뒤에 추가한 "저희" 규칙은 다시 실행해 확인하지 않았습니다. AskUserQuestion으로 분량과 어투 같은 설정을 묻는 흐름도 실행하지 못했습니다. write와 brief의 구성과 분량 범위는 측정해서 정한 값이 아닙니다. lint는 Plain 글에 섞인 반말 종결을 검출하지 못합니다.
