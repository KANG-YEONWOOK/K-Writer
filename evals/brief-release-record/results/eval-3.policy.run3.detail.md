# K-Writer 0.5.0 write, brief 스킬 추가와 short 모드 삭제 요약

K-Writer 0.5.0에서는 write 스킬과 brief 스킬을 추가하고 techblog의 short 모드를 삭제했습니다. write 스킬은 자료나 주제, 목적, 분량, 어투를 받아 글을 쓰고, brief 스킬은 자료를 한국어로 요약합니다. short 모드를 삭제한 대신 짧은 글은 brief 스킬로 작성하기로 했습니다. 이 작업을 요청한 사용자는 write 스킬이 기본 스킬이고 다른 스킬은 글의 목적, 문체, 구성을 미리 정해 둔 스킬이라고 설명했습니다.

- write 스킬은 자료나 주제가 없으면 먼저 요청하고, 목적과 분량, 어투 중 요청에 없는 값을 한 번에 묻습니다. 목적의 선택지는 설명, 설득, 안내, 기록이고 사용자가 직접 입력할 수도 있습니다.
- brief 스킬은 분량(한 줄, 한 문단, 자세히)과 어투만 묻고 `-o`가 있으면 요약을 파일에도 저장합니다.
- techblog에서는 `short.md`, `short` 인자, lint의 `--source`와 `--terms` 옵션, 원문 대조 항목 F1~F8을 삭제했습니다.
- core의 어투 선택지에 Plain(해라체)과 사용자가 직접 정한 어투를 추가했습니다. 어느 어투로 쓴 글이든 합니다체 초안의 종결부만 바꿔서 만듭니다.
- 짧은 글에 적용하는 검사 기준은 core의 `rules.json`으로 옮겼고 `lint_ko.py --short`와 `revise_ko.py`의 `check --short`, `audit --short`가 이 기준을 적용합니다.
- 기준 글 표본이 없는 write와 brief 스킬에는 특정 표현의 빈도를 세는 항목 15개의 기준치를 techblog에서 가져왔습니다. 문장 길이, 문단, 목록 비중 같은 분포 항목의 기준치는 가져오지 않았습니다.

short 모드 코드를 삭제하기 전과 후의 lint를 예시 글, eval 글, 평가 기록의 글 34개 파일에 `--tone default`와 `--tone casual`로 각각 실행했습니다. 수정 전과 수정 후의 출력 68개는 항목의 값과 판정이 모두 같았습니다. 스킬 문서만 받은 subagent가 실행한 테스트에서 영어 엔지니어링 노트를 한 문단으로 요약한 결과는 1차 실행의 590자에서 스킬 문서를 수정한 뒤 2차 실행의 296자로 줄었습니다. 1차 요약이 길어진 원인은 두 가지였습니다. 기본 독자를 분야 지식이 없을 수 있는 사람으로 정해서 용어마다 설명이 붙었고, 독자 점검에서 나온 질문마다 독립 점검이 설명을 추가했습니다. 그래서 기본 독자를 자료가 대상으로 삼은 독자와 같은 수준의 사람으로 바꿨습니다. 독립 점검은 요약만 읽는 subagent가 멈춘 부분을 보고하면 상위 agent가 분량 안에서 수정하는 방식으로 바꿨습니다. 검토를 맡은 다른 subagent는 lint를 통과한 요약이 `revise_ko.py check`에서 FAIL로 판정되는 것을 찾았습니다. 원인은 `check`와 `audit`가 짧은 글 기준을 적용하지 않는 것이었고, 두 명령에 `--short`를 추가했습니다. 단위 테스트 210개가 통과했습니다.

`claude plugin eval`과 dogfood는 실행하지 않았고 새 eval 케이스 4개는 작성만 했습니다. subagent의 테스트 실행은 설정마다 한 번이었습니다. 2차 실행 뒤에 수정한 내용은 다시 실행해 확인하지 않았습니다. 조직을 주어로 쓸 때 "저희" 대신 "우리 팀은"이나 조직 이름을 쓰게 한 규칙이 그중 하나입니다. AskUserQuestion으로 분량과 어투 같은 설정을 묻는 흐름도 실행해 보지 못했습니다.
