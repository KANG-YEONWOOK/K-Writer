# K-Writer 0.5.0 write, brief 스킬 추가와 short 모드 삭제 요약

K-Writer 0.5.0은 자료나 주제, 목적, 분량, 어투를 사용자에게 받아 글을 쓰는 write 스킬과 요약 스킬 brief를 추가하고 techblog의 short 모드를 삭제했습니다. 두 스킬을 요청한 사용자는 write가 기본 스킬이고 다른 스킬은 글의 목적, 문체, 구성을 미리 정한 스킬이라고 설명했습니다. 짧은 글은 short 모드 대신 brief로 작성합니다.

- write는 자료나 주제가 없으면 먼저 요청하고, 목적(설명, 설득, 안내, 기록, 직접 입력), 분량, 어투 중 요청에 없는 값을 한 번에 묻습니다.
- write는 본문이 공백 제외 1,500자 이상이면 독립 점검을 모두 subagent에 맡기고, 미만이면 독자 점검과 한국어 문장 점검만 맡깁니다.
- brief는 분량(한 줄, 한 문단, 자세히)과 어투만 묻고, `-o`가 있으면 요약을 파일에도 저장합니다.
- short 모드와 함께 `short.md`, `short` 인자, lint의 `--source`와 `--terms`, 원문 대조 항목 F1~F8을 삭제했습니다.
- core의 어투에 해라체(Plain)와 사용자가 직접 정한 어투를 추가했고, 어느 어투든 합니다체 초안의 종결부만 바꿔 만듭니다.
- `lint_ko.py --short`와 `revise_ko.py`의 `check --short`, `audit --short`는 core의 `rules.json`에 둔 짧은 글 기준을 적용합니다.
- write와 brief에는 기준 글 표본이 없어서 특정 표현의 빈도를 세는 lint 항목 15개의 기준치는 techblog의 값을 가져왔습니다.

short 모드 코드를 삭제하기 전과 후에 파일 34개에 lint를 `--tone default`와 `--tone casual`로 실행했습니다. 출력 68개에서 달라진 것은 G4.off_tone의 수정 방향 문구 한 줄뿐이었고 항목의 값과 판정은 모두 같았습니다. 단위 테스트 210개와 `claude plugin validate .`도 통과했습니다.

문서 작성에 참여하지 않은 subagent가 스킬 문서만 받아 요청을 실행한 테스트에서, 영어 엔지니어링 노트를 한 문단으로 요약한 brief의 결과는 1차 590자에서 문서를 수정한 뒤의 2차 296자로 줄었습니다. 1차 요약이 길어진 원인은 기본 독자를 분야 지식이 없을 수 있는 사람으로 정해 용어마다 설명이 붙은 것과 독립 점검이 독자 점검의 질문마다 설명을 추가한 것이었습니다. 그래서 기본 독자를 자료가 대상으로 삼은 독자와 같은 수준의 사람으로 바꿨습니다. 검토를 맡은 다른 subagent는 `revise_ko.py`의 `check`와 `audit`가 짧은 글 기준을 적용하지 않아 `lint_ko.py --short`와 판정이 다르다는 것을 찾았습니다. 두 명령에는 `--short`를 추가했습니다. write 2차 실행의 글에는 "저희"와 해라체가 함께 쓰인 문장이 6개 있었습니다. 그래서 조직을 주어로 쓸 때 "우리 팀은"이나 조직 이름을 쓰도록 genre.md, drafting.md, tone.md를 수정했습니다.

`claude plugin eval`과 dogfood는 실행하지 않았고 새 eval 케이스 4개는 작성만 했습니다. subagent 테스트는 설정마다 한 번만 실행했고, 2차 실행 뒤에 수정한 내용은 "저희" 규칙을 포함해 다시 실행해 확인하지 않았습니다. AskUserQuestion으로 사용자에게 설정값을 묻는 흐름과 대화에서 자료나 주제를 요청하는 흐름도 실행해 보지 못했습니다. lint는 해라체 글에 섞인 반말 종결을 검출하지 못합니다.
