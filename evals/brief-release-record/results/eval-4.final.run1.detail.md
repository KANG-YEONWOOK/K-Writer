# K-Writer 0.5.0 write, brief 스킬 추가와 short 모드 삭제 요약

K-Writer 0.5.0은 기본 글쓰기 스킬 write와 요약 스킬 brief를 추가하고 techblog의 short 모드를 삭제했습니다. write는 자료나 주제, 목적, 분량, 어투를 사용자에게 받아 글을 씁니다. 짧은 글은 short 모드 대신 brief로 작성합니다.

- write는 자료나 주제가 없으면 먼저 요청하고 목적(설명, 설득, 안내, 기록, 직접 입력), 분량, 어투 중 요청에 없는 값을 한 번에 묻습니다. 본문이 공백 제외 1,500자 미만이면 독립 점검 중 독자 점검과 한국어 문장 점검만 subagent에게 맡기고, 1,500자 이상이면 독립 점검을 모두 맡깁니다.
- brief는 분량(한 줄, 한 문단, 자세히)과 어투만 묻습니다. brief는 요약을 대화로 답하고 `-o` 인자가 있으면 파일에도 저장합니다.
- short 모드와 함께 `short.md`, techblog의 `short` 인자, `lint_ko.py`의 `--source`와 `--terms`, 원문 대조 항목 F1~F8을 삭제했습니다. 짧은 글 기준은 core의 `rules.json`으로 옮겼고 `lint_ko.py --short`와 `revise_ko.py`의 `check --short`, `audit --short`가 이 기준을 적용합니다.
- core의 어투에 해라체(Plain)와 사용자가 직접 정한 어투를 추가했습니다. 어느 어투의 글이든 합니다체 초안의 종결부만 바꿔서 만듭니다.
- write와 brief는 기준 글 표본이 없어서 부정 대구나 번역투도 판정하지 못합니다. 그래서 특정 표현의 빈도를 세는 항목 15개의 기준치를 techblog에서 가져왔고, 문장 길이, 문단, 목록 비중 같은 분포 항목의 기준치는 가져오지 않았습니다.

스킬 문서를 작성하지 않은 subagent가 스킬 문서만 받아 사용자 요청을 실행하는 테스트 실행을 했고, 1차 실행 뒤 문서를 수정해 2차 실행을 했습니다. brief로 영어 엔지니어링 노트를 한 문단으로 요약한 결과는 1차 590자에서 2차 296자로 줄었습니다. 1차 요약이 길어진 원인 하나는 기본 독자를 분야 지식이 없을 수 있는 사람으로 정해 용어마다 설명이 붙은 것이었습니다. 또 독립 점검이 독자 점검에서 나온 질문마다 설명을 추가해 요약이 469자에서 630자로 늘었습니다. 그래서 기본 독자를 자료가 대상으로 삼은 독자와 같은 수준의 사람으로 바꿨습니다. 독립 점검에서는 요약만 읽는 subagent가 읽다가 멈춘 부분을 보고하고 상위 agent가 분량 안에서 수정합니다.

검토를 맡은 subagent는 `revise_ko.py`의 `check`와 `audit`가 짧은 글 기준을 적용하지 않아 `lint_ko.py --short`와 판정이 다른 것을 찾았습니다. 그래서 두 명령에 `--short`를 추가했습니다. write 2차 실행의 글에는 "저희"와 해라체가 함께 쓰인 문장이 6개 있었습니다. 조직을 주어로 쓸 때는 "우리 팀은"이나 조직의 이름을 쓰도록 genre.md, drafting.md, tone.md를 수정했습니다. 테스트 210개와 `claude plugin validate .`는 통과했습니다.

`claude plugin eval`과 dogfood는 실행하지 않았고 write와 brief의 새 eval 케이스 4개는 작성만 했습니다. 테스트 실행은 설정마다 한 번이고, 2차 실행 뒤 수정한 "저희" 규칙은 다시 실행해 확인하지 않았습니다. 테스트 실행은 subagent 안에서 해서 AskUserQuestion으로 설정을 묻는 흐름과 대화에서 자료나 주제를 요청하는 흐름은 실행해 보지 못했습니다.
