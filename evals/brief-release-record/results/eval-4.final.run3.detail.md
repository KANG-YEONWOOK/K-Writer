# K-Writer 0.5.0 write, brief 스킬 추가와 short 모드 삭제 요약

K-Writer 0.5.0에서는 자료나 주제, 목적, 분량, 어투를 받아 글을 쓰는 기본 스킬 write와 요약 스킬 brief를 추가했습니다. techblog의 short 모드는 삭제했고 짧은 글은 brief로 작성합니다. 단위 테스트 210개가 통과했지만 claude plugin eval과 dogfood는 실행하지 않았습니다.

## 바꾼 것

- write는 자료나 주제가 없으면 먼저 요청하고 목적, 분량, 어투 중 빠진 값을 한 번에 묻습니다. 본문이 공백 제외 1,500자 미만이면 subagent에게 맡기는 독립 점검을 독자 점검과 한국어 문장 점검으로 줄입니다.
- brief는 분량(한 줄, 한 문단, 자세히)과 어투만 묻고 `-o`가 있으면 파일에도 요약을 저장합니다.
- short 모드와 함께 `short.md`, `lint_ko.py`의 `--source`와 `--terms` 옵션과 원문 대조 항목 F1~F8을 삭제했습니다. 짧은 글 기준은 core의 `rules.json`으로 옮겼고 `lint_ko.py --short`가 이 기준을 적용합니다.
- core의 어투에 Plain(해라체)과 사용자가 직접 정한 어투를 추가했습니다. 다른 어투의 글은 합니다체 초안의 종결부만 바꿔서 만듭니다.
- write와 brief에는 기준 글 표본이 없어서 특정 표현의 빈도를 세는 lint 항목 15개의 기준치를 techblog에서 가져왔습니다.
- settings-protocol.md에 "반드시 받는 값"을 추가해 자료나 주제를 받지 못하면 작업을 시작하지 않게 했습니다.

## 확인한 것

short 모드 코드를 삭제하기 전후로 예시 글, eval 글, 평가 기록의 글 34개에 `lint_ko.py`를 실행했습니다. 출력 68개에서 수정 방향 문구를 수정한 G4.off_tone 한 줄만 달랐고 항목의 값과 판정은 같았습니다.

스킬 문서만 받은 subagent에게 사용자 요청을 실행하게 하는 테스트 실행도 두 번 했습니다. 영어 노트를 한 문단, 합니다체로 요약한 brief 결과는 1차 5문장 590자에서 2차 4문장 296자로 줄었습니다. 1차 요약이 길어진 원인은 기본 독자를 "자료 분야의 지식이 없을 수 있는 사람"으로 정한 것과 독자 점검이 낸 질문마다 설명이 추가된 것이었습니다. 그래서 brief의 기본 독자를 "자료가 대상으로 삼은 독자와 같은 수준의 사람"으로 바꿨습니다.

감사를 맡은 subagent는 `revise_ko.py`의 `check`와 `audit`가 짧은 글 기준을 적용하지 않는 것을 찾았습니다. 그 뒤 두 명령에 `--short`를 추가했습니다. write 2차 글에는 "저희"와 해라체 종결이 함께 쓰인 문장이 6개 있어서 조직이 주어일 때 "우리 팀은"이나 조직 이름을 사용하도록 genre.md, drafting.md, tone.md를 수정했습니다.

## 한계

- write와 brief의 새 eval 케이스 4개는 작성만 했고 스킬 없이 쓴 글이나 사람이 쓴 글과 비교한 결과가 없습니다.
- 2차 실행 뒤에 추가한 "저희" 규칙은 다시 실행해 확인하지 않았습니다.
- 테스트 실행을 subagent 안에서 해서 AskUserQuestion으로 설정을 묻는 흐름은 실행해 보지 못했습니다.
- techblog에서 가져온 기준치 15개는 기술 블로그 글에서 측정한 값이고 Plain 종결의 분포는 측정하지 않았습니다.
- lint는 해라체 글에 섞인 반말 종결을 명사로 분류해서 검출하지 못합니다.
