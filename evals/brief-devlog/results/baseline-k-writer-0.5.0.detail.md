10월 21일에 검색 서비스 2.4를 배포한 뒤 1주 동안 자동완성 API의 p95 응답 시간은 배포 전 1주의 180ms에서 45ms로 줄었습니다. 같은 기간 자동완성 캐시 적중률은 62%에서 91%로 올랐습니다. 다만 2차 부하 테스트에서 캐시 서버 한 대가 재시작된 뒤 수정한 내용은 아직 다시 부하 테스트하지 않았습니다.

검색팀이 2.4에서 바꾼 것은 다음과 같습니다.

- 자동완성 API에서 인기 검색어 상위 1,000개의 응답은 캐시 만료 시간이 60초에서 10분으로 늘었고, 나머지 검색어는 60초를 유지합니다.
- 캐시 서버를 2대에서 3대로 늘렸습니다.
- 오타 교정은 사전 기반 규칙 대신 편집 거리 2 이하인 후보를 점수로 선택합니다. 점수는 최근 30일 검색 횟수와 클릭률로 계산합니다.
- 검색 로그의 보관 기간은 9월 개인정보 검토에서 나온 의견을 반영해 90일에서 30일로 줄였습니다.
- "결과 없음" 화면에는 추천 검색어 3개를 추가했습니다.
- 자동완성 API의 p95 응답 시간이 5분 동안 200ms를 넘으면 담당자에게 알림을 보내도록 응답 시간 경보를 설정했습니다.

배포 전 1주(10월 14일~20일)와 배포 후 1주(10월 21일~27일)를 비교하면 "결과 없음" 화면 비율은 4.8%에서 3.1%로 줄었습니다. 검색 뒤 첫 클릭까지 걸린 시간의 중앙값은 6.2초에서 5.9초로 줄었지만 차이 0.3초는 주간 변동 범위인 ±0.4초 안입니다. 사람이 확인한 오타 교정 결과 표본 500건 중 23건은 교정이 틀렸고, 틀린 23건 중 17건은 상품 이름을 일반 단어로 바꾼 경우였습니다.

10월 16일에 초당 2,000건으로 실행한 1차 부하 테스트에서는 오류가 없었고 p95 응답 시간은 52ms였습니다. 10월 19일에 초당 5,000건으로 실행한 2차 부하 테스트에서는 캐시 서버 한 대가 메모리 한도인 16GB에 도달해 재시작됐고, 재시작하는 4분 동안 p95 응답 시간이 900ms까지 올랐습니다. 2차 부하 테스트 뒤에는 캐시 항목 하나의 크기 상한을 4KB로 정하고 만료 시각을 항목마다 최대 60초씩 다르게 설정했습니다. 캐시 서버가 재시작되면 담당자에게 알림을 보내는 기능도 추가했습니다.

자동완성 캐시의 만료 시간과 대상 범위는 측정해서 정한 값이 아니고 10월 2일 운영팀 회의에서 정했습니다. 응답 시간 경보의 임계값도 측정하지 않고 결제 서비스의 값을 가져왔습니다. 오타 교정 오류를 확인한 표본은 한국어 질의만 포함하고, 영어와 숫자가 섞인 질의는 확인하지 않았습니다. 추천 모델은 최근 60일 로그로 학습하는데 검색 로그의 보관 기간을 30일로 줄인 변경이 추천 품질에 주는 영향은 확인하지 않았습니다. 추천 검색어를 누른 비율은 아직 집계하지 않았습니다.

한서진 님은 2차 부하 테스트 뒤에 수정한 세 가지를 포함해 초당 5,000건 부하 테스트를 11월 6일까지 다시 실행합니다. 오민재 님은 상품 이름을 교정 대상에서 제외하는 목록을 11월 13일까지 만듭니다. 캐시 만료 시간을 5분, 10분, 20분으로 바꿔 가며 적중률과 응답 시간을 측정하는 일은 아직 담당자와 일정이 정해지지 않았습니다.
