10월 21일에 배포한 검색 서비스 2.4는 인기 검색어 상위 1,000개의 자동완성 API 응답 캐시 만료 시간을 60초에서 10분으로 늘렸고 나머지 검색어의 만료 시간은 60초로 유지했습니다. 자동완성 API의 p95 응답 시간은 배포 전 1주의 180ms에서 배포 후 1주의 45ms로 줄었고, 자동완성 캐시 적중률은 62%에서 91%로 올랐습니다. 만료 시간 10분과 대상 범위인 상위 1,000개는 측정한 값이 아니고 10월 2일 운영팀 회의에서 정한 값입니다.

2.4는 자동완성 캐시 만료 시간 외에도 아래 다섯 가지를 바꿨습니다.

- 캐시 서버는 2대에서 3대로 늘었습니다.
- 오타 교정은 사전 기반 규칙에서 편집 거리 2 이하인 후보를 점수로 선택하는 방식으로 바뀌었습니다. 점수는 최근 30일 검색 횟수와 클릭률로 계산합니다.
- 검색 로그 보관 기간은 9월 개인정보 검토에서 나온 의견을 반영해 90일에서 30일로 줄었습니다.
- 검색 결과가 없을 때 보여 주는 "결과 없음" 화면에 추천 검색어 3개가 추가됐습니다.
- 자동완성 API의 p95 응답 시간이 5분 동안 200ms를 넘으면 담당자에게 알림을 보내는 경보가 추가됐습니다.

배포 전 1주(10월 14일~20일)와 배포 후 1주(10월 21일~27일)를 비교한 결과 "결과 없음" 화면 비율은 4.8%에서 3.1%로 줄었습니다. 검색 뒤 첫 클릭까지 걸린 시간의 중앙값은 6.2초에서 5.9초로 0.3초 줄었지만, 이 차이는 주간 변동 범위인 ±0.4초 안에 있습니다. 새 오타 교정의 결과 표본 500건을 사람이 확인했고 그중 23건은 교정이 틀렸습니다. 틀린 23건 중 17건은 상품 이름을 일반 단어로 바꾼 경우였습니다.

10월 16일에 초당 2,000건으로 한 부하 테스트에서는 오류가 없었고 p95 응답 시간은 52ms였습니다. 10월 19일에 초당 5,000건으로 한 부하 테스트에서는 캐시 서버 한 대가 메모리 한도 16GB에 도달해 재시작됐고, 재시작하는 4분 동안 p95 응답 시간이 900ms까지 올랐습니다. 검색팀은 그 뒤 캐시 항목 하나의 크기 상한 4KB를 추가하고 만료 시각을 항목마다 최대 60초까지 다르게 설정했으며, 캐시 서버가 재시작되면 담당자에게 알림을 보내게 했습니다. 이 세 가지 수정은 아직 다시 부하 테스트하지 않았고, 한서진 님이 11월 6일까지 이 수정을 포함해 초당 5,000건 부하 테스트를 다시 합니다.

자동완성 응답 시간 경보의 임계값 200ms는 측정한 값이 아니고 결제 서비스의 값을 가져온 것입니다. 오타 교정 결과 표본 500건은 한국어 검색어만 포함하며, 영어와 숫자가 섞인 검색어의 교정 결과는 확인하지 않았습니다. 추천 모델은 최근 60일 로그로 학습하는데, 검색 로그 보관 기간을 30일로 줄인 것이 추천 품질에 주는 영향은 확인하지 않았습니다. "결과 없음" 화면의 추천 검색어를 누른 비율은 아직 집계하지 않았습니다.

오민재 님은 11월 13일까지 상품 이름을 오타 교정 대상에서 제외하는 목록을 만듭니다. 검색팀은 캐시 만료 시간을 5분, 10분, 20분으로 바꿔 가며 적중률과 응답 시간을 측정할 계획이지만 담당자와 일정은 정하지 않았습니다.
