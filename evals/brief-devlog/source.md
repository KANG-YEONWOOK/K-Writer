# 검색 서비스 2.4 개발 기록 (2026-10-28)

검색팀이 2.4에서 바꾼 것, 배포 전후에 확인한 것, 아직 확인하지 못한 것을 적는다. 2.4는 10월 21일에 배포했다.

## 바꾼 것

- 자동완성 API의 캐시 만료 시간을 60초에서 10분으로 늘렸다. 대상은 인기 검색어 상위 1,000개의 응답이다. 나머지 검색어는 60초를 유지한다.
- 캐시 서버를 2대에서 3대로 늘렸다.
- 오타 교정을 사전 기반 규칙에서 편집 거리 2 이하인 후보를 점수로 선택하는 방식으로 바꿨다. 점수는 최근 30일 검색 횟수와 클릭률로 계산한다.
- 검색 로그의 보관 기간을 90일에서 30일로 줄였다. 9월 개인정보 검토에서 나온 의견을 반영했다.
- 검색 결과가 없을 때 보여 주는 "결과 없음" 화면에 추천 검색어 3개를 추가했다.
- 응답 시간 경보의 임계값을 추가했다. 자동완성 API의 p95 응답 시간이 5분 동안 200ms를 넘으면 담당자에게 알림을 보낸다.

## 확인한 것

### 배포 전후 비교

배포 전 1주(10/14~10/20)와 배포 후 1주(10/21~10/27)의 값을 비교했다.

| 지표 | 배포 전 | 배포 후 |
|---|---|---|
| 자동완성 API p95 응답 시간 | 180ms | 45ms |
| 자동완성 캐시 적중률 | 62% | 91% |
| "결과 없음" 화면 비율 | 4.8% | 3.1% |
| 검색 뒤 첫 클릭까지 걸린 시간(중앙값) | 6.2초 | 5.9초 |

- 첫 클릭까지 걸린 시간의 차이 0.3초는 주간 변동 범위(±0.4초) 안이다.
- 오타 교정 결과 표본 500건을 사람이 확인했다. 23건은 교정이 틀렸다. 틀린 23건 중 17건은 상품 이름을 일반 단어로 바꾼 경우였다.

### 부하 테스트

- 1차(10/16, 초당 2,000건): 오류 없음. p95 응답 시간 52ms.
- 2차(10/19, 초당 5,000건): 캐시 서버 한 대가 메모리 한도(16GB)에 도달해 재시작됐다. 재시작하는 4분 동안 p95 응답 시간이 900ms까지 올랐다.
- 2차 뒤에 세 가지를 수정했다. 캐시 항목 하나의 크기 상한(4KB) 추가, 만료 시각을 항목마다 최대 60초씩 다르게 설정, 캐시 서버가 재시작되면 담당자에게 알림 전송.

## 한계

- 2차 테스트 뒤에 수정한 내용은 다시 부하 테스트하지 않았다.
- 만료 시간과 대상 범위는 측정값이 아니다. 10월 2일 운영팀 회의에서 정했다.
- 경보 임계값도 결제 서비스의 값을 가져온 것이다.
- 교정 오류 표본은 한국어 질의뿐이다. 영어와 숫자가 섞인 질의는 확인하지 않았다.
- 로그 보관 기간 변경이 추천 품질에 주는 영향은 확인하지 않았다. 추천 모델은 최근 60일 로그로 학습한다.
- 추천 검색어를 누른 비율은 아직 집계하지 않았다.

## 다음 할 일

- 수정한 세 가지를 포함해 초당 5,000건 부하 테스트를 다시 한다. 담당 한서진, 11/6까지.
- 상품 이름을 교정 대상에서 제외하는 목록을 만든다. 담당 오민재, 11/13까지.
- 만료 시간을 5분, 10분, 20분으로 바꿔 가며 적중률과 응답 시간을 측정한다. 담당자와 일정은 정하지 않았다.
