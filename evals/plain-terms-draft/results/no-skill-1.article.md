# 노트북 약 4,000대의 동기화 에이전트를 Python에서 Rust로 옮긴 기록

> 이 글은 글쓰기 평가용으로 작성된 가상의 사내 노트를 바탕으로 합니다. 글에 나오는 수치와 결과는 실제 사례가 아니므로 인용하지 마시기 바랍니다.

회사 노트북 약 4,000대에는 동기화 에이전트가 설치되어 있습니다. 2023년부터 운영해 온 Python 버전은 유휴 상태에서 메모리를 210MB 사용했고, 시작하는 데 1.9초가 걸렸습니다. 그래서 팀은 3월에 Rust 버전 개발을 시작했습니다.

노트북 500대에서 2주 동안 측정해 보니 메모리 사용량은 38MB로, 시작 시간은 0.3초로 줄었습니다. 그렇다고 전환이 끝난 것은 아닙니다. 약 120대는 아직 Python 버전을 쓰고 있고, 네트워크 드라이브에서는 아무도 Rust 버전을 테스트하지 않았습니다.

## 두 버전을 함께 배포한 6주

6주 동안 설치 프로그램은 두 버전을 함께 배포했습니다. 1.8은 마지막 Python 버전이고, 2.0은 첫 Rust 버전입니다. 두 버전은 같은 설정 파일을 읽기 때문에, 노트북을 Rust 버전으로 옮겼다가 Python 버전으로 되돌려도 설정이 사라지지 않았습니다.

Rust 버전은 시작할 때 레지스트리에서 설치된 버전 번호를 읽고, 설치된 버전이 1.6보다 오래되었으면 실행을 거부합니다.

설치 프로그램은 새 바이너리 옆에 기존 바이너리 사본을 남겨 둡니다. 그래서 이전 버전으로 되돌리는 데 40초면 되고, 따로 내려받을 것도 없습니다.

최신 버전은 항상 업데이트 서버에 게시합니다. 패치 버전은 2.0.3처럼 세 번째 숫자만 바꿉니다.

## 테스트로 드러난 버그 22개

테스트 스위트에는 테스트가 1,240개 있습니다. 첫 Rust 빌드에서는 이 중 31개가 실패했습니다. 9개는 Python 버전에서도 실패하던 테스트라 회귀가 아니었고, 나머지 22개가 실제 버그였습니다.

가장 심각한 버그는 파일 감시기에서 나왔습니다. 사용자가 폴더 이름을 바꾸면 Rust 버전은 그 뒤로 폴더 안에서 일어나는 변경을 전부 놓쳤습니다. 이 버그는 2.0.3에서 수정했고, 지금은 테스트 스위트가 폴더 이름 변경 경로까지 검증합니다. 반면 네트워크 드라이브는 아직 테스트 범위에 들어 있지 않습니다.

## 파일 감시 라이브러리 비교

파일 감시 라이브러리를 비교할 때는 Lee et al. (2024)의 벤치마크를 사용했습니다. 벤치마크에 포함된 라이브러리 12개 중 Windows 정션을 지원하는 것은 3개입니다.

이 논문은 감시 대상 수와 메모리 사용량의 상관계수를 r = 0.91로 보고합니다. 감시 대상이 많을수록 메모리 사용량도 커지는 경향이 뚜렷하다는 뜻입니다. arXiv 판과 IEEE 출판본은 수식 번호가 서로 달라서, 사내 노트에서는 출판본 번호를 따랐습니다.

## 설계 문서 정리

설계 문서 첫 초안은 잠금 동작 방식을 잘못 설명하고 있었습니다. 그래서 두 번째 판에서는 그 절을 삭제했습니다. 검토자들은 현재 문서와 HEAD 커밋의 문서를 비교하며 검토했습니다.

초안에서는 "sync"나 "commit" 같은 단어가 두 가지 뜻으로 쓰였습니다. 저자들은 단어마다 뜻을 하나만 남기고, 모든 용어에 짧은 정의를 붙였습니다. 이 점검은 절마다 반복했고, 부록은 대상에서 제외했습니다.

## 측정 결과

Rust 버전을 노트북 500대에서 2주 동안 측정했습니다.

| 항목 | Python 버전 | Rust 버전 |
|---|---|---|
| 유휴 상태 메모리 사용량 | 210MB | 38MB |
| 시작 시간 | 1.9초 | 0.3초 |
| 동기화 1회당 로그 | 약 40줄 | 1줄 |

메모리 사용량은 약 82%, 시작 시간은 약 84% 줄었습니다.

## 남은 문제

약 120대는 아직 Python 버전을 쓰고 있습니다. 보안 도구가 Rust 바이너리를 차단하기 때문입니다.

Rust 버전이 네트워크 드라이브에서 Python 버전과 똑같이 동작하는지도 아직 모릅니다. 테스트 스위트가 이 경우를 다루지 않고, 직접 시험해 본 사람도 없습니다.

전환이 끝날 때까지는 팀이 두 버전을 모두 책임집니다.
