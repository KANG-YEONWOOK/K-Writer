메모의 사실은 다음과 같다.

- 13:50에 인스턴스마다 DB connection pool의 최댓값을 50에서 200으로 올리는 설정 변경을 배포했다. 인스턴스는 12개다.
- 14:10에 checkout API의 p99 latency가 180 ms에서 2,400 ms로 늘었고 알림이 발생했다.
- 14:25에 당직 엔지니어 Mina Park이 데이터베이스가 연결 한도 2,000개에 도달해 새 연결을 거부하는 것을 확인했다.
- 14:58에 설정을 50으로 되돌렸고 15:02에 p99 latency가 190 ms가 됐다.
- 영향: 52분 동안 결제가 지연됐고 그동안 결제 요청의 3.8%가 실패했다(평소 0.2%).

- 후속 조치 1: pool 최댓값 x 인스턴스 수가 DB 한도의 80% 아래인지 확인하는 배포 검사를 추가한다. 담당 Jisoo Han, 기한 2026-11-21.
- 후속 조치 2: DB 연결 한도를 올릴지는 아직 정하지 않았고 2026-11-14에 논의한다.
