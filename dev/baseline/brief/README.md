# brief 사람 글 표본: 논문 초록

이 폴더에는 사람이 쓴 요약의 표본으로 KCI(한국학술지인용색인) 논문의 한국어 초록을 `lint_ko.py`로 측정한 값을 저장한다. 초록은 저자가 자기 논문을 한 문단으로 요약한 글이다. 원문은 커밋하지 않고 논문 ID와 URL 목록(`urls.json`), 측정값(`stats.json`)만 저장소에 유지한다. 이 표본은 brief의 규칙과 검사 항목을 사람이 쓴 요약과 대조하는 데 사용하고, brief의 기준치(`skills/brief/scripts/thresholds.json`)를 보정하는 데는 사용하지 않는다. 이유는 아래 "한계"에 있다.

## 측정 범위 (2026-11-11)

`measure.py collect`로 초록 1,206편을 수집하고 `measure.py measure`로 모두 측정했다.

- 출처: KCI의 OAI-PMH(`https://open.kci.go.kr/oai/request`, `oai_kci` 형식). OAI-PMH는 서지 정보를 날짜 범위로 받아 가는 공개 프로토콜이고 KCI는 인증 키를 요구하지 않는다. KCI의 공개 데이터 안내 페이지는 공공누리 출처표시 조건으로 이용할 수 있다고 안내한다. 이 이용 조건이 저자가 쓴 초록 본문에도 적용되는지는 확인하지 못해서 원문은 저장소에 추가하지 않았다. 원문 cache는 gitignore 대상인 `docs/corpus/kci/`에 있다.
- 요청: `ListRecords`에 `from`과 `until`을 같은 날짜로 지정하면 그날 등록되거나 수정된 레코드를 100건까지 반환한다. 처음에는 2018-03-01부터 3일 간격으로 받았는데 40일치를 받는 동안 조건에 맞는 초록이 3편뿐이어서 중단했다. 그다음 2019-03-04부터 4일 간격으로 249일치(마지막 날짜 2021-11-20)를 받았다. 수집 로그의 마지막 줄은 `249 requests, 14406 records, 1206 kept, 321 journals`다. 처음 받은 3편은 cache에 남아 있어서 1,206편에 포함된다. 요청은 1초에 한 번 보냈다.
- 포함 조건: 논문 언어가 한국어이고, 원문 언어 초록(`abstract lang="original"`)의 한글이 200자 이상이며 한글과 영문 글자 중 한글이 70% 이상이고, 발행 연도(`pub-year`)가 2018~2021년인 초록이다. techblog 표본의 기준 기간은 ChatGPT가 공개되기 전인 2018-01-01~2022-11-30이다. 레코드에 발행 월(`pub-mon`)도 있지만 이번 수집에서는 연도만 확인해서 2022년 초록을 모두 제외했다.
- 학술지 하나에서 5편까지만 받았다. 표본은 학술지 321종, KCI 분류 70개의 초록이다. 초록이 많은 분류는 법학 117편, 교육학 103편, 역사학 76편, 한국어와문학 64편, 경영학 59편이다.
- 발행 연도는 2018년 83편, 2019년 218편, 2020년 594편, 2021년 311편이다.
- 목표는 1,200편이었다. 목표를 넘은 날짜의 레코드까지 받아서 1,206편이 됐다.
- 1,206편 모두 해라체 종결이 90% 이상이었다.

## 결과

아래 값은 `measure.py summary`가 출력한다. 본문은 661,491자(공백 제외), 10,337문장이다.

| 값 | p5 | p25 | 중앙값 | p75 | p95 |
|---|---|---|---|---|---|
| 초록의 본문 글자 수(공백 제외) | 294 | 410 | 512 | 648 | 929 |
| 초록의 문장 수 | 4 | 6 | 8 | 10 | 15 |
| 문장의 글자 수(공백 제외) | 26 | 43 | 59 | 79 | 119 |
| 문장의 글자 수(공백 포함) | 32 | 55 | 75 | 101 | 150 |

- 공백을 포함해 120자를 넘는 문장은 10,337문장 중 1,392문장(13.5%)이다.
- 공백 제외 59자(문장 길이의 중앙값)인 문장 3~5개는 177~295자다. brief의 한 문단 분량(3~5문장, 150~300자)은 사람이 쓴 문장 3~5개의 길이와 비슷하다. 0.5.0에서는 개발자가 이 범위를 사람 글과 대조하지 않고 정했다.
- 대조한 것은 문장 하나의 길이뿐이다. 초록 한 편은 중앙값이 512자, 8문장이어서 brief의 한 문단 요약보다 길다. 300자 이하인 초록은 전체의 5%쯤이다.

### 바꾼 내용을 밝히지 않고 바꿨다고만 쓴 문장과 부정 대구

사용자는 2026-11-11에 brief가 개발 기록을 요약한 글의 "write와 brief의 구성과 분량 범위는 측정값이 아니라 정한 값입니다"를 읽고 무엇을 어떻게 정했다는 것인지 알 수 없다고 했다. 같은 요약에 "수정한 내용 세 가지는", "방식을 수정했습니다"도 있었다. 세 형태가 사람이 쓴 요약에 얼마나 나오는지 측정했다.

| 항목 | 초록 1,206편(661,491자) | 1,000자당 | 0.5.0 최종 요약 3편(2,302자) | 1,000자당 |
|---|---|---|---|---|
| A18.category_change(바꾼 내용을 밝히지 않고 바꿨다고만 쓴 문장) | 3문장 | 0.0045 | 3문장 | 1.3 |
| A18.count_only(개수만 쓰고 항목을 쓰지 않은 문장) | 1문장 | 0.0015 | 1문장 | 0.43 |
| A18.value_kind(측정값이 아니라고만 쓰고 그 값을 쓰지 않은 문장) | 0문장 | 0 | 2문장 | 0.87 |
| A18.value_kind_check(값의 종류만 쓰고 그 값을 쓰지 않은 문장) | 0문장 | 0 | 0문장 | 0 |
| A1.np(부정 대구) | 164문장, 135편(11.2%) | 0.248 | 1문장 | 0.43 |

- 0.5.0 최종 요약 3편은 0.5.0의 brief가 쓴 글이다. 한 편은 사용자가 받은 저장소 상태 요약(861자)이고 자료는 git 기록, README, `EVALUATION.md`의 0.5.0 섹션, 테스트 결과였다. 나머지 두 편은 그 0.5.0 섹션만 자료로 주고 `claude -p`에서 brief를 다시 실행해 받은 자세한 요약(1,153자)과 한 문단 요약(288자)이다. 세 요약은 `evals/brief-release-record/results/`에 있다.
- 세 요약에서 A18.category_change로 검출된 문장은 "그래서 기본 독자와 독립 점검 방식을 수정했습니다", "2차 테스트 뒤에 수정한 내용 세 가지는 다시 실행해 확인하지 않았습니다", "테스트 실행을 마친 뒤에 수정한 내용은 다시 테스트하지 않았습니다"다. 둘째 문장은 A18.count_only로도 검출됐다. A18.value_kind로 검출된 문장은 사용자가 지적한 문장과, 다시 실행한 자세한 요약의 "write와 brief의 구성과 분량 범위는 측정해서 정한 값이 아니고 techblog에서 가져온 기준치는 기술 블로그 글에서 측정한 값입니다"다. A1.np로 검출된 문장도 사용자가 지적한 문장이다.
- A18.value_kind는 초록 1,206편과 기술 블로그 사람 글 368편에서 한 번도 검출되지 않아서 policy 항목(한 번만 나와도 FAIL)으로 분류했다. "임시로 정한 값입니다", "추정치입니다"처럼 넓은 형태(A18.value_kind_check)는 2025년 이후 기술 블로그 글 186편 중 1편에 있어서 점검 후보로 분류했다. 두 항목 모두 그 구절 앞에 숫자나 인라인 코드가 있는 문장은 세지 않는다.
- 초록에서 A18.category_change로 검출된 3문장의 구절은 "사용방식이 변경되었다", "구조를 바꾸고", "부분을 개선하고"다.
- 부정 대구는 350자 이하인 초록 164편 중 9편(5.5%)에 있었다. 사람이 쓴 요약에도 나오는 형태라서 한 번을 FAIL로 판정하지 않고, 짧은 글 기준에서 점검 후보(`A1.np_check`)로 출력한다.
- 초록은 무엇을 바꿨다고 전하는 일이 드문 글이다. 그래서 이 값은 "논문 초록에는 이런 문장이 드물다"는 것까지만 뒷받침한다. 기술 블로그 사람 글에서 측정한 값은 [techblog/README.md](../techblog/README.md)의 "바꾼 내용을 밝히지 않고 바꿨다고만 쓴 문장" 섹션에 있다.

### brief의 짧은 글 기준으로 판정한 통과율

brief의 `thresholds.json`과 core의 짧은 글 기준(`rules.json`의 `short`)으로 초록을 판정했다. PASS는 FAIL이 없고 WARN이 2개 이하인 초록이다. policy 항목(문장 부호, 숫자 뒤 조사처럼 스킬 출력에만 적용하는 규칙. [dev/baseline/README.md](../README.md))은 사람 글 검증에서 제외했다.

| 초록의 길이(공백 제외) | 편수 | PASS | 통과율 |
|---|---|---|---|
| 350자 이하 | 164 | 145 | 88.4% |
| 351~600자 | 650 | 495 | 76.2% |
| 601~900자 | 320 | 192 | 60.0% |
| 901자 이상 | 72 | 26 | 36.1% |
| 전체 | 1,206 | 858 | 71.1% |

| 항목 | WARN | FAIL |
|---|---|---|
| A13.demonstrative_start_per_1k(지시어로 시작하는 문장) | 351편(29.1%) | 136편(11.3%) |
| A5.style_words_per_1k(과사용 어휘) | 253편(21.0%) | 90편(7.5%) |
| A14.translationese_per_1k(번역투) | 155편(12.9%) | 71편(5.9%) |
| A12.progressive_per_1k("~되고 있다") | 43편(3.6%) | 16편(1.3%) |

- 350자는 한 문단 요약의 상한 300자에 가까운 길이로 정한 경계다. 이 길이 이하인 초록의 통과율은 88.4%다.
- 초록이 길수록 통과율이 낮다. 짧은 글 기준은 위 표의 네 항목을 글 길이와 관계없이 개수로 판정하기 때문이다.
- 논문 ID의 sha1 해시를 5로 나눈 나머지가 0인 252편(holdout)만 판정하면 172편(68.3%)이 PASS다. 이 표본으로 기준치를 보정하지 않았으므로 holdout과 나머지의 통과율은 비슷하다.
- 검출된 표현은 대부분 학술 초록에서 흔히 사용하는 표현이다. 지시어로 시작하는 문장 651개 중 첫 어절이 "이러한"인 문장이 308개, "이를"이 165개, "이는"이 114개였다. 과사용 어휘 468개 중 "시사점"이 109개, "시사하다"의 활용형이 62개였다. 번역투 327개 중 "~에 의해", "~에 의한", "~에 의하여"가 197개였다.

### 해라체 종결 분포

`measure.py endings`는 "~다"로 끝난 문장의 종결을 정규식으로 분류한다. 초록 1,206편에서 "~다"로 끝난 문장은 10,258개다. techblog 표본에서 기준 기간의 해라체 글 57편("~다"로 끝난 5,870문장)도 같은 방법으로 분류했다.

| 종결 | 초록 1,206편 | 해라체 기술 블로그 글 57편 |
|---|---|---|
| 과거형(~었다, ~했다) | 4,540문장(44.3%) | 1,178문장(20.1%) |
| 현재형 동사(~ㄴ다, ~는다) | 2,289문장(22.3%) | 2,045문장(34.8%) |
| ~있다, ~없다 | 1,117문장(10.9%) | 457문장(7.8%) |
| ~이다, ~아니다 | 815문장(7.9%) | 601문장(10.2%) |
| ~것이다 | 559문장(5.4%) | 160문장(2.7%) |
| 형용사(~하다, ~않다, ~같다) | 464문장(4.5%) | 471문장(8.0%) |
| ~수 있다, ~수 없다 | 397문장(3.9%) | 732문장(12.5%) |
| 그 밖의 ~다 | 77문장(0.8%) | 226문장(3.9%) |

- 초록에는 과거형이 가장 많고 기술 블로그 글에는 현재형 동사가 가장 많다.
- 두 분포는 `core/references/tone.md`의 "Plain 종결(해라체)"에 참고값으로 추가했다. lint는 Plain 종결의 비율을 판정하지 않는다.
- 형태소 분석기 없이 마지막 어절의 형태로 분류했으므로 잘못 분류한 문장이 있을 수 있다.

## 한계

- 표본은 학술 논문의 초록뿐이다. 초록에는 "본 연구는", "이러한 결과는"으로 시작하고 "시사점을 제시한다"로 끝나는 문장이 흔하다. brief의 요약은 자료를 소개하는 말 없이 결론부터 쓰고, K-Writer는 "시사하다"를 과사용 어휘로 다룬다. 그래서 이 표본으로 brief의 기준치를 보정하지 않았다. 통과율 표는 지금 기준으로 사람이 쓴 초록의 29%가 통과하지 못한다는 기록이다.
- 표본은 모두 해라체다. 합니다체와 해요체로 쓴 사람 요약은 측정하지 않았다.
- 초록은 저자가 자기 글을 요약한 글이다. brief는 다른 사람이 쓴 자료를 요약하는 경우가 많다.
- 회의록, 개발 기록, 공지를 사람이 요약한 글은 표본에 없다. 사용자가 지적한 문장은 개발 기록의 요약에서 나왔다.
- 학술지마다 5편으로 제한했지만 분류별 편수는 제한하지 않았다. 법학과 교육학 초록이 220편(18%)이다.
- 한 줄 요약과 자세한 요약의 분량 범위는 이 표본으로 대조할 수 없다.

## 재현

```bash
python -I -X utf8 dev/baseline/brief/measure.py collect --cache docs/corpus/kci --start 2019-03-04 --step 4 --target 1200
python -I -X utf8 dev/baseline/brief/measure.py measure --cache docs/corpus/kci
python -I -X utf8 dev/baseline/brief/measure.py summary
python -I -X utf8 dev/baseline/brief/measure.py endings --cache docs/corpus/kci --techblog-cache docs/corpus/techblog
```

- `collect`는 KCI에 등록된 날짜 순서로 초록을 받으므로 KCI가 레코드를 수정하면 같은 명령으로도 다른 초록을 받을 수 있다. 측정한 초록의 ID는 `urls.json`에 있다.
- 요청의 User-Agent는 환경 변수 `BASELINE_USER_AGENT`로 바꿀 수 있다.
