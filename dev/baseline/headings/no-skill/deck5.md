## 코드 리뷰 문화 개선 방안
### 리뷰 대기 시간을 줄이고 리뷰 품질을 높이기 위한 제안
- 대상: 개발팀 전원 12명
- 배경: 리뷰 대기가 길어져 배포 일정이 밀리는 사례 증가
- 제안: 작은 PR, 응답 시간 약속, 코멘트 규칙 세 가지
- 오늘 결정할 것: 12주 시범 운영 여부

## 현재 상황
### 최근 3개월 PR 412건을 보면 리뷰가 병목이다
- 첫 리뷰까지 평균 26시간 대기
- PR 생성부터 머지까지 평균 3.4일
- PR 1건당 평균 변경량 620줄
- 전체 리뷰의 58%를 상위 3명이 담당

## 원인
### 느린 리뷰는 개인 문제가 아니라 구조 문제다
- PR이 커서 한 번에 읽기 어렵고 리뷰가 뒤로 밀림
- 리뷰 시간이 일정에 잡혀 있지 않아 본인 작업에 밀림
- 리뷰어 지정 기준이 없어 특정 인원에게 요청이 몰림
- 스타일 지적과 설계 지적이 섞여 논의가 길어짐

## 목표
### 12주 뒤 네 가지 지표로 효과를 확인한다
- 첫 리뷰 대기: 26시간 → 8시간 이내
- 머지까지 걸리는 시간: 3.4일 → 1.5일
- PR 평균 변경량: 620줄 → 300줄 이하
- 상위 3명 리뷰 비중: 58% → 40% 이하

## 방안 1: PR을 작게 만든다
### 400줄이 넘으면 나눠서 올린다
- PR 1건 변경량은 400줄 이하 권장, 초과 시 사유를 설명에 기재
- PR 템플릿 도입: 변경 목적, 테스트 방법, 중점 확인 사항
- 포맷과 린트는 CI에서 자동 검사하고 리뷰에서는 다루지 않음
- 큰 기능은 설계를 먼저 합의한 뒤 단계별 PR로 분할

## 방안 2: 리뷰 응답을 약속한다
### 요청받은 리뷰는 업무 시간 8시간 안에 첫 응답을 한다
- 첫 응답은 승인, 코멘트, 일정 안내 중 하나면 충분
- 리뷰어 자동 순환 배정으로 편중 해소
- 매일 오전 10시~11시를 리뷰 집중 시간으로 지정
- 24시간 넘게 대기 중인 PR은 팀 채널에 자동 알림

## 방안 3: 코멘트 방식을 맞춘다
### 반드시 고칠 것과 의견을 구분해서 쓴다
- 코멘트 앞에 구분 표기: [필수], [제안], [질문]
- 지적에는 이유와 대안을 함께 작성
- 같은 주제로 코멘트가 3회 이상 오가면 대화로 전환
- 잘한 부분도 코멘트로 남기기

## 실행 계획과 요청 사항
### 12주 시범 운영 후 지표로 정식 도입을 판단한다
- 1~2주: PR 템플릿, CI 자동 검사, 리뷰어 자동 배정 설정
- 3~12주: 전체 팀 적용, 2주마다 회고에서 지표 공유
- 12주 차: 목표 대비 결과를 확인하고 정식 도입 여부 결정
- 요청 사항: 시범 운영 동의, 리뷰 집중 시간 캘린더 등록
