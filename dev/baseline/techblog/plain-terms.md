# 같은 대상을 부르는 말: 사례와 측정 (2026-11-04)

K-Writer 0.4.0의 `A6.version_pan`, `A5.plain_terms`, `A6.metaphor_check`, 한국어 문장 점검 유형 U, style-guide.md의 "같은 대상을 부르는 말"을 만든 근거다. 표의 값은 `dev/baseline/techblog/term_stats.py`로 다시 만들 수 있다.

## 사용자 지적

2026-11-04 사용자는 플러그인 없이 AI에게 글을 쓰게 하면 version을 "판"으로 써서 글이 어색하다고 지적했다. 자연스러운 한국어 글은 version을 그냥 "버전"이라고 쓴다. 사용자는 이 예 말고 같은 종류의 표현이 스킬로 쓴 글에도 나오는지 확인하고, AI 글쓰기 자료에서 사례를 모아 이 플러그인의 글에 나오지 않게 해 달라고 했다. 같은 날 사용자는 "값과 걸린 말을 낸다"의 "낸다"도 지적했다. 프로그램이 값을 보여 주는 일은 "출력한다"로 쓴다.

## 측정 방법

- 사람 글: `stats.json`의 included 글 600편(한글 2,919,971자). 기준 기간 203편, 중간 기간 141편, 2025년 이후 256편이다.
- 스킬 없이 쓴 AI 글: 이 PC의 Claude Code 세션 기록에서 `claude-opus-5-5`의 대화 응답과 Write 도구로 쓴 Markdown을 모았다. dev는 개발 프로젝트의 글(569건, 한글 808,655자), note는 노트 작업 세션의 글(755건, 한글 1,858,021자)이다. K-Writer와 Skill-Techblog 세션은 제외했다. 사용자의 전역 지침이 적용된 글이고, 세션 내용은 저장소에 포함하지 않는다.
- 스킬 글: 0.2.0~0.3.0 dogfood 3편, 예시 글 2편, eval 결과 4편(한글 49,255자).
- 스킬 문서: 0.3.1의 core 문서와 techblog 문서(commit cfd0950). 이 열은 해당 commit의 문서를 꺼내 `--extra`로 지정했다.
- 형태소 분석(Kiwi 0.24)으로 사람 글과 AI 글의 단어 빈도를 비교해 후보를 찾고, 후보를 정규식으로 다시 세었다. 코드, URL, 따옴표 안은 세지 않았다.

```bash
python -I dev/baseline/techblog/term_stats.py --cache docs/corpus --sessions ~/.claude/projects \
    --extra "skill=docs/dogfood/*/*/article.md" --extra "skill=examples/*.default.md" --extra "skill=examples/*.casual.md" \
    --extra "skill=evals/*/results/article.md" --extra "skill=evals/*/results/revised*.md"
```

## 해석

- **"판"**: 사람 글 600편에서 version의 의미로 한 번도 나오지 않았다(책의 판을 포함한 "판" 전체도 4번이다). 스킬 없이 쓴 AI 글에서는 "Python 판", "이전 판", "두 번째 판", "arXiv판", "HEAD 판", "설치된 판 번호", "판을 올리다" 형태로 나왔다. note에서는 "판"(119번)이 "버전"(36번)보다 많았다.
- **스킬 문서가 만든 단어**: "낱말"은 dev에서 0번인데 스킬 문서에 107번, 스킬 글에 29번, 노트 작업 세션에 422번 나왔다. "뜻"은 dev의 비율(0.27)이 사람 글(0.28)과 같은데 스킬 문서는 24.32, 스킬 글은 8.53이었다. "이 가운데", "짝", "세기"도 스킬 글이 dev보다 많았다. 모델은 스킬 문서를 읽은 뒤 글을 쓰므로 문서의 단어 선택이 출력에도 나타났다. 0.4.0은 이 문서들을 먼저 수정했다.
- **스킬 없이 쓴 글의 단어 선택**: dev에서 "결함"은 580번, "버그"는 3번이고 사람 글은 54번과 183번이다. "갱신"과 "업데이트"는 dev 456번과 55번, 사람 글 234번과 580번이다. 같은 대상을 사전의 대응어로 부르는 경향이 사람 글보다 강하다. 다만 결함과 갱신은 사람 글도 사용하는 단어라 lint로 세지 않고 문서의 표와 유형 U에 적었다.

- 초안을 쓰기 전에 읽는 문서(style-guide.md, fact-sheet.md, drafting.md)에는 사용할 표현만 적었다. 수정 전 표현은 초안을 쓴 뒤에 읽는 ai-patterns.md와 korean-review.md에만 적는다. 2026-11-02 측정의 다른 항목과 같은 이유다(Antislop의 금지어 지시 역효과).
- `A5.plain_terms`를 추가한 기준치의 사람 글 통과율: 기준 기간 holdout 31편 중 28편 통과(90%)로 이전과 같다. 이 항목의 FAIL과 WARN은 기준 기간 사람 글에서 0편이다.

## 실행 비교

가상 노트 `evals/plain-terms-draft/source.md`(약 500단어)로 글을 작성했다. 이 노트에는 version, test, bug, word, copy, among, return 같은 단어를 일부러 많이 넣었다. 스킬 없는 글은 `claude -p`에 "한국어 기술 블로그 아티클로 정리해 달라"고만 요청했고, 나머지는 `dev/dogfood/run.py`로 6단계까지 실행했다. 사용자의 CLAUDE.md는 표에 표시한 한 번의 실행에만 적용했다.

- 0.3.1은 스킬 없는 글보다 "낱말"과 "가운데"가 많았다. 스킬 없는 세 글은 "단어"와 "중"을 사용했다.
- 0.3.1의 lint는 "두 번째 판", "낱말"이 있는 최종 글을 PASS로 판정했고, 한국어 문장 점검도 이 표현을 수정하지 않았다. 해당하는 유형이 없었기 때문이다.
- 0.4.0의 fact sheet 용어 표에는 "version | 버전", "copy | 복사본"이 있었다. 초안 단계에서 이미 0건이었으므로 lint가 수정한 결과가 아니라 초안 전에 읽는 문서와 fact sheet의 영향이다. 한국어 문장 점검은 유형 U로 "시험입니다"를 "테스트입니다"로, "내놓아"를 "제공해"로 수정했다.
- X와 Y로 가린 두 글을 다른 agent가 `graders/plain-terms.md`로 채점했다. 자료 표현 22개에서 0.4.0은 어색한 표현 0개, 0.3.1은 5개(두 번째 판, 사본, 낱말과 뜻, 가운데, 돌려줍니다)였고, 음역으로 바꿔 어색해진 표현은 두 글 모두 없었다. 채점 보고는 `evals/plain-terms-draft/results/independent-review.md`에 있다.

규칙을 만들 때 사용하지 않은 자료로도 확인했다. 논문 Boggia(2026)를 `C-epanorthosis-default`로 실행해 초안 단계까지만 확인했다(예산 $6, 실제 $4.95).

- 실행은 설정마다 한 번씩이다. 0.4.0의 논문 실행은 예산 때문에 후처리와 한국어 문장 점검을 마치지 않았다.
- 판정에 반영되지 않는 표현(결함, 돌려주다, 상한)은 문서의 표와 유형 U에만 의존하므로 실행마다 나올 수 있다. 0.4.0 최종 글에는 "반환은 ... 돌려주는 일입니다"(반환을 정의하는 문장), "이 상한은 넘을 수 없습니다"가 남았다.
- 채점자는 0.4.0 글의 "자기를 실행한 코드"를 어색하다고 지적했다. 이후 style-guide.md 표에 call(호출하다)과 section(섹션) 행을 추가했고, 이 두 행을 넣은 버전으로는 다시 실행하지 않았다.
