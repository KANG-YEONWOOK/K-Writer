# 뉴스 기사, 논문 초록, 연설문 구조 주석 지침

배치 파일에는 사람이 쓴 한국어 글이 문단 번호(`[P1]`)와 문장 번호(`S1.`)와 함께 들어 있다. 글의 종류는 뉴스 기사(2013~2015년 한국경제 기사), 논문 초록(2018~2019년 KCI 등재지 국문 초록), 연설문(2003~2019년 대통령 연설문) 중 하나이고 prompt가 알려 준다. 글마다 아래 형식으로 주석을 달아 JSON 파일 하나로 저장한다. 목적은 사람이 쓴 글이 내용을 어떤 순서로 전개하고, 전하려는 바를 어떤 표현으로 전하며, 문장을 어떻게 잇는지를 세는 것이다. 글에 담긴 사실이 지금도 맞는지는 따지지 않는다. 글쓰기 방식과 표현만 본다. 뉴스 기사의 문단 구분은 자동으로 복원한 것이라 일부 틀릴 수 있다.

## 출력 형식

```json
[
 {
  "id": "news-klue-mrc-v1_train_00001",
  "genre": "news",
  "main_point": "이 글이 전하는 핵심(한 문장)",
  "first_sentence": "첫 문장이 하는 일을 한 구절로(예: 누가 무엇을 했는지를 먼저 전함)",
  "last_sentence": "마지막 문장이 하는 일을 한 구절로",
  "sentences": [
   {"s": 1, "move": "핵심 사실", "attaches_to": 0, "relation": "새 내용 시작", "link": ["없음"]},
   {"s": 2, "move": "세부 사실", "attaches_to": 1, "relation": "상세화", "link": ["핵심어 반복"]}
  ],
  "expressions": [
   {"move": "출처 밝히기", "s": 3, "phrase": "~에 따르면"},
   {"move": "결과 보고", "s": 5, "phrase": "~것으로 나타났다"}
  ],
  "off_point": []
 }
]
```

## 항목 설명

- 문장 `move`: 그 문장이 글 전체에서 하는 일 하나. 아래 종류별 목록에서 고른다.
- 문장 `attaches_to`, `relation`, `link`: 수능 지문 지침과 같다. `attaches_to`는 이 문장이 설명, 예시, 근거, 결과, 대조로 붙는 앞 문장의 번호(새 내용을 시작하면 0), `relation`은 그 문장과의 논리 관계, `link`는 앞 문장과 이어져 있음을 알아보게 하는 표현 장치(해당하는 것 모두, 가장 뚜렷한 것 먼저)다.
- `expressions`: 그 글이 어떤 일을 하려고 사용한 정형 표현을 글마다 3~8개 적는다. `phrase`에는 지문의 표현을 20자 이내로, 바뀌는 부분은 "~"로 줄여 적는다. `move`에는 그 표현이 하는 일을 적는다(아래 "표현이 하는 일"에서 고른다).
- `off_point`: 글의 핵심과 관계없는 문장 번호. 없으면 빈 배열.

## 라벨

뉴스 기사의 `move`
- 핵심 사실(리드), 세부 사실, 수치·근거, 관계자 발언, 배경·경위, 원인·분석, 반응·평가, 전망·계획, 비교·사례, 정의·설명

논문 초록의 `move`
- 배경, 문제·필요성, 목적, 방법, 결과, 해석·논의, 결론·의의, 한계·제언

연설문의 `move`
- 호칭·인사, 행사의 의미, 감사·치하, 회고·경과, 현황·성과, 과제·문제, 원칙·가치, 약속·계획, 당부·호소, 맺음

`relation`
- 새 내용 시작, 상세화, 예시, 이유, 결과, 대조, 조건·단서, 다음 단계, 추가, 바꿔 말하기, 정리, 질문에 답함

`link`
- 핵심어 반복, 지시어, 접속어, 바꿔 부르기, 주어 생략, 없음

표현이 하는 일(`expressions`의 `move`)
- 출처 밝히기, 발언 옮기기, 결과 보고, 수치 제시, 원인 설명, 목적 밝히기, 방법 설명, 전망·계획, 평가·의의, 대조, 예시, 정의, 범위·조건, 강조, 전환, 당부·요청, 감사, 다짐

## 작업 방법

1. 글을 처음부터 끝까지 읽고 `main_point`를 정한다.
2. 문장마다 `move`, `attaches_to`, `relation`, `link`를 정한다. 문장을 건너뛰지 않는다. 문장 번호는 배치 파일의 번호를 그대로 사용한다.
3. JSON을 지정된 경로에 저장한 뒤 `python3 -I -c "import json,sys; d=json.load(open(sys.argv[1])); print(len(d), sum(len(x['sentences']) for x in d))" <경로>`로 형식과 문장 수를 확인한다. 배치 파일의 문장 수와 같아야 한다.
4. 같은 폴더에 관찰 기록 파일(`.notes.md`)을 쓴다. 600단어 이내로, 아래 질문에 글 ID와 문장 번호를 근거로 들어 답한다.
   - 글은 무엇으로 시작하는가? 핵심을 어디에서 밝히는가?
   - 내용은 어떤 순서로 이어지는가? 그 종류의 글에 공통된 순서가 있는가?
   - 수치, 인용, 주장, 계획, 원인을 전할 때 각각 어떤 문형과 서술어를 사용하는가?
   - 한 문장에 내용을 얼마나 담는가? 긴 문장은 어떤 구조인가?
   - 문장과 문단은 어떤 장치로 이어지는가?
   - 글은 무엇으로 끝나는가?
   - 줄여 쓴 표현(명사 나열, 조사 생략, 괄호)이 어디에 얼마나 나오는가?
