# 수능 국어 독서 지문 구조 주석 지침

배치 파일에는 대학수학능력시험 국어(언어) 영역의 설명문 지문이 문단 번호(`[P1]`)와 문장 번호(`S1.`)와 함께 들어 있다. 지문마다 아래 형식으로 주석을 달아 JSON 파일 하나로 저장한다. 목적은 잘 쓴 한국어 설명문이 글 전체, 문단, 문장 수준에서 내용을 어떻게 전개하고 문장을 어떻게 잇는지를 세는 것이다. 원문에는 PDF에서 옮기며 생긴 띄어쓰기 오류가 조금 있다. 무시하고 읽는다.

## 출력 형식

배치의 모든 지문을 배열 하나에 담는다. 라벨은 아래 "라벨" 목록의 문자열을 그대로 사용한다. 목록에 없는 라벨을 만들지 않는다.

```json
[
 {
  "id": "csat-2007-000",
  "topic": "글의 화제(명사구)",
  "main_point": "이 글을 읽은 독자가 알게 되는 것(한 문장)",
  "development": ["개념 설명", "사례 적용"],
  "paragraphs": [
   {
    "p": 1,
    "function": "도입",
    "point": "이 문단이 독자에게 전하는 내용(한 문장)",
    "topic_sentence": 3,
    "topic_sentence_position": "last",
    "link_to_prev": "해당 없음",
    "sentences": [
     {"s": 1, "role": "배경 사실", "attaches_to": 0, "relation": "새 내용 시작", "link": ["없음"]},
     {"s": 2, "role": "상세화", "attaches_to": 1, "relation": "결과", "link": ["지시어", "핵심어 반복"]}
    ]
   }
  ],
  "terms": [{"term": "제3자 효과", "s": 8, "how": "현상을 먼저 설명한 뒤 이름 붙임"}],
  "gaps": [{"s": 12, "note": "독자가 스스로 채워야 하는 단계"}],
  "off_point": []
 }
]
```

## 항목 설명

- `development`: 글 전체의 전개 방식. 주된 것 하나를 먼저 적고 필요하면 하나를 더 적는다.
- 문단 `function`: 그 문단이 글 전체에서 하는 일 하나.
- 문단 `point`: 그 문단을 한 문장으로 줄인 내용. 지문의 표현을 사용해 구체적으로 쓴다.
- `topic_sentence`: 문단의 `point`를 가장 직접 말하는 문장 번호. 그런 문장이 없으면 0.
- `topic_sentence_position`: `first`(문단 첫 문장), `second`(둘째 문장), `middle`, `last`(마지막 문장), `none`.
- 문단 `link_to_prev`: 문단 첫 문장이 앞 문단과 이어지는 방식 하나. 첫 문단은 "해당 없음".
- 문장 `role`: 그 문장이 문단 안에서 하는 일 하나.
- 문장 `attaches_to`: 이 문장이 설명, 예시, 근거, 결과, 대조로 붙는 앞 문장의 번호. 대부분 바로 앞 문장이다. 문단의 새 내용을 시작하는 문장이면 0.
- 문장 `relation`: `attaches_to`의 문장과 이 문장의 논리 관계 하나.
- 문장 `link`: 이 문장이 앞 문장과 이어져 있음을 독자가 알아보게 하는 표현 장치. 해당하는 것을 모두 적고 가장 뚜렷한 것을 먼저 적는다. 문단의 첫 문장은 앞 문단의 마지막 문장을 기준으로 적는다. 글의 첫 문장은 ["없음"].
- `terms`: 지문이 독자에게 새로 알려 주는 용어와 그 용어를 처음 설명한 문장 번호, 설명 방식.
- `gaps`: 앞 문장에서 뒤 문장으로 넘어갈 때 독자가 스스로 채워야 하는 추론 단계나 설명되지 않은 용어가 있는 곳. 없으면 빈 배열. 억지로 찾지 않는다.
- `off_point`: 문단의 `point`를 설명하지도 뒷받침하지도 않는 문장 번호. 없으면 빈 배열.

## 라벨

`development`
- 개념 설명, 원리·과정 설명, 분류·유형 설명, 비교·대조, 시간 순 변화, 문제와 해결, 주장과 근거, 견해 소개와 비판, 사례 적용

문단 `function`
- 도입, 개념 정의, 배경·기존 견해, 문제 제기, 원리·과정, 구체화·사례, 비교·대조, 원인·이유, 한계·반론, 해결·대안, 의의·평가, 정리

문단 `link_to_prev`
- 핵심어 반복, 지시어, 접속어, 앞 문단 끝의 대상을 이어받음, 글의 화제로 돌아감, 시간·순서 표지, 없음, 해당 없음

문장 `role`
- 화제 제시: 글이나 문단이 무엇을 다룰지 처음 꺼내는 문장
- 배경 사실: 뒤의 설명에 필요한 상황, 역사적 사실, 기존 지식을 전하는 문장
- 정의: 용어나 개념이 무엇인지 밝히는 문장
- 주제문: 문단의 핵심 주장이나 내용을 직접 말하는 문장
- 상세화: 앞 문장의 내용을 더 자세히 풀어 설명하는 문장
- 예시: 앞 내용의 구체적인 사례를 드는 문장
- 이유·근거: 앞 문장의 이유나 근거를 대는 문장
- 결과·귀결: 앞 내용에서 따라 나오는 결과나 결론을 말하는 문장
- 대조: 앞 내용과 다른 대상, 견해, 경우를 맞세우는 문장
- 조건·단서: 조건, 예외, 한계를 다는 문장
- 과정·단계: 절차나 작동 과정의 한 단계를 말하는 문장
- 질문: 독자에게 묻는 문장
- 평가·의의: 의의, 가치, 평가를 말하는 문장
- 전환·예고: 다음에 다룰 내용으로 넘어가는 문장
- 요약·정리: 앞 내용을 묶어 다시 말하는 문장

문장 `relation`
- 새 내용 시작, 상세화, 예시, 이유, 결과, 대조, 조건·단서, 다음 단계, 추가(같은 종류의 내용을 하나 더), 바꿔 말하기, 정리, 질문에 답함

문장 `link`
- 핵심어 반복: 앞 문장에 나온 명사를 그대로 다시 사용
- 지시어: 이, 그, 이러한, 이때, 이처럼, 그것 등으로 앞 내용을 가리킴
- 접속어: 그러나, 따라서, 또한, 즉, 예를 들어, 한편 등
- 바꿔 부르기: 앞 문장의 대상을 다른 말(상위어, 풀어 쓴 말)로 가리킴
- 주어 생략: 앞 문장의 주어를 이어받아 주어 없이 시작
- 없음: 위 장치 없이 새 대상으로 시작

## 작업 방법

1. 지문을 처음부터 끝까지 읽고 `topic`, `main_point`, 문단마다 `point`를 먼저 정한다.
2. 문장마다 `role`, `attaches_to`, `relation`, `link`를 정한다. 문장을 건너뛰지 않는다. 문장 번호는 배치 파일의 번호를 그대로 사용한다.
3. JSON을 지정된 경로에 저장한 뒤 `python3 -I -c "import json,sys; d=json.load(open(sys.argv[1])); print(len(d), sum(len(p['sentences']) for x in d for p in x['paragraphs']))" <경로>`로 형식과 문장 수를 확인한다. 배치 파일의 문장 수와 같아야 한다.
4. 같은 폴더에 관찰 기록 파일(`.notes.md`)을 쓴다. 600단어 이내로, 아래 질문에 지문 ID와 문장 번호를 근거로 들어 답한다.
   - 첫 문단은 무엇으로 시작하고 글의 화제를 어떻게 꺼내는가?
   - 새 용어는 어떤 순서와 문형으로 소개하는가?
   - 추상적인 진술 뒤에는 무엇이 오는가(예시, 풀이, 이유)? 추상적인 진술만 하고 넘어간 곳이 있는가?
   - 인과나 과정을 설명할 때 단계를 어떻게 하나씩 밟는가? 단계를 건너뛴 곳이 있는가?
   - 문단은 어떤 내용 단위로 나뉘고 문단의 첫 문장은 앞 문단과 어떻게 이어지는가?
   - 한 문장에 내용을 얼마나 담는가? 긴 문장은 어떤 구조인가?
   - 글의 마지막 문단과 마지막 문장은 무엇을 하는가?
   - 그 밖에 독자가 한 번 읽고 이해하게 하는 장치가 있으면 적는다.
