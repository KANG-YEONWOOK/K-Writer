# write의 기준 글 표본: 수능 국어 지문, 신문 기사, 논문 초록, 연설문

이 폴더는 write 스킬이 글의 전개와 문장 연결의 기준으로 삼는 사람 글을 측정한 도구와 결과다. 2026-11-26에 사용자는 K-Writer로 쓴 글에 번역투와 어색한 단어는 줄었지만 중요한 내용을 줄여 말하는 문장과 글의 주제와 관계없는 내용이 계속 나온다고 지적했다. 참고할 글로는 2027학년도 수능 이전의 수능 국어 지문, 2020년 이전의 뉴스와 논문 초록, 연설문, 국립국어원 모두의 말뭉치를 지정했다. 뉴스와 초록은 내용이 지금의 사실과 다를 수 있으므로 글쓰기 방식과 표현만 참고한다. 이 문서는 표본을 어디에서 어떤 조건으로 가져왔는지, 무엇을 측정했는지, 측정값을 스킬의 어느 문서와 검사 항목에 반영했는지를 기록한다.

원문은 저장소에 없다. 측정이 끝난 2026-11-26에 내려받은 원문과 주석 파일을 모두 삭제했고 저장소에는 글의 식별자(`ids.json`), 측정 도구, 집계한 값만 남겼다.

- 한국교육과정평가원의 기출문제 게시판(suneung.re.kr)은 robots.txt가 모든 경로의 자동 수집을 차단한다. 그래서 문제지 PDF를 직접 받지 않고 공개 데이터셋을 사용했다. 이 데이터셋에는 2024~2026학년도 수능이 없어서 사용자가 지정한 범위 중 최근 3년은 측정하지 못했다.
- CSAT-QA의 지문은 문제지의 줄바꿈이 그대로 있거나(39편) 문단마다 한 줄이거나(33편) 지문 전체가 한 줄이다(10편). `collect_csat.py`는 줄바꿈이 있는 지문에서 문단의 마지막 줄이 짧다는 점으로 문단을 복원하고 형태소 분석기 kiwipiepy로 줄을 이어 붙인다. 문학 작품, 화법과 작문 영역의 글, 문법 지문은 제외했다. 주석하는 과정에서 학생이 쓴 글로 확인된 2편도 제외했다. 지문 전체가 한 줄인 자료와 문단이 문장 중간에서 나뉜 자료는 문장 단위 측정에만 사용했다.
- KLUE-MRC의 기사는 문단을 공백 없이 이어 붙여 놓았다. 마침표 바로 뒤에 한글이 오는 위치를 문단 경계로 복원했다. 기사 일부는 끝이 잘려 있어서 기사의 마지막 문장은 주석한 18편에서만 세었다.
- 국립국어원 모두의 말뭉치의 원문 말뭉치는 내려받지 않았다. 말뭉치는 신청서를 내고 관리자의 승인을 받은 뒤 이용 약정서에 서명해야 받을 수 있고, 말뭉치로 만든 결과물을 공개하려면 사전 승인이 필요하다(`docs`의 계획 문서가 2026-11-10에 확인한 내용). 대신 로그인 없이 공개된 말뭉치 분석기(웹 버전)에서 신문 말뭉치의 2009~2019년 어절 묶음 상위 100개를 연도마다 조회했다(`collect_nikl_ngram.py`). 상위 목록은 대부분 인명과 기관명이었다. 서술 표현으로는 "수 있는", "것으로 나타났다", "수 있다", "있는 것으로 나타났다", "대한 관심이 높아지고 있다"가 11개 연도 중 10개 연도 이상에서 상위 100개에 들었다. 이 결과는 아래 종결 표현 측정이 다른 연도의 신문에서도 같은지 확인하는 데만 사용했다.

## 측정 방법

```bash
# 원문은 gitignore된 docs/corpus/write에 받는다. 원문을 읽는 Python은 -I로 실행한다.
curl -L -o docs/corpus/write/csat/csatqa.json https://huggingface.co/datasets/HAERAE-HUB/csatqa/resolve/main/data/csatqa.json
curl -L -o docs/corpus/write/news/klue_mrc_train.parquet https://huggingface.co/api/datasets/klue/klue/parquet/mrc/train/0.parquet
python -I dev/baseline/write/collect_csat.py docs/corpus/write/csat/csatqa.json docs/corpus/write/csat/passages.json
python -I dev/baseline/write/collect_speech.py docs/corpus/write/speech/speeches.jsonl 2003 2019 5
python -I dev/baseline/write/measure_flow.py docs/corpus/write . dev/baseline/write/flow-stats.json
python -I dev/baseline/write/measure_lint.py docs/corpus/write . dev/baseline/write/lint-stats.json
python -I dev/baseline/write/expr_stats.py docs/corpus/write . dev/baseline/write/expression-stats.json
python -I dev/baseline/write/calibrate.py docs/corpus/write . dev/baseline/write/calibration.json A13.demonstrative_start_per_1k A14.translationese_per_1k A7.see_judgment
```

- `measure_flow.py`는 kiwipiepy(0.25.1)로 문장을 나누고 품사를 붙여 문장 길이, 절의 수, 문장 사이에 겹치는 명사, 주제어, 조사와 서술어의 수를 측정한다. `collect_csat.py`, `measure_flow.py`, `prep_batches.py`에는 kiwipiepy가, 기사 표본에는 pyarrow가 필요하다. 스킬의 검사 스크립트에는 외부 패키지가 필요 없다.
- `measure_lint.py`는 스킬의 `lint_ko.py`가 계산하는 문장 연결 항목(A23, A24)을 표본과 저장소의 AI 글에 실행한다. lint는 형태소 분석 없이 어절에서 조사와 어미를 떼고 앞 두 음절을 비교하므로 `measure_flow.py`의 값과 조금 다르다. 문단 구분이 필요한 항목이라 수능 지문은 46편만 측정했다.
- 구조 주석: `prep_batches.py`가 문단 번호와 문장 번호를 붙인 글을 만들고, 글을 처음 읽는 subagent(Claude Fable 5.2)가 `annotation/GUIDE-csat.md`와 `annotation/GUIDE-genre.md`의 라벨을 문단과 문장마다 붙였다. 수능 지문은 문단 구분이 남아 있는 46편(993문장)을 네 묶음으로 나눠 subagent 네 개가, 기사 18편(358문장), 초록 26편(234문장), 연설문 10편(343문장)은 subagent 두 개가 주석했다. `aggregate_annot.py`가 라벨을 세어 `structure-stats.json`에 저장한다. 사람이 붙인 라벨이 아니고 글마다 한 번만 주석했으므로 주석자 사이의 일치도는 측정하지 못했다.

### write의 기준치

- 0.6.0까지 write는 표현의 빈도를 세는 항목 15개를 techblog의 기준치로 판정했다. 이 기준치로 수능 지문 84편(제외 전)을 검사하면 31편만 통과했다. 지시어로 시작하는 문장(A13)에서 37%, 번역투(A14.translationese_per_1k)에서 26%, 판단을 옮기는 "~라고 봅니다"(A7.see_judgment)에서 11%가 불합격이었다. 검출된 표현은 A13이 "이러한"(58회), "이처럼"(17회), "이는"(16회), A14가 "~에 의해"(30회), "그것이"(13회), "~에 의한"(10회), A7.see_judgment가 "~다고 보았다"(9회), "~다고 본다"(6회)였다.
- 세 항목의 1,000자당 횟수는 수능 지문 1.25, 0.85, 0.34, 논문 초록 1.03, 0.52, 0.10, 신문 기사 0.17, 0.03, 0.08이다(`calibration.json`). write는 세 항목을 수능 지문의 값을 비율로 하는 Poisson 한도(PASS는 0.95 분위, WARN은 0.995 분위)로 판정한다. 수능 지문은 대부분 본문이 1,500자 미만이라 글의 길이에 따라 한도가 달라지는 방식을 선택했다. `lint_ko.py`의 짧은 글 기준은 Poisson으로 판정하는 항목을 개수 기준으로 바꾸지 않는다.
- 이 기준치로 다시 검사하면 수능 지문 82편 중 64편(78%)이 통과한다. 남은 불합격은 항목마다 1~3편(과사용 어휘 3편, "~되고 있다" 2편, 부정 대구 1편 등)이고 원문 변환 과정에서 생긴 문장 부호도 포함된다.
- 나머지 13개 항목은 그대로 techblog의 기준치를 가져온다. 이 기준치에서 수능 지문, 기사, 초록의 항목별 불합격은 4% 이하였다. 연설문은 부정 대구가 1,000자당 0.71번으로 많아서(수능 지문 0.30번) 표현 항목의 기준으로 사용하지 않았다.

### 구조 주석: 수능 지문 46편

`structure-stats.json`의 값이다. 문단 207개, 문장 993개에 라벨을 붙였다.

## 한계

- 수능 지문은 82편, 문단 구분이 남은 지문은 46편이다. 글마다 계산한 값의 분위수(p90, p95)는 글 몇 편에 따라 달라진다.
- 수능 지문은 시험 문제를 내려고 쓴 설명문이다. 1,100~2,500자 분량에 정보를 촘촘하게 담고 일부 추론 단계를 생략한다. 공지, 보고서, 메일처럼 write가 쓰는 다른 종류의 글은 측정하지 못했다.
- 신문 기사는 한국경제 한 곳의 2013~2015년 기사이고 연설문은 대통령 연설문이다. 한 매체와 한 기관의 문체가 값에 반영되어 있다.
- 구조 주석은 모델이 한 번 붙인 라벨이다. 라벨의 경계(상세화와 결과, 주제문과 정의)는 주석자마다 다르게 적용됐을 수 있다. 원문의 문장 분리 오류로 한 문장이 둘로 나뉜 곳도 집계에 포함되어 있다.
- lint의 A23은 형태소 분석 없이 어절의 앞 두 음절을 비교한다. 앞 문장을 다른 말로 푼 문장은 이어지지 않는 문장으로 검출되고, 우연히 앞 두 음절이 같은 다른 단어는 이어지는 것으로 처리된다.
- AI 글과의 비교는 스킬 없이 쓴 보고서 4편과 0.6.0까지의 글 14편으로 했다. 표본이 작아서 차이의 크기는 참고값이다.
- 모두의 말뭉치는 공개된 분석기의 상위 100개 목록만 조회했다. 원문 말뭉치로 같은 지표를 측정하려면 국립국어원의 이용 승인과 결과물 공개 승인이 필요하다.
