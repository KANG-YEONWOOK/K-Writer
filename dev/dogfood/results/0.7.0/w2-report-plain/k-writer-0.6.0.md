# 2026년 11월 7일 checkout API의 지연 장애 보고

2026년 11월 7일 14:10에 checkout API의 p99 latency가 180ms에서 2,400ms로 올랐다. 원인은 13:50에 배포된 설정 변경으로 인스턴스당 connection pool 최대 크기가 50에서 200으로 늘면서 인스턴스 12개가 열 수 있는 데이터베이스 연결 수가 데이터베이스의 연결 수 한도인 2,000개를 넘은 것이었다. connection pool은 인스턴스마다 데이터베이스 연결을 열어 두고 요청마다 재사용하는 연결 묶음이고, connection pool 최대 크기는 인스턴스 하나의 connection pool이 열 수 있는 연결 수의 상한이다.

설정 변경은 14:58에 되돌렸고 15:02에 checkout API의 p99 latency는 190ms로 낮아졌다. checkout API의 성능은 52분 동안 저하됐고 이 기간에 checkout API 요청의 3.8%가 실패했다. 평소 checkout API 요청의 실패율은 0.2%다.

아래 표는 설정 변경을 배포한 13:50부터 p99 latency가 190ms로 낮아진 15:02까지의 경과다.

| 시각 | 경과 |
|---|---|
| 13:50 | 인스턴스당 connection pool 최대 크기를 50에서 200으로 늘리는 설정 변경 배포. 인스턴스 수는 12개 |
| 14:10 | checkout API의 p99 latency가 180ms에서 2,400ms로 오름. 알림 발생 |
| 14:25 | 온콜 엔지니어 Mina Park 님이 데이터베이스의 연결 수가 한도인 2,000개에 도달했고 데이터베이스가 새 연결을 거부하고 있는 것을 확인 |
| 14:58 | connection pool 최대 크기를 50으로 되돌림 |
| 15:02 | checkout API의 p99 latency가 190ms로 낮아짐 |

인스턴스 12개의 connection pool 최대 크기를 합친 값은 연결 2,400개로 데이터베이스의 연결 수 한도인 2,000개보다 많다. 스테이징 환경에서는 인스턴스가 2개만 실행되기 때문에 connection pool 최대 크기를 200으로 늘린 설정 변경은 배포 전에 스테이징 환경에서 부하 테스트를 거치지 않았다.

후속 조치는 배포할 때 실행하는 검사를 추가하는 일과 데이터베이스의 연결 수 한도를 늘릴지 논의하는 일이다.

- 인스턴스당 connection pool 최대 크기와 인스턴스 수를 곱한 값이 데이터베이스의 연결 수 한도의 80% 미만인지 확인하는 검사를 배포 과정에 추가한다. 담당자는 Jisoo Han 님이고 기한은 2026년 11월 21일이다.
- 데이터베이스의 연결 수 한도를 2,000개보다 늘릴지는 아직 정하지 않았고 2026년 11월 14일에 논의할 예정이다.
