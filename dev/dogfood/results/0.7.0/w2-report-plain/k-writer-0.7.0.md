# 11월 7일 checkout API 응답 지연 장애 보고

2026년 11월 7일 14시 10분부터 15시 2분까지 52분 동안 checkout API의 응답이 느려지고 checkout 요청 일부가 실패했다. checkout 요청의 실패율은 평소 0.2%였는데 장애가 이어진 52분 동안은 3.8%였다. 장애는 13시 50분에 배포된 DB 커넥션 풀 설정 변경 때문에 생겼고, 14시 58분에 이 설정을 되돌린 뒤 15시 2분에 끝났다.

장애 경과를 시각 순서로 정리하면 다음과 같다.

- 13시 50분: DB 커넥션 풀 최댓값(인스턴스 하나가 DB에 동시에 열 수 있는 커넥션 수의 상한)을 50에서 200으로 올리는 설정 변경이 인스턴스 12대에 배포됐다.
- 14시 10분: checkout API의 p99 응답 시간(요청의 99%가 응답을 받는 데 걸린 최대 시간)이 180ms에서 2,400ms로 올랐고 알림이 발생했다.
- 14시 25분: 온콜 담당자 Mina Park 님이 DB에 열린 커넥션이 DB 커넥션 한도인 2,000개에 도달해 DB가 새 커넥션을 거부하고 있는 것을 확인했다.
- 14시 58분: 커넥션 풀 최댓값을 다시 50으로 되돌렸다.
- 15시 2분: checkout API의 p99 응답 시간이 190ms로 낮아졌다.

커넥션 풀 최댓값이 인스턴스마다 200으로 올라가면서 인스턴스 12대가 DB에 열 수 있는 커넥션은 합쳐서 2,400개가 됐다. 이렇게 합친 커넥션 수 2,400개가 DB 커넥션 한도인 2,000개를 넘은 것이 장애의 원인이다. 스테이징은 인스턴스를 2대만 운영하기 때문에 이 설정 변경은 스테이징에서 부하 테스트를 거치지 않았다.

후속 조치로 커넥션 풀 최댓값에 인스턴스 수를 곱한 값이 DB 커넥션 한도의 80% 미만인지 배포할 때 확인하는 검사를 추가하기로 했다. 이 배포 검사는 Jisoo Han 님이 맡았고 기한은 11월 21일이다. DB 커넥션 한도를 올릴지는 아직 정하지 않았고 11월 14일에 논의할 예정이다.
