# 설계

- 핵심 주제: K-Writer를 이미 사용하는 사람은 0.5.0에서 write와 brief 스킬이 추가되고 techblog의 short 모드가 삭제됐으며 Plain(해라체)과 직접 정한 어투를 쓸 수 있게 됐다는 것과, 이번 버전에서 확인하지 못한 부분을 알게 된다.
- 전개 순서: 0.5.0 변경 요약 → write 스킬 → brief 스킬과 short 모드 삭제 → 새 어투와 lint 결과 → 짧은 글 기준 이동 → 확인하지 못한 부분

## 단위 0. 제목
- 형태: 제목
- 전할 내용: 이 글은 K-Writer 0.5.0에서 달라진 점을 다룬다.
- 전개: 제목

1. [제목] K-Writer 0.5.0에서 달라진 점 (버전과 날짜)

## 단위 1. 0.5.0 변경 요약
- 형태: 제목과 첫 문단
- 전할 내용: K-Writer 0.5.0에는 write와 brief 스킬이 추가됐고 techblog의 short 모드가 삭제됐으며 어투에 Plain(해라체)과 사용자가 직접 정한 어투가 추가됐다.
- 전개: 추가된 스킬 두 개와 각 스킬의 정의 → 삭제된 기능과 추가된 어투

1. [핵심] K-Writer 0.5.0에는 자료나 주제를 받아 사용자가 정한 목적, 분량, 어투에 맞는 글을 쓰는 write 스킬과 자료나 내용을 자연스러운 한국어로 요약하는 brief 스킬이 추가됐다. (사실: 추가한 스킬, write가 받는 값, 용어: brief)
2. [핵심] core의 어투에는 Plain(해라체)과 사용자가 직접 정한 어투를 추가했고 techblog의 short 모드는 삭제했다. (사실: short 모드 삭제, 어투 추가)

## 단위 2. write 스킬
- 형태: 문단
- 전할 내용: write는 K-Writer의 기본 스킬이고, 자료나 주제를 먼저 받은 뒤 요청에 없는 목적, 분량, 어투를 한 번에 묻고 목적에 따라 독자와 구성을 정한다.
- 전개: 다른 스킬과 구별되는 점 → 자료나 주제를 요청하는 과정 → 나머지 값을 묻는 과정 → 목적의 선택지와 목적이 정하는 것

1. [대조] write는 문체를 미리 정하지 않는 K-Writer의 기본 스킬이고 techblog 같은 다른 스킬은 글의 목적, 문체, 구성을 미리 정해 둔 스킬이다. (사실: write의 위치)
2. [단계] 요청에 자료나 주제가 없으면 write는 대화에서 자료나 주제를 먼저 요청하고 받지 못하면 작업을 시작하지 않는다. (사실: write의 자료 요청)
3. [단계] write는 목적, 분량, 어투 가운데 요청에 없는 값을 한 번에 묻는다. (사실: write의 설정 질문)
4. [풀이] 사용자는 목적을 설명, 설득, 안내, 기록 중에서 선택하거나 직접 입력하고 write는 정한 목적에 따라 글의 독자와 구성을 정한다. (사실: write의 목적 선택지, write의 독자와 구성)

## 단위 3. brief 스킬과 short 모드 삭제
- 형태: 문단
- 전할 내용: techblog의 short 모드가 삭제됐으므로 짧은 글은 brief로 작성하고, brief는 분량과 어투만 묻는다.
- 전개: 이전 기능과 함께 삭제한 인자와 옵션 → 대신 사용할 스킬 → brief가 묻는 값 → brief의 출력

1. [바뀐 일] techblog의 short 모드와 함께 이 모드에서 사용하던 `short` 인자, lint의 `--source`와 `--terms` 옵션, 원문 대조 항목 F1~F8을 삭제했다. (사실: short 모드 삭제 대상)
2. [바뀐 일] short 모드로 쓰던 짧은 글은 이제 brief로 작성한다. (사실: short 모드 삭제)
3. [풀이] brief가 사용자에게 묻는 값은 분량(한 줄, 한 문단, 자세히)과 어투뿐이다. (사실: brief가 묻는 값)
4. [풀이] brief는 요약을 대화의 답으로 보여 주고 `-o`를 붙이면 같은 요약을 파일에도 저장한다. (사실: brief의 출력)

## 단위 4. 새 어투와 lint 결과
- 형태: 문단
- 전할 내용: 새 어투도 합니다체 초안의 종결부만 바꿔 만들고, 검사 스크립트의 `--tone`에 `plain`과 `free`를 지정할 수 있으며, 기존 어투의 lint 판정은 바뀌지 않았지만 `--tone auto`의 출력은 해라체 문서에서 달라질 수 있다.
- 전개: 새 어투를 만드는 방식 → 검사 스크립트의 인자 → 기존 어투의 lint 결과 → `--tone auto`의 변화

1. [풀이] 스킬은 Plain과 사용자가 직접 정한 어투를 포함해 어느 어투의 글이든 합니다체 초안을 먼저 쓴 뒤 그 초안의 종결부만 바꿔 만든다. (사실: 어투 변환 방식)
2. [방법] `lint_ko.py`와 `tone_check.py`의 `--tone` 옵션에는 Plain을 `plain`으로, 사용자가 직접 정한 어투를 `free`로 지정한다. (사실: 어투 인자)
3. [결과] 0.5.0에서 수정하기 전과 후의 `lint_ko.py`로 예시 글, eval 글, 평가 기록의 글을 합친 34개 파일을 `--tone default`와 `--tone casual`로 검사했더니 두 버전이 출력한 항목의 값과 판정은 모두 같았다. (사실: lint 회귀 확인 대상, lint 회귀 확인 결과)
4. [대조] `--tone auto`로 검사했을 때는 0.5.0의 `lint_ko.py`가 해라체로 쓴 문서 7개를 `plain`으로 인식해서 출력이 수정 전과 달라졌다. (사실: `--tone auto` 변화)

## 단위 5. 짧은 글 기준 이동
- 형태: 문단
- 전할 내용: 짧은 글 기준이 core의 `rules.json`으로 옮겨져 `lint_ko.py`와 `revise_ko.py`가 같은 기준으로 짧은 글을 판정한다.
- 전개: 무엇이 어디로 옮겨졌는지와 그 기준을 적용하는 명령 → 바꾼 이유

1. [바뀐 일] 짧은 글 기준은 core의 `rules.json`으로 옮겨졌고 `lint_ko.py --short`와 `revise_ko.py`의 `check --short`, `audit --short`가 같은 기준을 적용한다. (사실: 짧은 글 기준 이동)
2. [이유] `check`와 `audit`에 `--short`를 추가한 것은 두 명령이 짧은 글 기준을 적용하지 않아 `lint_ko.py --short`와 판정이 달랐기 때문이다. (사실: check, audit 판정 차이)
3. [예] lint를 통과한 요약이 `check`에서는 FAIL로 판정됐고 lint가 찾은 번역투 두 개를 `check`는 통과시켰다. (사실: check, audit 판정 차이)

## 단위 6. 확인하지 못한 부분
- 형태: 목록
- 전할 내용: write와 brief의 기준치는 techblog에서 가져온 값이고, lint는 해라체 글의 반말 종결을 검출하지 못하며, plugin eval과 설정 질문 흐름은 실행하지 않았다.
- 전개: 목록 소개 → 기준치를 가져온 이유와 범위 → 기준치의 출처와 가져오지 않은 항목 → lint가 검출하지 못하는 종결 → 실행하지 않은 확인 → 실행해 보지 못한 흐름

1. [전환] 0.5.0에 남은 한계를 목록으로 소개한다.
- [목록] 기준치, 반말 종결 검출, plugin eval, 설정 질문 흐름
2. [한계] write와 brief는 기준치를 측정할 기준 글 표본이 없어서 특정 표현의 빈도를 세는 항목 15개의 기준치를 techblog에서 가져왔다. (사실: 가져온 기준치, 기준치를 가져온 이유)
3. [한계] 가져온 기준치는 기술 블로그 글에서 측정한 값이고 문장 길이, 문단, 목록 비중 같은 분포 항목의 기준치는 가져오지 않았다. (사실: 가져오지 않은 항목, 한계: 측정값이 아닌 기준)
4. [한계] lint는 해라체 글에 섞인 합니다체와 해요체 종결은 검출하지만 반말 종결은 검출하지 못한다. (한계: 반말 종결 검출)
5. [한계] 0.5.0에서는 `claude plugin eval`을 실행하지 않았고 새 eval 케이스 4개는 작성만 했다. (한계: eval과 dogfood)
6. [한계] 테스트 실행을 subagent 안에서 했기 때문에 AskUserQuestion으로 목적, 분량, 어투 같은 설정을 묻는 흐름과 대화에서 자료나 주제를 요청하는 흐름은 실행해 보지 못했다. (한계: 설정 질문 흐름)

## 제외한 사실
- 버전 기록 날짜(2026-11-10): 기존 사용자가 달라진 점을 이해하는 데 필요하지 않다.
- write의 독립 점검(1,500자 기준): 스킬 내부의 점검 절차이고 분량 안에서 제외한다.
- 장르별 허용 표현(`allow_patterns` 등, write의 요청문 허용): 스킬 내부의 lint 설정이고 분량 안에서 설명할 공간이 없다.
- lint 출력 68개와 G4.off_tone 문구 변경: 항목의 값과 판정이 같았다는 결과만 전한다.
- tone_check 회귀 확인(문장 207쌍, FAIL 0): 기존 어투 lint 결과로 회귀 확인을 이미 전하므로 제외한다.
- 테스트 실행 결과 표(brief 1차 5문장 590자 27분, 2차 296자 9분, 회의록 338자 14분에서 189자 3분, write 423자 20분, 905자 24분): 개발 중 문서를 수정한 과정이고 사용자가 0.5.0에서 달라진 점과 관계가 적다.
- brief 기본 독자 변경: 0.5.0에서 처음 추가된 스킬의 개발 중 변경이라 기존 사용자에게 달라진 점이 아니다.
- "저희" 규칙: 개발 중 문서 수정이고 분량 안에서 제외한다.
- 단위 테스트 210개 통과: 핵심 주제와 관계가 적다.
- 스킬 없이 쓴 글이나 사람이 쓴 글과의 비교 없음, 재실행하지 않은 수정, 사전 허용 유지 미확인, Plain 종결 분포 없음, 구성과 분량 범위가 측정값이 아님: 분량 안에서 기존 사용자에게 가장 관계가 큰 한계만 남겼다.
- dogfood 미실행: dogfood를 설명할 자료가 없어 plugin eval만 쓴다.
