# K-Writer 0.5.0 변경 사항: write, brief 스킬 추가와 short 모드 삭제

K-Writer 0.5.0에는 사용자가 정한 목적에 맞는 글을 쓰는 write 스킬과 자료를 요약하는 brief 스킬이 추가됐고 techblog의 short 모드는 삭제됐습니다. techblog의 short 모드로 쓰던 짧은 글은 0.5.0부터 brief로 작성합니다.

write는 K-Writer의 기본 스킬이고 글의 목적, 문체, 구성을 미리 정해 둔 techblog, brief와 달리 자료나 주제, 목적, 분량, 어투를 받아 그에 맞는 글을 씁니다. write는 사용자가 자료나 주제를 알려 주지 않으면 대화에서 자료나 주제를 먼저 묻고, 목적, 분량, 어투 중 요청에 없는 값은 한 번에 묻습니다. 목적은 설명, 설득, 안내, 기록 중에서 선택하거나 직접 입력하고, write는 선택한 목적에 따라 독자와 글의 구성을 정합니다.

brief는 사용자가 지정한 자료나 내용을 자연스러운 한국어로 요약하는 스킬입니다. brief는 분량과 어투만 묻고, 분량은 한 줄, 한 문단, 자세히 중에서 선택합니다. 요약은 대화에 답으로 표시되고 `-o`로 파일 경로를 지정하면 파일에도 저장됩니다.

short 모드와 함께 techblog의 `short` 인자가 삭제됐고, `lint_ko.py`에서도 `--source`, `--terms` 옵션과 원문 대조 항목 F1~F8이 삭제됐습니다. 짧은 글 기준은 남겨서 `rules.json`으로 옮겼고 `lint_ko.py --short`와 `revise_ko.py`의 `check --short`, `audit --short`가 이 기준을 적용합니다. 0.5.0 이전의 `check`와 `audit`는 짧은 글 기준을 적용하지 않아서 `lint_ko.py --short`를 통과한 요약이 `check`에서 FAIL로 판정되기도 했습니다.

어투에는 해라체(Plain)와 사용자가 직접 정한 어투가 추가됐고 `lint_ko.py`와 `tone_check.py`의 `--tone` 옵션에 `plain`과 `free`를 지정할 수 있습니다. 스킬은 어느 어투로 쓰든 먼저 합니다체 초안을 쓰고 초안의 종결부만 바꿔 요청한 어투의 글을 만듭니다. short 모드 코드를 삭제하기 전과 후의 `lint_ko.py`를 예시 글과 평가에 사용한 글 34개 파일에 `--tone default`와 `--tone casual`로 실행한 결과 항목의 값과 판정은 모두 같았습니다. 해라체로 쓴 문서 7개는 `--tone auto`로 실행하면 `plain`으로 인식돼서 출력이 0.5.0 이전과 달라졌습니다.

0.5.0에서는 새로 작성한 eval 케이스 4개를 `claude plugin eval`로 실행하지 않았습니다. 새 스킬의 테스트는 스킬 문서만 받은 subagent 안에서 실행됐기 때문에 스킬이 사용자에게 설정을 묻는 흐름과 대화에서 자료나 주제를 요청하는 흐름은 확인하지 못했습니다. write와 brief에는 기준치를 측정할 사람 글 표본이 없어서 두 스킬은 `lint_ko.py`에서 특정 표현의 빈도를 세는 항목 15개의 기준치로 techblog의 기술 블로그 글에서 측정한 값을 사용합니다. `lint_ko.py`는 해라체 글에 섞인 합니다체와 해요체 종결은 찾지만 "~해", "~야" 같은 반말 종결은 찾지 못합니다.
