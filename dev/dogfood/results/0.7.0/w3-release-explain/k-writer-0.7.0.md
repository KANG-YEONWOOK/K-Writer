# K-Writer 0.5.0에서 달라진 점

K-Writer 0.5.0에는 자료나 주제를 받아 사용자가 정한 목적, 분량, 어투에 맞는 글을 쓰는 write 스킬과 자료나 내용을 자연스러운 한국어로 요약하는 brief 스킬이 추가됐습니다. core의 어투에는 Plain(해라체)과 사용자가 직접 정한 어투를 추가했고 techblog의 short 모드는 삭제했습니다.

write는 문체를 미리 정하지 않는 K-Writer의 기본 스킬이고 techblog 같은 다른 스킬은 글의 목적, 문체, 구성을 미리 정해 둔 스킬입니다. 요청에 자료나 주제가 없으면 write는 대화에서 자료나 주제를 먼저 요청하고 받지 못하면 작업을 시작하지 않습니다. 자료나 주제를 받은 뒤에는 목적, 분량, 어투 중 요청에 없는 값을 한 번에 묻습니다. 사용자는 목적을 설명, 설득, 안내, 기록 중에서 선택하거나 직접 입력하고, write는 정한 목적에 따라 글의 독자와 구성을 정합니다.

techblog의 short 모드와 함께 이 모드에서 사용하던 `short` 인자, lint의 `--source`와 `--terms` 옵션, 원문 대조 항목 F1~F8을 삭제했습니다. short 모드로 쓰던 짧은 글은 이제 brief로 작성합니다. brief가 사용자에게 묻는 값은 분량(한 줄, 한 문단, 자세히)과 어투뿐입니다. brief는 요약을 대화의 답으로 보여 주고 `-o`를 붙이면 같은 요약을 파일에도 저장합니다.

스킬은 Plain과 사용자가 직접 정한 어투를 포함해 어느 어투의 글이든 합니다체 초안을 먼저 쓴 뒤 그 초안의 종결부만 바꿔 만듭니다. 검사 스크립트 `lint_ko.py`와 `tone_check.py`의 `--tone` 옵션에는 Plain을 `plain`으로, 사용자가 직접 정한 어투를 `free`로 지정합니다. 0.5.0에서 수정하기 전과 후의 `lint_ko.py`로 예시 글, eval 글, 평가 기록의 글을 합친 34개 파일을 `--tone default`와 `--tone casual`로 검사했더니 두 버전이 출력한 항목의 값과 판정은 모두 같았습니다. 다만 `--tone auto`로 검사했을 때는 0.5.0의 `lint_ko.py`가 해라체로 쓴 문서 7개를 `plain`으로 인식해서 출력이 수정 전과 달라졌습니다.

짧은 글 기준은 core의 `rules.json`으로 옮겨졌고 `lint_ko.py --short`와 `revise_ko.py`의 `check --short`, `audit --short`가 같은 기준을 적용합니다. `check`와 `audit`에 `--short`를 추가한 것은 두 명령이 짧은 글 기준을 적용하지 않아 `lint_ko.py --short`와 판정이 달랐기 때문입니다. lint를 통과한 요약이 `check`에서는 FAIL로 판정됐고 lint가 찾은 번역투 두 개를 `check`는 통과시켰습니다.

0.5.0에 남은 한계는 다음과 같습니다.

- write와 brief는 기준치를 측정할 기준 글 표본이 없어서 특정 표현의 빈도를 세는 항목 15개의 기준치를 techblog에서 가져왔습니다. 가져온 기준치는 기술 블로그 글에서 측정한 값이고 문장 길이, 문단, 목록 비중 같은 분포 항목의 기준치는 가져오지 않았습니다.
- lint는 해라체 글에 섞인 합니다체와 해요체 종결은 검출하지만 반말 종결은 검출하지 못합니다.
- 0.5.0에서는 `claude plugin eval`을 실행하지 않았고 새 eval 케이스 4개는 작성만 했습니다.
- 테스트 실행을 subagent 안에서 했기 때문에 AskUserQuestion으로 목적, 분량, 어투 같은 설정을 묻는 흐름과 대화에서 자료나 주제를 요청하는 흐름은 실행해 보지 못했습니다.
