# API 요청 제한 방식의 토큰 버킷 전환 노트 요약

공개 API의 요청 제한 방식을 고정 윈도우에서 클라이언트별 토큰 버킷으로 바꾸고 2주 뒤 같은 트래픽 수준에서 측정한 결과 게이트웨이의 p99 지연이 1,850ms에서 420ms로 줄었습니다. 고정 윈도우 방식에서 p99 지연이 1,850ms까지 늘었던 것은 60초 윈도우가 시작할 때마다 요청이 제한됐던 클라이언트들이 한꺼번에 재시도해 첫 1초에 요청이 초당 최대 4,800건까지 몰렸기 때문입니다. 토큰 버킷으로 바꾼 뒤에는 클라이언트가 윈도우 경계에서 제한을 넘을 수 없게 되면서 거부된 요청의 비율이 2.1%에서 2.6%로 늘었고 버킷 상태를 저장하는 Redis의 CPU 사용률은 8%포인트 올랐습니다. 다만 클라이언트마다 하나씩 두는 토큰 버킷으로는 서로 다른 클라이언트 여러 개가 같은 순간에 요청을 시작할 때 생기는 몰림을 막지 못하며 배포 뒤에는 지금도 요청이 잠깐 몰립니다. 활성 클라이언트가 50,000개를 넘는 조건에서는 토큰 버킷 설계를 아직 테스트하지 않았습니다.
