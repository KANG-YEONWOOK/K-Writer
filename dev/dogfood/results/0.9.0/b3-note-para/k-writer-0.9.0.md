# API 요청 수 제한 방식을 고정 윈도우에서 토큰 버킷으로 바꾼 노트 요약

공개 API의 요청 수를 제한하는 방식을 고정 윈도우에서 클라이언트별 토큰 버킷으로 바꾸자 배포 2주 뒤 같은 트래픽 수준에서 게이트웨이의 p99 지연이 1,850ms에서 420ms로 줄었습니다. 고정 윈도우에서는 한도를 넘은 클라이언트가 새 60초 윈도우가 시작될 때마다 한꺼번에 재시도해 1초 동안의 최대 요청 수가 4,800건에 이르렀는데, 토큰 버킷으로 바꾼 뒤에는 1,400건으로 줄었습니다. 토큰 버킷에는 토큰이 최대 100개까지 들어가고 초당 10개씩 채워지므로 장기 한도는 고정 윈도우와 같은 분당 600건으로 유지됩니다. 대신 클라이언트가 고정 윈도우의 경계에서처럼 한도를 넘을 수 없게 되면서 거부된 요청의 비율이 2.1%에서 2.6%로 늘었고 버킷 상태를 저장하는 Redis의 CPU 사용률은 8%포인트 올랐습니다. 다만 서로 다른 클라이언트 여러 개가 같은 순간에 요청을 보내기 시작하면 토큰 버킷으로도 요청이 몰리는 것을 막을 수 없고 토큰 버킷으로 바꾼 뒤에도 배포 직후에는 요청이 잠깐 몰립니다.
