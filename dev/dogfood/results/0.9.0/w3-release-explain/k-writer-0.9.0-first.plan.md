# 설계

- 핵심 주제: K-Writer를 이미 사용하는 사람은 0.5.0에서 write와 brief 스킬이 추가되고 techblog의 short 모드가 삭제되고 Plain(해라체)과 사용자가 직접 정한 어투가 추가됐다는 것과, 이 변경에서 아직 확인하지 않은 부분을 알게 된다.
- 전개 순서: 0.5.0 변경 요약 → write 스킬 → brief 스킬과 short 모드 삭제 → 추가된 어투 → 검사 스크립트의 변화 → 아직 확인하지 않은 부분

## 단위 1. 0.5.0 변경 요약
- 형태: 제목과 첫 문단
- 전할 내용: 0.5.0에서 write와 brief 스킬이 추가되고 techblog의 short 모드가 삭제됐으며 어투에 Plain과 사용자가 직접 정한 어투가 추가됐다.
- 전개: 추가된 스킬과 삭제된 모드 → 추가된 어투

- [제목] K-Writer 0.5.0의 변경 사항: write와 brief 추가, short 모드 삭제
1. [핵심] K-Writer 0.5.0에서는 글을 쓰는 write 스킬과 자료를 요약하는 brief 스킬이 추가됐고 techblog의 short 모드가 삭제됐다. (S2, S13, 핵심 요소 1)
2. [핵심] 0.5.0의 어투에는 Plain(해라체)과 사용자가 직접 정한 어투가 추가됐다. (S15)

## 단위 2. write 스킬
- 형태: 문단
- 전할 내용: write는 자료나 주제, 목적, 분량, 어투를 받아 글을 쓰는 기본 스킬이고, 자료나 주제를 먼저 요청한 뒤 나머지 값을 한 번에 묻고 목적에 따라 독자와 구성을 정한다.
- 전개: 정의 → 다른 스킬과 구별되는 점 → 자료나 주제를 요청하는 단계 → 나머지 값을 묻는 단계 → 목적으로 독자와 구성을 정하는 단계

3. [정의] write 스킬은 자료나 주제, 목적, 분량, 어투를 사용자에게 받은 뒤 그에 맞는 글을 쓴다. (S3, 핵심 요소 2)
4. [대조] techblog 같은 다른 스킬이 글의 목적, 문체, 구성을 미리 정해 둔 스킬이라면, write는 문체를 미리 정하지 않고 목적도 사용자에게 받는 K-Writer의 기본 스킬이다. (S3, S4)
5. [단계] write는 요청에 자료나 주제가 없으면 대화에서 자료나 주제를 먼저 요청하고, 자료나 주제를 받지 못하면 작업을 시작하지 않는다. (S5, S8, 핵심 요소 3)
6. [단계] write는 목적(설명, 설득, 안내, 기록, 직접 입력), 분량, 어투 중 요청에 없는 값을 한 번에 묻는다. (S5)
7. [단계] write는 사용자가 정한 목적에 따라 글의 독자와 구성을 정한다. (S6)

## 단위 3. brief 스킬과 short 모드 삭제
- 형태: 문단
- 전할 내용: brief는 분량과 어투만 묻는 요약 스킬이고, techblog의 short 모드가 삭제되면서 짧은 글은 brief로 작성하며 short 모드의 인자와 lint 옵션도 삭제됐다.
- 전개: brief의 정의 → brief가 묻는 값 → brief의 출력 → short 모드 대신 brief를 사용하는 결정 → 함께 삭제된 인자와 옵션

8. [정의] brief는 사용자가 전달한 자료나 내용을 자연스러운 한국어로 요약하는 스킬이다. (S9, 핵심 요소 4)
9. [방법] brief는 분량(한 줄, 한 문단, 자세히)과 어투 두 값만 묻는다. (S10)
10. [방법] brief는 요약을 대화에 답하고, `-o`를 붙이면 요약을 파일에도 저장한다. (S11)
11. [결정] 짧은 글은 이제 techblog의 short 모드 대신 brief로 작성한다. (S13, 핵심 요소 5)
12. [변경] short 모드에서 사용하던 techblog의 `short` 인자, `lint_ko.py`의 `--source`와 `--terms` 옵션, 원문 대조 항목 F1~F8도 short 모드와 함께 삭제됐다. (S14, 용어: lint_ko.py)

## 단위 4. 추가된 어투
- 형태: 문단
- 전할 내용: 어느 어투든 합니다체 초안의 종결부만 바꿔 만들고, 새 어투는 `--tone plain`과 `--tone free`로 지정하며, `lint_ko.py`는 해라체 글의 반말 종결을 검출하지 못한다.
- 전개: 다른 어투의 글을 만드는 방법 → 새 어투를 지정하는 옵션 → 검사의 한계

13. [방법] Plain과 사용자가 직접 정한 어투를 포함해 어느 어투로 요청해도 K-Writer는 합니다체 초안을 먼저 쓰고 초안 문장의 종결부만 바꿔 요청한 어투의 글을 만든다. (S17, 용어: 종결부, 핵심 요소 6)
14. [방법] 검사 스크립트에서는 `lint_ko.py`와 `tone_check.py`의 `--tone`에 Plain은 `plain`, 사용자가 직접 정한 어투는 `free`로 지정할 수 있다. (S16, 용어: tone_check.py)
15. [한계] `lint_ko.py`는 해라체 글에 섞인 합니다체와 해요체 종결은 검출하지만, 반말 종결은 명사로 분류해서 검출하지 못한다. (L6, 용어: 반말 종결, 핵심 요소 7)

## 단위 5. 기존 lint 출력과의 비교
- 형태: 문단
- 전할 내용: 기존 lint 출력은 G4.off_tone 수정 방향 한 줄을 빼면 0.5.0 전과 같고, `--tone auto`로 검사한 해라체 문서 7개만 출력이 달라졌다.
- 전개: 기존 출력과 비교한 결과 → 출력이 달라진 조건

16. [결과] 0.5.0에서 수정하기 전과 후의 `lint_ko.py`를 예시 글, eval 글, 평가 기록의 글을 합친 34개 파일에 `--tone default`와 `--tone casual`로 실행해 출력 68개를 비교한 결과, 달라진 부분은 어투 항목 G4.off_tone의 수정 방향 문구 한 줄이었고 항목의 값과 판정은 모두 같았다. (S23, 용어: G4.off_tone, 핵심 요소 8)
17. [조건] `--tone auto`로 실행하면 0.5.0의 `lint_ko.py`는 해라체로 쓴 문서 7개를 새로 추가된 `plain`으로 인식해서 수정 전과 다른 출력을 냈다. (S24, S16)

## 단위 6. 아직 확인하지 않은 부분
- 형태: 문단
- 전할 내용: write와 brief의 기준치는 techblog에서 가져온 값이고 구성과 분량 범위는 측정한 값이 아니며, `claude plugin eval`, dogfood, 설정을 묻는 흐름은 아직 실행하지 않았다.
- 전개: 기준치를 가져온 이유와 범위 → 측정하지 않은 값 → 실행하지 않은 평가 → 실행하지 못한 흐름

18. [한계] write와 brief에는 기준 글 표본이 없어서, 특정 표현의 빈도를 세는 항목 15개의 기준치를 techblog에서 가져왔다. (S21, 용어: 기준 글 표본, 핵심 요소 9)
20. [한계] 스킬을 평가할 요청과 자료를 담은 새 eval 케이스 4개는 작성만 했고, `claude plugin eval`과 dogfood는 아직 실행하지 않았다. (L1, 용어: eval case, 용어: dogfood, 핵심 요소 10)
21. [한계] write와 brief의 테스트는 스킬 문서만 받은 subagent 안에서 실행했고, AskUserQuestion으로 목적, 분량, 어투 같은 설정을 묻는 흐름과 대화에서 자료나 주제를 요청하는 흐름은 실행해 보지 못했다. (L3, S26, 용어: AskUserQuestion)

## 제외한 사실
- S1 개발 기록의 날짜(2026년 11월 10일): 개발 기록을 작성한 날짜이고 배포한 날짜인지 자료에 없다.
- S7 write의 독립 점검 범위(1,500자): 네 가지 중 두 가지의 이름이 자료에 없어 내용을 다 쓸 수 없다.
- S18, S19 짧은 글 기준의 이동과 `revise_ko.py`의 `--short`: 핵심 요소 3차에서 제외했다(검사 명령 사이의 판정 차이를 고친 내용이고 분량을 넘었다).
- fact sheet의 분량 값(1,000자, 1,200자): 글의 설정값이라 글에 쓰지 않는다.
- S21 분포 항목(문장 길이, 문단, 목록 비중)의 기준치를 가져오지 않은 사실: 독립 점검 반영 뒤 분량을 넘어서 핵심 요소 5차에서 제외했다. write와 brief에서 분포 항목을 어떻게 검사하는지 자료에 없다.
- L5 write와 brief의 구성과 분량 범위가 측정값이 아니라는 사실: 그 구성과 분량 범위가 어떤 값인지 자료에 없어서 핵심 요소 4차에서 제외했다.
- S12 brief의 기본 독자 변경: 개발 중 1차 실행 뒤 수정한 경위이고 독자는 brief가 묻는 값으로 사용 방법을 안다.
- S20 스킬별 허용 표현: 검사 내부의 기준이라 독자가 사용 방법을 바꾸지 않는다.
- S22 표본이 없을 때 판정하지 못하는 항목: S21의 이유를 덧붙이는 내용이다.
- S25 tone_check와 repeats 비교(207쌍): 같은 결과를 다른 명령으로 다시 확인한 사실이다.
- S26~S30 테스트 실행의 글자 수와 시간(5문장, 590자, 27분, 296자, 9분, 338자, 14분, 189자, 3분, 423자, 20분, 500자, 905자, 24분): 설정마다 한 번 실행한 결과이고 변경 내용의 설명을 바꾸지 않는다.
- S31 "저희" 규칙(6개), S32 README 점검, S33 단위 테스트 통과(210개): 개발 중 수정과 확인의 경위다.
- L2 다시 실행하지 않은 수정, L4 genre.md 예 변경: 테스트 실행의 세부 경위이고 독자가 0.5.0을 사용하는 방법을 바꾸지 않는다.
