# K-Writer 0.5.0의 변경 사항: write와 brief 추가, short 모드 삭제

K-Writer 0.5.0에서는 글을 쓰는 write 스킬과 자료를 요약하는 brief 스킬이 추가됐고 techblog의 short 모드가 삭제됐습니다. 어투에는 Plain(해라체)과 사용자가 직접 정한 어투가 추가됐습니다.

write 스킬은 자료나 주제, 목적, 분량, 어투를 사용자에게 받은 뒤 그에 맞는 글을 씁니다. techblog 같은 다른 스킬이 글의 목적, 문체, 구성을 미리 정해 둔 스킬이라면, write는 문체를 미리 정하지 않고 목적도 사용자에게 받는 K-Writer의 기본 스킬입니다. 요청에 자료나 주제가 없으면 write는 대화에서 자료나 주제를 먼저 요청하고, 받지 못하면 작업을 시작하지 않습니다. 자료나 주제를 받은 뒤에는 목적(설명, 설득, 안내, 기록, 직접 입력), 분량, 어투 중 요청에 없는 값을 한 번에 묻고, 정한 목적에 따라 글의 독자와 구성을 정합니다.

brief는 사용자가 전달한 자료나 내용을 자연스러운 한국어로 요약하는 스킬입니다. brief는 분량(한 줄, 한 문단, 자세히)과 어투 두 값만 묻고, 요약을 대화의 답으로 출력하며 `-o`를 붙이면 파일에도 저장합니다. 짧은 글은 이제 techblog의 short 모드 대신 brief로 작성합니다. short 모드에서 사용하던 techblog의 `short` 인자, `lint_ko.py`(문체 검사 스크립트)의 `--source`와 `--terms` 옵션, 원문 대조 항목 F1~F8도 short 모드와 함께 삭제됐습니다.

Plain과 사용자가 직접 정한 어투를 포함해 어느 어투로 요청해도 K-Writer는 합니다체 초안을 먼저 작성하고 초안 문장의 종결부만 바꿔 요청한 어투의 글을 만듭니다. 검사 스크립트에서는 `lint_ko.py`와 `tone_check.py`(어투 검사 스크립트)의 `--tone`에 Plain은 `plain`, 사용자가 직접 정한 어투는 `free`로 지정할 수 있습니다. 다만 `lint_ko.py`는 해라체 글에 섞인 합니다체와 해요체 종결은 검출하지만, 반말 종결("~해", "~야"처럼 해요체에서 "요"를 뺀 종결)은 명사로 분류해서 검출하지 못합니다.

0.5.0에서 수정하기 전과 후의 `lint_ko.py`를 예시 글, eval 글, 평가 기록의 글을 합친 34개 파일에 `--tone default`와 `--tone casual`로 실행해 출력 68개를 비교한 결과, 달라진 부분은 어투 항목 G4.off_tone의 수정 방향 문구 한 줄이었고 항목의 값과 판정은 모두 같았습니다. `--tone auto`로 실행하면 0.5.0의 `lint_ko.py`는 해라체로 쓴 문서 7개를 새로 추가된 `plain`으로 인식해서 수정 전과 다른 출력을 냈습니다.

write와 brief에는 기준 글 표본(검사 항목의 기준치를 측정하는 데 사용하는, 사람이 작성한 같은 종류의 글)이 없어서, 특정 표현의 빈도를 세는 항목 15개의 기준치는 techblog에서 가져온 값입니다. 스킬을 평가할 요청과 자료를 담은 새 eval 케이스 4개는 작성만 했고, `claude plugin eval`과 dogfood(만든 사람이 실제 작업에 직접 사용해 보는 검증)는 아직 실행하지 않았습니다. write와 brief의 테스트는 스킬 문서만 받은 subagent 안에서 실행했고, Claude Code가 선택지로 질문하는 AskUserQuestion 도구로 목적, 분량, 어투 같은 설정을 묻는 흐름과 대화에서 자료나 주제를 요청하는 흐름은 실행해 보지 못했습니다.
