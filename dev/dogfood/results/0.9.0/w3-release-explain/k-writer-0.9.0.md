# K-Writer 0.5.0의 write, brief 스킬 추가와 techblog short 모드 삭제

K-Writer 0.5.0에서는 사용자가 정한 목적, 분량, 어투에 맞춰 글을 쓰는 write 스킬과 자료를 요약하는 brief 스킬이 추가됐고 techblog의 short 모드가 삭제됐습니다. 스킬이 공통으로 사용하는 어투 규칙(core)에도 해라체(Plain)와 사용자가 직접 정한 어투가 추가됐습니다. 문체 검사 스크립트 `lint_ko.py`가 기존 글에 내리는 판정은 합니다체와 해요체 설정에서 0.5.0 이전과 같았습니다.

write는 자료나 주제, 목적, 분량, 어투를 사용자에게 받은 뒤 그에 맞는 글을 쓰는 K-Writer의 기본 스킬입니다. write는 자료나 주제 없이 호출되면 대화에서 먼저 자료나 주제를 요청하고, 받지 못하면 글을 쓰기 시작하지 않습니다. 자료나 주제를 받은 뒤에는 목적, 분량, 어투 중 사용자가 요청에 적지 않은 값을 한 번에 묻습니다. 목적은 설명, 설득, 안내, 기록, 직접 입력 중에서 선택하고 write는 선택한 목적에 따라 글의 독자와 구성을 정합니다.

techblog의 short 모드가 삭제되면서 `short` 인자가 없어졌고 `lint_ko.py`에서도 `--source`와 `--terms` 옵션, 원문 대조 항목 F1~F8이 삭제됐습니다. 0.5.0부터 짧은 글은 short 모드 대신 brief로 작성합니다. brief는 사용자가 요약을 요청한 자료나 내용을 자연스러운 한국어로 요약하는 스킬입니다. brief가 묻는 값은 분량과 어투뿐이고 분량은 한 줄, 한 문단, 자세히 중에서 선택합니다. brief는 요약을 대화의 답으로 보여 주고 `-o`를 붙이면 같은 요약을 파일에도 저장합니다.

새 어투 중 해라체는 문장을 "~다"로 끝내는 어투이고, 사용자가 직접 정한 어투는 사용자가 요청에 적은 대로 문장을 끝내는 어투입니다. 어느 어투로 요청하든 K-Writer는 합니다체 초안을 먼저 쓰고 그 초안의 종결부만 바꿔 요청한 어투의 글을 만듭니다. `lint_ko.py`와 어투 검사 스크립트 `tone_check.py`의 `--tone` 옵션도 두 어투에 해당하는 `plain`과 `free`를 받습니다.

`lint_ko.py`의 기존 판정이 0.5.0에서도 그대로인지는 예시 글, eval 글, 평가 기록의 글을 합친 34개 파일에 수정 전과 후의 스크립트를 `--tone default`와 `--tone casual`로 실행해 확인했습니다. 두 설정의 출력 68개에서 달라진 부분은 어투 항목 G4.off_tone이 출력하는 수정 방향 문구 한 줄뿐이었고 항목의 값과 판정은 모두 수정 전과 같았습니다. 다만 `--tone auto`로 실행하면 `lint_ko.py`가 해라체로 쓴 문서 7개를 0.5.0에서 추가된 `plain`으로 인식해서 출력이 수정 전과 달라졌습니다.

write와 brief에는 검사 기준치를 정할 사람 글 표본이 없어서 `lint_ko.py`에서 특정 표현의 빈도를 세는 항목 15개는 techblog의 기준치를 사용합니다. 또 `lint_ko.py`는 해라체 글에 섞인 합니다체와 해요체 종결은 찾지만 반말 종결은 명사로 분류해서 찾지 못합니다.

0.5.0에서는 플러그인 평가 명령 `claude plugin eval`을 실행하지 않았고 write와 brief용으로 새로 만든 eval 케이스(평가에 사용하는 요청과 자료) 4개는 작성만 했습니다. 설정값을 사용자에게 묻는 흐름과 대화에서 자료나 주제를 요청하는 흐름도 아직 실행해 보지 못했습니다.
