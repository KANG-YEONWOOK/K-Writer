# API 요청 제한 방식을 토큰 버킷으로 바꾼 엔지니어링 노트 요약

공개 API의 요청 제한 방식을 고정 윈도우에서 클라이언트별 토큰 버킷으로 바꾸자 배포 2주 뒤 같은 트래픽 수준에서 게이트웨이 p99 지연이 1,850ms에서 420ms로 줄었습니다. 클라이언트마다 60초에 600건을 허용하던 고정 윈도우에서는 윈도우가 시작될 때마다 제한에 걸린 클라이언트가 동시에 재시도해 초당 최대 부하가 4,800건까지 올랐습니다. 토큰 버킷으로 바꾼 뒤에는 같은 한도에서 초당 최대 부하가 1,400건으로 줄었습니다. 대신 클라이언트가 윈도우 경계에서 한도를 넘길 수 없게 되어 요청 거부율은 2.1%에서 2.6%로 늘었습니다. 다만 이 팀은 활성 클라이언트가 50,000개를 넘는 조건에서는 이 설계를 테스트하지 않았습니다.
