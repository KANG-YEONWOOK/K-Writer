# API 요청 수 제한 방식의 토큰 버킷 전환 요약

공개 API의 클라이언트별 요청 수 제한 방식을 고정 윈도우에서 토큰 버킷으로 바꾸자 배포 2주 뒤 같은 트래픽 수준에서 게이트웨이의 p99 지연이 1,850ms에서 420ms로 줄었습니다. 기존에는 60초 윈도우가 시작될 때마다 제한에 걸렸던 클라이언트들이 동시에 재시도했고, 바꾼 뒤 1초 동안의 최대 요청 수는 4,800건에서 1,400건으로 줄었습니다. 요청 거부율은 2.1%에서 2.6%로 늘었고 버킷 상태를 저장하는 Redis의 CPU 사용률은 8%p 올라갔습니다. 서로 다른 클라이언트들이 동시에 요청을 시작할 때는 토큰 버킷도 효과가 없고 배포 직후에는 여전히 짧게 요청이 몰립니다. 활성 클라이언트가 50,000개를 넘는 환경에서는 이 설계를 테스트하지 않았습니다.
