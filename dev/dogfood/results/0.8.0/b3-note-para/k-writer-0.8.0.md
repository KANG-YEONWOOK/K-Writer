# API 요청 수 제한 방식의 토큰 버킷 전환 요약

공개 API의 요청 수 제한을 고정 윈도우에서 클라이언트별 토큰 버킷으로 바꾸고 2주 뒤 같은 트래픽 수준에서 측정한 게이트웨이 p99 지연은 1,850ms에서 420ms로 줄었습니다. 고정 윈도우에서는 60초 구간이 시작될 때마다 제한에 걸린 클라이언트가 동시에 재시도해 요청이 초당 최대 4,800개까지 몰리며 p99 지연을 높였지만 토큰 버킷에서는 1,400개였습니다. 구간 경계에서 한도를 넘던 요청도 거부되어 거부율은 2.1%에서 2.6%로 늘었고 Redis CPU 사용률은 8%p 올랐습니다. 배포할 때마다 여러 클라이언트가 동시에 요청을 시작해 잠깐 몰리는 요청은 토큰 버킷으로도 막지 못했고 활성 클라이언트가 50,000개를 넘는 환경에서 테스트하지 않았습니다.
