# K-Writer 0.5.0 write, brief 스킬 추가와 short 모드 삭제 요약

K-Writer 0.5.0은 자료를 한국어로 요약하는 brief 스킬과 자료나 주제, 목적, 분량, 어투를 사용자에게 받아 글을 쓰는 write 스킬을 추가했습니다. 두 스킬을 요청한 사용자는 write가 기본 스킬이고 다른 스킬은 글의 목적, 문체, 구성을 미리 정해 둔 스킬이라고 설명했습니다. techblog의 short 모드는 삭제하고 짧은 글은 brief로 작성하기로 했습니다. 새 스킬은 스킬 문서를 작성하지 않은 subagent에게 스킬 문서만 주고 사용자 요청을 실행하게 하는 테스트 실행으로 확인했고 `claude plugin eval`과 dogfood는 실행하지 않았습니다.

write는 자료나 주제가 없으면 대화에서 먼저 요청하고 목적(설명, 설득, 안내, 기록, 직접 입력), 분량, 어투 중 요청에 없는 값을 한 번에 묻습니다. brief는 분량(한 줄, 한 문단, 자세히)과 어투만 묻고 `-o`가 있으면 요약을 파일에도 저장합니다.

core의 어투에는 해라체(Plain)와 사용자가 직접 정한 어투를 추가해 `lint_ko.py`와 `tone_check.py`의 `--tone`이 `plain`과 `free`를 받습니다. 짧은 글 기준은 core의 `rules.json`으로 옮겼고 `lint_ko.py --short`와 `revise_ko.py`의 `check --short`, `audit --short`가 이 기준을 적용합니다. write와 brief는 기준 글 표본이 없어 부정 대구나 번역투도 판정하지 못하므로 특정 표현의 빈도를 세는 lint 항목 15개는 techblog의 기준치를 가져와 사용합니다.

수정 전후의 `lint_ko.py`를 예시 글, eval 글, 평가 기록의 글 34개에 `--tone default`와 `--tone casual`로 실행해 출력 68개를 비교했습니다. 달라진 부분은 이번에 문구를 바꾼 G4.off_tone의 수정 방향 한 줄뿐이고 항목의 값과 판정은 모두 같았습니다.

테스트 실행에서 영어 엔지니어링 노트를 한 문단, 합니다체로 요약한 brief의 요약은 첫 실행에서 5문장 590자였고 문서를 수정한 뒤의 두 번째 실행에서 4문장 296자였습니다. 첫 실행의 요약이 길어진 원인은 기본 독자를 자료 분야의 지식이 없을 수 있는 사람으로 정해 용어마다 설명이 붙은 것과 독립 점검 단계에서 독자 점검이 낸 질문마다 요약에 설명을 추가한 것이었습니다. 그래서 기본 독자를 자료가 대상으로 삼은 독자와 같은 수준의 사람으로 바꿨습니다. 독립 점검은 요약만 읽는 subagent가 읽다가 멈춘 부분을 보고하면 상위 agent가 분량 안에서 수정하는 방식으로 바꿨습니다.

write의 두 번째 실행에서 해라체로 쓴 기록에는 어투 변환이 합니다체 초안의 종결부만 바꾸는 탓에 "저희"와 해라체가 함께 쓰인 문장이 6개 있었습니다. 그래서 조직을 주어로 쓸 때 "우리 팀은"이나 조직의 이름을 쓰도록 genre.md, drafting.md, tone.md를 수정했습니다.

새로 작성한 eval 케이스 4개는 실행하지 않았고 스킬 없이 쓴 글이나 사람이 쓴 글과 비교한 결과도 없습니다. 테스트의 두 번째 실행 뒤에 수정한 "저희" 규칙, 사실 표의 열, brief의 출력 파일 조립은 다시 실행해 확인하지 않았습니다. 테스트 실행을 subagent 안에서 해서 AskUserQuestion으로 설정을 묻는 흐름과 대화에서 자료나 주제를 요청하는 흐름은 실행해 보지 못했습니다.
