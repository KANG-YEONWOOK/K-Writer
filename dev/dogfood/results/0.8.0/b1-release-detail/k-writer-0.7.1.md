# K-Writer 0.5.0 write, brief 스킬 추가와 short 모드 삭제 요약

K-Writer 0.5.0은 요약 스킬 brief와 자료, 목적, 분량, 어투를 받아 글을 쓰는 write 스킬을 추가하고 techblog의 short 모드를 삭제했습니다. 짧은 글은 앞으로 brief로 작성합니다. 스킬 문서만 받은 subagent로 사용자 요청을 1차 실행하고 문서를 수정한 뒤 2차 실행했습니다. brief의 영어 엔지니어링 노트 한 문단 요약은 1차 590자에서 2차 296자로, 회의록 항목 요약은 338자에서 189자로 줄었습니다. 다만 claude plugin eval과 dogfood는 실행하지 않았고 brief와 write의 새 eval 케이스 4개는 작성만 했습니다.

write는 자료나 주제가 없으면 대화에서 먼저 요청하고, 목적(설명, 설득, 안내, 기록 또는 직접 입력), 분량, 어투 중 요청에 없는 값을 한 번에 묻습니다. brief는 분량(한 줄, 한 문단, 자세히)과 어투만 묻고 `-o`가 있으면 대화에 답한 요약을 파일에도 저장합니다. techblog에서는 short 모드와 함께 `short.md`, `short` 인자, `thresholds.json`의 short 설정, lint의 원문 대조 항목(F1~F8) 등을 삭제했습니다. 0.5.0에서 함께 바꾼 내용은 다음과 같습니다.

- core의 어투에 해라체(Plain)와 사용자가 직접 정한 어투를 추가했고, 어느 어투든 합니다체 초안의 종결부만 바꿔 만듭니다.
- 짧은 글 기준을 core의 `rules.json`으로 옮겼습니다.
- write와 brief는 기준 글 표본이 없어서 특정 표현의 빈도를 세는 항목 15개의 기준치를 techblog에서 가져왔고, 문장 길이 같은 분포 항목은 가져오지 않았습니다.
- settings-protocol.md에는 자료나 주제처럼 기본값이 없는 값을 먼저 묻고 받지 못하면 작업을 시작하지 않는 규칙을 추가했습니다.

short 모드 코드를 삭제한 뒤 34개 파일에 수정 전후의 lint를 `--tone default`와 `--tone casual`로 실행했고, 출력 68개에서 항목의 값과 판정은 모두 같았습니다.

1차 실행에서 brief 요약이 길어진 원인은 기본 독자를 "자료 분야의 지식이 없을 수 있는 사람"으로 정해 용어마다 설명이 붙은 것과 독립 점검이 독자 점검의 질문마다 설명을 추가한 것이었습니다. 그래서 brief의 기본 독자를 "자료가 대상으로 삼은 독자와 같은 수준의 사람"으로 바꾸고, 독립 점검은 subagent가 읽다가 멈춘 부분을 보고하고 상위 agent가 분량 안에서 수정하게 했습니다. 감사를 맡은 subagent는 `revise_ko.py`의 `check`와 `audit`가 짧은 글 기준을 적용하지 않는 것을 찾았고, 이 두 명령에는 `--short`를 추가했습니다. write 2차 실행의 글에는 "저희"와 해라체를 함께 쓴 문장이 6개 있어서 조직을 주어로 쓸 때 "우리 팀은"이나 조직 이름을 쓰도록 genre.md, drafting.md, tone.md를 수정했습니다.

테스트는 subagent 안에서 실행해서 AskUserQuestion으로 설정을 묻는 흐름과 대화에서 자료나 주제를 요청하는 흐름은 확인하지 못했습니다. 2차 실행 뒤에 수정한 "저희" 규칙은 다시 실행해 확인하지 않았습니다.
