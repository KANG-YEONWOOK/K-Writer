# 코드 리뷰 방식 변경 제안: 리뷰어 자동 지정과 PR 나누기

리뷰어를 자동으로 지정하고 500줄이 넘는 PR은 나눠서 올리는 방식을 시범 운영할 것을 제안합니다. 3분기 PR 412건 중 131건(32%)은 첫 리뷰까지 24시간 넘게 걸렸고 리뷰 없이 머지된 PR도 18건 있었습니다.

지금은 PR을 올린 뒤 팀 채널에 링크를 올리면 누구든 리뷰하는 방식입니다. 리뷰어를 지정하지 않아 서로 미루기 때문에 첫 리뷰가 늦어진다고 추정합니다. 특히 변경이 500줄 이상인 PR의 리뷰가 늦어졌는데 첫 리뷰까지 24시간 넘게 걸린 PR 131건 중 74건이 500줄 이상이었습니다.

제안하는 방식에서는 PR을 올릴 때 코드 소유자 파일을 기준으로 주 단위 순번에 따라 리뷰어 2명을 자동으로 지정합니다. 500줄이 넘는 PR은 올리기 전에 나누고, 나눌 수 없으면 PR 설명에 이유를 적습니다.

시범 운영은 12월 1일부터 12월 31일까지 결제 서비스 저장소에서만 합니다. 결과는 첫 리뷰까지 걸린 시간의 중앙값과 24시간을 넘긴 PR의 비율로 확인합니다. 3분기의 중앙값은 9.5시간이었습니다.

순번에 따라 휴가 중인 팀원이 리뷰어로 지정될 수 있습니다. 리뷰어 자동 지정이 아직 휴가 캘린더와 연동되어 있지 않아서 시범 운영 기간에는 리뷰어를 수동으로 바꿔 지정합니다.

시범 운영에는 저장소 설정을 변경할 권한이 필요하고 이 권한은 인프라팀에 요청하면 하루가 걸립니다. 시범 운영을 승인할지 11월 25일(수)까지 결정해 주세요.
