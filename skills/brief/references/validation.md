# 점검과 출력: 4~7단계

합니다체 요약 초안(`<이름>.draft.md`)을 작성한 뒤 이 문서 전체를 읽고 4~7단계를 수행한다. 아래 `references/`와 `scripts/` 경로는 스킬 루트 기준이다.

요약은 대부분 본문이 공백 제외 1,500자 미만이다. 이런 요약에는 이 문서의 모든 문체 검사와 `revise_ko.py`의 `check`, `audit`에 짧은 글 기준(`--short`)을 붙인다. 본문이 1,500자 이상인 요약에만 `--short`를 제외한다.

### 4. 요약 점검

1. 문체 검사를 실행한다(`--tone default`, `--facts "<이름>.facts.md"`, `--short`).
2. 문체 검사 결과의 GATE와 FAIL 항목은 반드시 수정한다. WARN이 2개 이하(짧은 글 기준을 적용하지 않았으면 3개 이하)면 통과다.
   - GATE, FAIL, WARN, 한국어 점검 후보 중 검출된 항목이 하나라도 있으면 `references/ai-patterns.md`의 "수정 절차", 그 항목의 섹션, "과교정하지 않기"를 읽고 수정 방법을 찾는다. 검출된 항목이 없으면 ai-patterns.md를 읽지 않는다.
   - 검출된 구절을 삭제해도 정보(사실, 수치, 조건)가 줄지 않으면 삭제하고 정보가 있으면 그 정보를 직접 쓰는 문장으로 바꾼다. 검출된 표현을 같은 수사 기법의 다른 표현으로 바꾸지 않는다.
   - 수치, 날짜, 고유명사는 바꾸지 않는다. 자료가 추정한 내용을 단정으로 바꾸지 않는다.
   - `A15.unknown_numbers`는 fact sheet에 없는 수치다. 자료에서 그 수치를 확인해 fact sheet에 적거나 요약에서 삭제한다.
   - 검출된 문장만 편집 도구로 바꾸고 다시 검사한다. PASS가 될 때까지 최대 3회 반복한다.
3. 문체 검사 결과의 점검 후보("단독 읽기 점검 후보", "서술어 반복 점검 후보", "한국어 점검 후보", "용어 설명 점검 후보")에 나온 문장을 모두 읽는다. 검출된 표현이 ai-patterns.md의 "과교정하지 않기"에 있는 용법이면 그대로 둔다. "용어 설명 점검 후보"의 용어는 genre.md의 "용어"에 따라 설명 없이 쓰기로 한 용어면 그대로 둔다.
4. 요약의 문장을 하나씩 fact sheet의 사실 표와 대조한다. 요약은 문장이 적으므로 모든 문장을 대조한다.
   - 수치와 날짜: 값, 단위, 무엇을 측정한 값인지, 조건, 비교 대상이 사실 표의 원문 표현과 같은가
   - 주체: 누가 한 일인지, 누가 맡은 일인지, 누구의 주장인지가 자료와 같은가
   - 서술어가 말하는 일: 결정했는지 논의 중인지, 끝났는지 진행 중인지, 없어졌는지 줄었는지가 자료와 같은가
   - 관계: 두 사실을 이은 원인, 대조, 순서가 자료가 밝힌 관계인가. 문장을 합치면서 자료에 없는 인과가 생기지 않았는가
   - 범위와 강도: "모두", "~뿐", "대부분"이 자료의 표현인가. 자료의 추정이 단정으로, 일부가 전체로 바뀌지 않았는가
   - 조건과 예외: 결론의 범위를 바꾸는 조건이나 예외가 자료에 있는데 요약에서 빠지지 않았는가
   - 덧붙인 내용: 문장마다 대응하는 사실 표의 행이 있는가. 행이 없는 평가, 조언, 전망은 삭제한다.
5. 요약의 구성과 분량을 점검한다.
   - 첫 문장이 fact sheet 맨 위의 핵심 주제를 말하는가. 자료가 무엇을 다루는지만 말하고 결론이 없으면 결론으로 다시 쓴다.
   - 문체 검사 결과 첫 줄의 글자 수와 문장 수가 genre.md의 "분량별 형식"에서 정한 범위 안인가. 넘으면 핵심 주제와 관련이 가장 적은 사실부터 제외한다. 주어, 목적어, 수치의 조건을 삭제해서 분량을 맞추지 않는다.
   - 공백을 포함해 120자를 넘는 문장이 있으면 나누고, 나눠서 문장 수가 분량을 넘으면 사실을 줄인다.
   - 요약에 자료를 소개하는 말, 사용자에게 하는 말, 인사, 요약을 시작한다는 말이 없는가
6. `references/rubric.md`의 "판정" 표의 J1~J8로 요약을 읽고 점검한다. 점수는 파일에 저장하지 않는다. 0점인 항목이 있거나 평균이 1.6 미만이면 해당 문장을 수정한다.

### 5. 독립 읽기 점검

요약을 쓴 agent는 자료를 읽은 상태라서 요약에 빠진 주어나 비교 대상을 이미 아는 내용으로 채워 읽고, 자기가 쓴 어색한 문장을 자연스럽다고 판단하기 쉽다. 그래서 초안을 작성한 대화를 상속하지 않는 subagent 하나가 자료 없이 요약만 읽는다. 이 subagent는 요약을 수정하지 않고 읽다가 멈춘 부분만 보고한다. 수정은 fact sheet를 가진 상위 agent가 분량 안에서 한다.

reader-check.md와 revision.md는 긴 글의 독립 점검 절차라서 brief는 사용하지 않는다. korean-review.md는 아래 3에서 지적된 문장의 수정 방법을 찾을 때만 읽는다.

1. 후처리 시작 명령(`revise_ko.py start "<이름>.draft.md"`)으로 점검 전 초안 복사본을 만든다. 이 명령이 함께 만드는 반복 후보 파일은 사용하지 않는다.
2. subagent 하나를 띄우고 끝날 때까지 기다린다. 기다리는 방법은 runtime.md의 "후처리 context"를 따른다. prompt는 아래 문단을 사용하고 `<...>`를 실제 절대 경로나 값으로 바꾼다. fact sheet와 자료의 경로, 자료 내용, 요약을 쓰며 내린 판단은 prompt에 포함하지 않는다.
   > `<이름>.draft.md`는 어떤 자료를 요약한 한국어 글이다. 이 파일 하나만 읽고 다른 파일, 웹, 자료는 찾지 않는다. 파일은 수정하지 않는다. 독자는 "<fact sheet의 독자 줄>"이다. 이 독자의 입장에서 요약을 문장마다 읽고 아래 다섯 가지에 해당하는 부분을 모두 찾는다. (1) 무엇에 대한 문장인지, 누가 한 일인지 알 수 없는 문장. (2) 수치가 무엇을 측정한 값인지, 무엇과 비교한 값인지 알 수 없는 문장. (3) 두 가지 의미로 읽히거나 한 번 읽어서는 의미가 들어오지 않아 다시 읽은 문장. (4) 사람이 쓴 한국어 글에 그대로 실리면 어색한 표현. 서술어마다 주어, 목적어와 이어 읽어서 영어로 되돌려 옮겨야만 의미가 통하는 조합(예: "문제가 열렸다"), 그 분야에서 사용하지 않는 번역어, 사람이 쓴 글이 다른 단어로 부르는 표현(예: version을 "판"으로, test를 "시험"으로 쓴 표현), 번역투("~에 의해", "~를 가지고 있다")가 여기에 해당한다. (5) 이 독자가 모를 용어인데 설명도 없고 풀어 쓰지도 않은 용어. 요약은 짧은 글이라서 자료의 모든 내용을 담지 않는다. 더 알고 싶은 내용이 아니라 지금 있는 문장을 이해하는 데 방해가 되는 부분만 적는다. 자연스러운 문장을 다른 표현으로 바꾸자는 제안은 적지 않는다. 결과는 `번호 | 문장(그대로 인용) | 해당하는 번호 | 무엇을 알 수 없거나 어색한지` 표로 보고하고, 해당하는 부분이 없으면 없다고 보고한다. 마지막에 이 요약이 말하는 핵심을 한 문장으로 적는다.
3. 상위 agent는 보고의 행마다 수정할지 정한다.
   - subagent가 적은 "핵심 한 문장"이 fact sheet의 핵심 주제와 다르면 요약의 첫 문장이 결론을 전하지 못한 것이다. 첫 문장을 다시 쓴다.
   - (1), (2), (3)에 해당하는 문장은 fact sheet에서 빠진 주어, 측정 대상, 비교 대상을 찾아 그 문장에 넣거나 문장을 다시 쓴다. fact sheet와 자료에 없는 내용으로 채우지 않는다.
   - (4)에 해당하는 표현은 `references/korean-review.md`의 "유형과 수정 방법"에서 해당하는 유형의 섹션을 읽고 그 방법으로 수정한다. 서술어가 주어, 목적어와 어울리지 않으면 유형 C, 그 분야에서 사용하지 않는 번역어면 유형 D, 번역투면 유형 G, 사람이 쓴 글이 다른 단어로 부르는 표현이면 유형 U다. "수정하지 않는 표현"에 있는 표현이면 그대로 둔다.
   - (5)에 해당하는 용어는 genre.md의 "용어"에 따라 풀어 쓰거나 한 구절로 설명한다. 자료가 설명 없이 사용한 용어이고 독자가 기본 독자면 그대로 두고 이유를 보고에 적는다.
   - 수정해서 분량이 genre.md의 "분량별 형식"에서 정한 범위를 넘으면 핵심 주제와 관련이 가장 적은 사실을 제외한다. 설명을 추가하려고 문장을 늘리지 않는다.
   - 수치, 날짜, 고유명사, 추정의 강도는 수정하면서 바꾸지 않는다.
4. `revise_ko.py check "<이름>.draft.md" --short`를 실행한다. 종료 코드가 1이면 출력의 Gate, FAIL, 나빠진 항목, 초안에만 있는 수치와 새로 생긴 수치를 확인해 수정한다. 출력의 "바뀐 문장이 25%를 넘었다"는 안내는 긴 글을 위한 것이므로 요약에서는 따르지 않아도 된다. 대신 바꾼 문장마다 4단계의 4를 다시 수행해 사실 표와 대조한다.
5. 문체 검사를 4단계의 1과 같은 옵션으로 다시 실행한다. 이 결과가 점검을 마친 요약의 판정이다.
- 독립 subagent를 사용할 수 없으면 요약을 쓴 agent가 2의 다섯 가지를 문장마다 직접 확인한다. 이 경우 독립 점검을 했다고 보고하지 않고 직접 점검했다고 보고한다.

### 6. 어투 적용 (어투가 Default가 아닐 때)

1. `references/tone.md`를 읽는다.
2. 점검을 마친 합니다체 초안의 문장마다 종결부(마지막 1~2 어절)만 바꾼다. Casual은 tone.md의 "Default와 Casual 대응표", Plain은 "Plain 종결(해라체)", 직접 입력한 어투는 "사용자가 직접 정한 어투"를 따른다. 문장의 내용, 주어, 수치는 바꾸지 않고 문장을 나누거나 합치지 않는다. 종결부는 문장마다 읽고 바꾸며 정규식이나 스크립트로 일괄 치환하지 않는다.
3. 바꾼 요약은 `<이름>.answer.md`에 본문만 저장한다.
4. 어투 검사를 실행한다. 인자 순서는 합니다체 초안, 어투를 바꾼 요약이다. Plain이면 `--tone plain`, 직접 입력한 어투면 `--tone free`를 붙인다. FAIL이 나온 문장은 종결부만 다시 수정한다.
5. 어투를 바꾼 요약에 문체 검사를 목표 어투(`--tone casual`, `--tone plain`, `--tone free`)와 `--facts`, `--short`로 실행한다. 어투 항목(G4, T.*)과 변환한 종결부에서 생긴 숫자 뒤 조사(G10)가 검출되면 수정한다. 직접 입력한 어투는 lint가 종결을 판정하지 않으므로 변환한 문장을 모두 읽어 종결이 섞이지 않았는지 확인한다.

### 7. 출력하고 보고하기

- 최종 본문은 어투가 Default면 점검을 마친 초안(`<이름>.draft.md`)이고 그 밖의 어투면 `<이름>.answer.md`다. `-o`가 있으면 출력 파일에 genre.md의 "분량별 형식"대로 제목 줄, 최종 본문, 자료 줄을 차례로 저장한다. 출력 파일에는 문체 검사를 다시 실행하지 않는다.
- 최종 요약의 조건은 Gate 위반 0, FAIL 0이고 분량이 정한 범위 안인 것이다. 조건을 맞추지 못한 항목이 있으면 그 항목을 보고에 적는다.
- 대화에 최종 본문을 그대로 보여 준다. 요약 앞에 인사나 소개 문장을 붙이지 않는다.
- 요약 아래에 보고를 세 줄 안팎으로 짧게 쓴다. 보고에는 설정값(독자, 분량, 어투)과 값마다 출처(요청, 사용자 선택, 기본값), 본문 글자 수, 저장 경로(`-o`가 있을 때), 문체 검사 판정, 독립 읽기 점검 방식(독립 subagent 또는 직접 수행)과 그 점검으로 수정한 문장 수를 쓴다.
- 사용자가 확인할 내용이 있을 때만 보고에 따로 쓴다. 읽지 못한 자료의 범위, 자료끼리 값이 달랐던 부분, 자료의 표현이 여러 의미로 읽혀 한쪽으로 옮긴 부분이 여기에 해당한다. 분량 때문에 제외한 내용은 사용자가 요청할 때만 알려 준다.
- `--keep-work`가 없으면 이번 실행에서 만든 작업 파일만 작업 파일 삭제 명령으로 삭제한다. 입력 자료와 `-o`로 저장한 요약은 작업 파일이 아니다.
