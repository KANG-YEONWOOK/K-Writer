# 점검: 검사, 독립 점검, 수정한 부분 확인

이 문서는 합니다체 초안을 쓴 뒤에 하는 점검의 방법이다. 스킬의 작업 문서가 정한 시점에 읽고, 점검의 순서와 스킬마다 다른 대조 항목은 그 작업 문서를 따른다. 점검은 글 전체를 대상으로 두 번만 한다. 검사 스크립트가 글 전체를 한 번 검사하고, 글을 쓰지 않은 subagent가 글 전체를 한 번 읽는다. 그 뒤에는 수정한 문장과 그 앞뒤 세 문장만 다시 확인한다. 이미 확인한 문장은 글을 수정할 때마다 다시 검사하거나 다시 읽지 않는다.

점검 대상은 합니다체 글이다. 어투가 Default면 출력할 글이고 그 밖의 어투면 Default 초안이다. 검사 명령을 실행하는 방법과 `<스킬 절대 경로>`는 [runtime.md](runtime.md)를 따른다.

## 검사 명령

검사에는 아래 명령 하나를 사용한다.

```
python3 "<스킬 절대 경로>/scripts/check_ko.py" "<점검 대상>"
```

- 처음 실행하면 글 전체를 검사하고, 검사한 글의 복사본을 점검 대상과 같은 폴더의 `<점검 대상 이름>.checked.md`에 저장한다.
- 글을 수정한 뒤 다시 실행하면 복사본과 달라진 문장, 헤딩, 표의 행만 검사한다. 글 전체의 판정, 반드시 수정할 항목(GATE, FAIL), 바뀐 문장에서 검출된 표현, 없어진 수치와 새로 쓴 수치, 바뀐 부분과 그 앞뒤 세 문장을 출력한다. 그다음 지금 글을 새 복사본으로 저장하므로 다음 실행은 그 뒤에 수정한 부분만 검사한다.
- 글과 같은 폴더에 fact sheet(`<이름>.facts.md`)가 있으면 글의 수치를 fact sheet와 대조한다. 본문이 공백 제외 1,500자 미만이면 짧은 글 기준을 적용한다. 두 가지 모두 옵션 없이 자동으로 적용된다.
- 글 전체를 다시 검사해야 할 때만 `--all`을 붙인다.

## 검사 결과 수정하기

1. GATE와 FAIL 항목은 반드시 수정한다. 판정이 PASS면 통과다. PASS는 GATE와 FAIL이 없고 WARN이 3개 이하(짧은 글 기준에서는 2개 이하)라는 의미다.
2. 검출된 문장마다 그 구절을 삭제해도 되는지 확인한다. 삭제해도 정보(사실, 수치, 조건, 독자가 할 일)가 줄지 않으면 삭제하고, 정보가 있으면 그 정보를 직접 쓰는 문장으로 바꾼다. 주어, 목적어, 비교 기준, 기한, 수치가 가리키는 대상은 정보이므로 삭제하지 않는다. WARN 항목은 이 방법으로 삭제할 수 있는 문장만 수정한다.
3. 수정 방법은 출력의 "수정 방향"을 따른다. "수정 방향"만으로 수정할 수 없는 항목만 [ai-patterns.md](ai-patterns.md)에서 그 항목의 섹션을 읽는다. 섹션은 runtime.md의 섹션 읽기 명령으로 읽는다(예: `section.py ai-patterns.md "G6"`). 검출된 표현이 그 문서의 "과교정하지 않기"에 있는 용법이면 수정하지 않는다.
4. 점검 후보(CHECK)는 판정에 반영되지 않는다. 후보로 출력된 문장을 읽고 출력에 적힌 기준에 해당하는 문장만 수정한다. 처음 나온 용어의 설명은 style-guide.md의 "처음 나오는 용어와 중심 대상 설명"을, 바꾼 내용이나 값이 빠진 문장은 "바꾼 일과 정한 값의 내용 쓰기"를 따른다.
5. 수정할 때 아래를 지킨다.
   - 검출된 표현을 같은 수사 기법의 다른 표현으로 바꾸지 않는다.
   - 수치, 날짜, 고유명사, 인용은 바꾸지 않는다. 자료가 추정한 내용을 단정으로 바꾸지 않는다.
   - 값이 기준치 안으로 들어오면 수정을 멈춘다. 사람이 쓴 글에도 있는 표현까지 0으로 줄이지 않는다.
   - 검출된 문장만 편집 도구로 수정한다. 전체 바꾸기와 일괄 치환은 사용하지 않는다.
   - 문장 부호(G6)는 검출된 위치마다 용법을 구분해서 수정한다. 숫자 뒤 조사(G10)는 출력에 나온 조사로 수정한다.
6. 수정한 뒤 검사 명령을 다시 실행한다. 이번에는 수정한 문장만 검사한다. 판정이 PASS가 될 때까지 반복하되 세 번을 넘기지 않는다. 세 번 수정해도 남은 항목은 결과 보고에 적는다.

## 독립 점검

글을 쓴 agent는 자료를 읽은 상태라서 글에 빠진 설명을 알아차리기 어렵다. 그래서 초안을 작성한 대화를 상속하지 않는 subagent 하나가 글만 읽고 [independent-review.md](independent-review.md)의 항목을 찾아 보고한다. 이 subagent는 글을 수정하지 않는다. 독립 점검은 글 하나에 한 번만 한다.

1. 검사 결과의 "용어 설명 점검 후보"에 나온 용어 이름과, 읽고도 수정할지 정하지 못한 점검 후보의 줄 번호를 모은다.
2. subagent 하나를 띄우고 끝날 때까지 기다린다. prompt는 아래 문단을 사용하고 `<...>`를 실제 값으로 바꾼다. fact sheet와 자료의 경로, 자료의 내용, 글을 쓰면서 내린 판단은 prompt에 포함하지 않는다.
   > `<점검 대상의 절대 경로>`는 어떤 자료를 바탕으로 쓴 한국어 글이다. 먼저 `<스킬 절대 경로>/references/independent-review.md`를 읽고 그 절차대로 이 글을 점검한다. 이 두 파일과 글에 실린 그림만 읽고 다른 파일, 자료, 웹은 찾지 않는다. 글은 수정하지 않는다. 독자는 "<독자>"다. 글의 목적은 "<목적>"이다. 기준 글은 <스킬이 정한 기준 글>이다. 다음 용어와 줄은 반드시 확인한다: <용어 이름과 줄 번호. 없으면 "없음">. 결과는 independent-review.md의 "보고" 형식으로 답한다.
3. subagent를 사용할 수 없으면 글을 쓴 agent가 independent-review.md의 "찾는 항목" 표로 글을 직접 읽는다. 이 경우 결과 보고에는 점검 방식을 독립 점검이 아니라 직접 점검으로 적는다.

## 지적 반영하기

1. 보고의 "핵심 한 문장"이 fact sheet의 핵심 주제와 다르면 제목과 첫 문단이 핵심을 전하지 못한 것이다. 제목과 첫 문단을 다시 쓴다.
2. 표의 행마다 수정할지 정한다. 수정하지 않는 행은 이유를 한 구절로 정해 두고 결과 보고에 쓴다. 자료에 답이 없는 질문, 독자가 아는 용어, "과교정하지 않기"에 있는 표현이 수정하지 않는 이유가 된다.
3. 항목 번호에 따라 아래 방법으로 수정한다. 유형별 수정 방법이 필요하면 [korean-review.md](korean-review.md)에서 해당하는 유형의 섹션만 읽는다(예: `section.py korean-review.md "C" "V"`). 지적된 문장을 fact sheet만 보고 바로 수정할 수 있으면 읽지 않는다.

   | 번호 | 수정 방법 |
   |---|---|
   | 1 설명이 없는 용어 | fact sheet 용어 표의 설명을 처음 나온 위치에 쓴다. 용어 표에 없으면 자료에서 찾고, 자료에도 없으면 style-guide.md의 "처음 나오는 용어와 중심 대상 설명"의 조건에 맞는 일반 지식으로 쓴다 |
   | 2 대상을 찾을 수 없는 문장, 3 내용이 빠진 문장 | fact sheet에서 빠진 주어, 대상, 비교 기준, 바꾼 내용과 값을 찾아 그 문장에 쓴다. 빠진 기준값은 비교되는 수치 바로 앞이나 뒤에 쓴다. 지적된 구절만 삭제하거나 더 넓은 의미의 명사로 바꾸지 않는다 |
   | 4 다시 읽은 문장 | 그 문장이 말하려던 사실을 fact sheet와 자료에서 다시 확인한 뒤 다시 쓴다(유형 F) |
   | 5 어색한 표현 | 서술어가 주어, 목적어와 어울리지 않으면 유형 C, 번역어면 유형 D, 번역투면 유형 G, 기준 글이 다른 단어로 부르는 표현이면 유형 U를 읽는다. "수정하지 않는 표현"에 있는 표현은 그대로 둔다 |
   | 6 이어지지 않는 문장 | 짧은 선언형 문장은 유형 V, 문단의 내용과 맞지 않는 문장은 유형 W, 같은 서술어의 반복은 유형 S를 읽는다. 같은 조건이나 비교 기준의 반복은 [revision.md](revision.md)의 해당 항목을 읽는다 |
   | 7 제목과 헤딩 | style-guide.md의 "제목과 헤딩"대로 명사나 명사형으로 끝내고 그 섹션이 다루는 대상과 결과를 쓴다 |
   | 8 목적에 필요한데 없는 정보 | fact sheet와 자료에서 찾아 추가한다 |

4. 수정할 때 아래를 지킨다.
   - 지적이 요구한 만큼만 수정한다. 지적되지 않은 문장은 바꾸지 않는다.
   - 답이 fact sheet와 자료에 없으면 지어내지 않는다. 그 문장을 제외하거나 그대로 두고 결과 보고의 확인할 내용에 적는다.
   - 수치, 날짜, 고유명사, 추정의 강도, 결정 여부와 완료 여부는 바꾸지 않는다. 사실을 수정하거나 추가하는 문장은 fact sheet의 행을 바탕으로 쓰고 그 행의 조건을 생략하지 않는다.
   - 같은 사실(같은 수치, 같은 이름, 같은 일정)을 쓴 다른 문장도 찾아 함께 수정한다.
   - 설명을 추가해서 분량이 정한 범위를 넘으면 핵심 주제와 관련이 가장 적은 사실을 쓴 문장 전체를 제외한다. 주어, 목적어, 조건을 삭제해서 분량을 맞추지 않는다.

## 수정한 부분 확인하기

1. 지적을 반영한 뒤 검사 명령을 실행한다. 출력에는 반영하면서 바뀐 부분과 그 앞뒤 세 문장만 나온다.
2. 바뀐 부분마다 출력 끝의 질문에 답한다. 이때 바뀐 문장을 앞뒤 문맥과 이어 읽고, 출력에 나오지 않은 문장은 다시 읽지 않는다. 새로 쓴 수치와 없어진 수치가 출력되면 fact sheet와 대조한다.
3. 답할 수 없는 문장과 반드시 수정할 항목(GATE, FAIL)을 수정하고 검사 명령을 다시 실행한다. 이번 출력에는 방금 수정한 부분만 나온다. 반드시 수정할 항목이 없고 모든 질문에 답할 수 있으면 점검을 마친다.
4. 독립 점검을 다시 맡기지 않는다. 자료에 근거가 없어서 해결하지 못한 지적은 결과 보고에 적는다.

마지막 검사 명령의 "글 전체 판정"이 점검을 마친 글의 판정이다. 최종 글의 조건은 Gate 위반 0, FAIL 0이다. 문장과 문단의 분포 항목의 WARN은 의도한 형태면 남길 수 있고 남긴 이유를 결과 보고에 적는다.

## 어투 적용하기

어투가 Default가 아닐 때만 한다.

1. [tone.md](tone.md)에서 정한 어투의 섹션을 섹션 읽기 명령으로 읽는다. Casual은 "Default와 Casual 대응표", Plain은 "Plain 종결(해라체)", 직접 입력한 어투는 "사용자가 직접 정한 어투"다. 숫자나 영어 뒤의 조사를 바꿔야 하면 "숫자, 영어, 기호 뒤 조사"도 읽는다.
2. 점검을 마친 Default 초안의 문장마다 종결부(마지막 1~2 어절)만 바꿔 출력할 글로 저장한다. 문장의 내용, 주어, 수치는 바꾸지 않고 문장을 나누거나 합치지 않는다. 제목, 헤딩, 코드, 표, 인용, 명사구 목록은 그대로 둔다. 종결부는 문장마다 읽고 바꾸며 정규식이나 스크립트로 일괄 치환하지 않는다.
3. 어투 검사를 실행한다. 인자 순서는 Default 초안, 어투를 바꾼 글이다. Plain이면 `--tone plain`, 직접 입력한 어투면 `--tone free`를 붙인다.
   ```
   python3 "<스킬 절대 경로>/scripts/tone_check.py" "<Default 초안>" "<어투를 바꾼 글>" --tone casual --lint
   ```
   이 명령은 두 글이 종결부만 다른지 확인하고, 어투를 바꾼 글의 문체 검사도 함께 실행한다.
4. FAIL이 나온 문장은 종결부만 다시 수정한다. 어투 항목(G4, T로 시작하는 항목)과 바꾼 종결부에서 생긴 숫자 뒤 조사(G10)는 어투를 바꾼 글에서 수정한다. 그 밖의 항목이 검출되면 Default 초안의 해당 문장을 수정하고 그 문장만 다시 바꾼다.
5. 직접 입력한 어투는 검사 스크립트가 종결을 판정하지 않는다. 바꾼 문장을 모두 읽어 사용자가 정한 종결이 섞이지 않았는지 확인한다.

## 작업 파일 정리하기

사용자가 작업 파일을 남기라고 하지 않았으면 이번 실행에서 만든 작업 파일만 삭제한다. 입력 자료와 출력할 글은 작업 파일이 아니다.

```
python3 "<스킬 절대 경로>/scripts/tone_check.py" --cleanup "<이름>.facts.md" "<이름>.checked.md" "<이름>.draft.md" "<이름>.draft.checked.md"
```

이번 실행에서 만든 파일만 적는다. 대화로 답하는 스킬이 답변을 저장한 `<이름>.answer.md`도 이 명령으로 삭제한다.
