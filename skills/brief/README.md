# brief

brief는 문서나 웹 페이지 같은 자료와 대화 내용을 자연스러운 한국어로 요약하는 K-Writer 스킬입니다. 글의 목적을 요약으로 정해 둔 스킬이라 분량과 어투만 선택하면 됩니다. 설치 방법과 K-Writer 전체 소개는 [저장소 README](https://github.com/KANG-YEONWOOK/K-Writer#readme)에 있습니다.

## 사용법

Claude Code:

```
/brief report.pdf
/brief https://arxiv.org/abs/2309.06180 한 줄로
/brief meeting-notes.md 결정 사항만 항목으로, 해요체
/brief plain design-doc.md -o design-doc-summary.md --defaults
/brief 위 대화 요약해줘
```

Codex:

```text
$brief report.pdf
$brief https://arxiv.org/abs/2309.06180 한 줄로
$brief meeting-notes.md 결정 사항만 항목으로, 해요체
$brief plain design-doc.md -o design-doc-summary.md --defaults
$brief 위 대화 요약해줘
```

다른 플러그인이나 스킬에 같은 이름의 명령이 있으면 Claude Code에서는 `/k-writer:brief`, Codex에서는 `$k-writer:brief`로 호출합니다. 셸에서 `codex exec`로 실행할 때는 셸이 `$brief`를 변수로 해석하지 않도록 명령 전체를 작은따옴표로 감쌉니다.

brief는 요약을 대화에 바로 보여 줍니다. `-o <경로>`를 붙이면 제목과 자료 줄을 붙여 파일에도 저장합니다. 요약할 자료가 요청에도 대화에도 없으면 어떤 자료를 요약할지 묻습니다. 요청에 분량과 어투가 없으면 요약하기 전에 이 값을 묻습니다. `claude -p`나 `codex exec`처럼 질문에 답할 사람이 없는 환경에서 실행할 때는 `--defaults`를 붙입니다.

| 인자 | 설명 |
|---|---|
| 자료 | 요약할 파일(PDF, 마크다운, 텍스트)의 경로나 URL입니다. 대화에 붙여넣은 텍스트와 앞서 나눈 대화도 요약할 수 있습니다. |
| 분량 | `한 줄로`, `한 문단으로`, `자세히`처럼 문장으로 적습니다. "세 줄로", "500자 이내로"처럼 직접 정해도 됩니다. 기본값은 한 문단입니다. |
| `default`, `casual`, `plain` | 요약의 어투입니다. 차례로 합니다체, 해요체, 해라체("~다"로 끝나는 문장)이고 `합니다체`, `해요체`, `해라체`라고 써도 됩니다. "개조식으로"처럼 다른 어투를 적을 수도 있습니다. 기본값은 합니다체입니다. |
| `-o <경로>` | 요약을 저장할 경로입니다. |
| `--keep-work` | fact sheet(자료의 사실을 모아 둔 파일)와 초안 같은 작업 파일을 삭제하지 않습니다. 작업 파일은 `-o`가 있으면 그 폴더에, 없으면 현재 폴더에 만듭니다. |
| `--defaults` | 분량과 어투 중 요청에 없는 값을 묻지 않고 기본값을 사용합니다. |
| 추가 지시 | "개발자가 아닌 사람이 읽을 요약", "비용 중심으로", "항목으로"처럼 독자, 초점, 형식을 문장으로 덧붙입니다. |

| 분량 | 형식 |
|---|---|
| 한 줄 | 자료의 결론을 한두 문장, 공백 제외 120자 이내로 씁니다. |
| 한 문단 | 3~5문장, 150~300자입니다. 첫 문장에 결론을 쓰고, 이어서 근거가 되는 사실과 수치, 한계나 조건을 씁니다. |
| 자세히 | 800~1,200자입니다. 첫 문단은 한 문단 요약과 같고, 그 뒤에 자료를 크게 나눈 부분마다 한 문단이나 한 항목을 씁니다. |

## 필요한 환경

Python 3.8 이상이 필요합니다. Codex에 PDF를 읽는 기능이 없으면 brief는 오픈소스 PDF 라이브러리 Poppler의 `pdftotext`와 `pdftoppm`을 사용합니다. brief는 필요한 도구를 자동으로 설치하지 않습니다.

## 요약하는 방식

brief의 요약은 자료를 읽지 않은 사람이 요약만 읽어도 자료가 무엇을 말하는지 알 수 있어야 하고, 정한 분량을 넘지 않아야 합니다. 그래서 아래 규칙을 따릅니다.

- 첫 문장에 자료의 결론을 씁니다. "이 문서는 캐시 지연을 다룹니다"처럼 자료가 무엇을 다루는지만 알리는 문장으로 시작하지 않습니다.
- 자료에 있는 내용만 씁니다. 요약하는 쪽의 평가와 조언, 전망은 덧붙이지 않습니다.
- 한 문장에는 사실을 하나나 둘만 씁니다. 분량 안에 다 넣을 수 없으면 문장을 길게 잇지 않고 덜 중요한 사실을 제외합니다.
- 남긴 문장에서는 주어와 목적어를 생략하지 않습니다. 수치에는 무엇을 측정한 값인지와 무엇과 비교한 값인지를 함께 밝힙니다.
- 두 사실을 한 문장으로 이을 때는 자료가 밝힌 관계(원인, 대조, 순서)로만 잇습니다.

기본 독자는 자료를 읽지 않았지만 자료가 대상으로 삼은 독자와 같은 수준의 지식이 있는 사람입니다. 그래서 자료가 설명 없이 사용한 용어는 요약에서도 설명하지 않습니다. "개발자가 아닌 사람이 읽을 요약"처럼 독자를 정하면 그 독자가 아는 단어로 풀어 쓰고, 풀어 쓰느라 길어진 만큼 사실의 수를 줄입니다.

자료의 종류에 따라 남기는 내용이 다릅니다. 예를 들어 논문에서는 핵심 결과와 방법, 다룬 문제와 한계를 남기고, 회의록에서는 결정한 것과 정하지 못한 것, 그리고 담당자와 기한이 정해진 할 일을 남깁니다. 자료 종류별 기준과 예시는 [`genre.md`](references/genre.md)에 있습니다.

## 요약을 쓰는 순서

1. 자료를 처음부터 끝까지 읽습니다.
2. 자료의 결론과 요약에 남길 사실, 수치를 fact sheet에 정리합니다. 요약의 사실은 fact sheet에서만 가져옵니다.
3. 한국어 문장 규칙([`style-guide.md`](references/style-guide.md))을 읽고 합니다체로 요약 초안을 작성합니다.
4. 검사 스크립트 `lint_ko.py`로 초안을 검사하고 요약의 문장을 하나씩 fact sheet와 대조합니다. `lint_ko.py`는 fact sheet에 없는 수치도 찾습니다. 자료를 읽지 않은 독자가 "무엇을 무엇으로 바꿨는지", "누가 어떤 값으로 정했는지"를 되물어야 하는 문장이 있는지도 확인합니다. 분량이 정한 범위 안인지도 확인합니다.
5. 초안을 작성한 대화의 내용을 모르는 subagent가 자료 없이 요약만 읽습니다. 이 subagent는 문장마다 그 문장이 전하는 내용을 자기 말로 다시 적고, 다시 적을 수 없는 문장과 두 가지 의미로 읽히는 문장, 직역처럼 어색한 표현을 찾아 보고합니다. brief를 실행한 agent가 fact sheet를 확인해 지적된 문장을 정한 분량 안에서 수정합니다.
6. 합니다체가 아닌 어투로 요청했으면 점검을 마친 초안의 문장 끝만 그 어투로 바꿉니다.
7. 요약을 대화에 보여 주고 설정값과 검사 결과를 짧게 보고합니다.

글을 다시 읽는 단계에서 techblog는 subagent 네 개를 차례로 실행하지만, brief는 요약이 짧아서 subagent 하나가 요약만 읽고 보고합니다. subagent를 실행할 도구가 없으면 brief를 실행한 agent가 같은 항목을 직접 확인하고 그 사실을 보고합니다.

## 검사 기준

brief는 techblog와 같은 검사 스크립트를 사용합니다. 사람이 작성한 요약의 표본으로 2018~2021년 논문 초록 1,206편을 측정했지만, 초록은 학술 문체라서 그 측정값으로 기준치를 보정하지는 않았습니다. 그래서 항목의 종류에 따라 기준을 다르게 적용합니다.

- 한 번만 나와도 불합격인 항목은 techblog와 똑같이 적용합니다. 자료에 없는 수치, "도움이 되셨길 바랍니다" 같은 챗봇 응답 문구, "단순한 X를 넘어", 가운뎃점과 em dash, 맞춤법 오류가 여기에 해당합니다.
- 부정 대구("A가 아니라 B입니다"처럼 한쪽을 부정한 뒤 다른 쪽을 말하는 문장), 강조 문장, 번역투처럼 특정 표현이 얼마나 자주 나오는지 세는 항목 15개는 techblog의 기준치를 가져와 판정합니다.
- 본문이 공백 제외 1,500자 미만인 요약(대부분의 요약)에는 짧은 글 기준을 적용합니다. 이 기준은 번역투와 과사용 어휘(AI 글에 지나치게 자주 나오는 단어) 같은 네 항목을 1,000자당 비율 대신 개수로 판정하고, 문장 길이 분포나 목록 비중처럼 문장 하나로 값이 크게 달라지는 항목을 제외합니다.
- "범위는 측정값이 아닙니다"처럼 측정값이 아니라고만 쓰고 그 값을 쓰지 않은 문장은 한 번만 나와도 불합격입니다. 이 형태는 논문 초록 1,206편(66만 자)과 기술 블로그 글 368편(240만 자)에서 한 번도 검출되지 않았고, 이전 버전인 0.5.0의 brief가 쓴 요약 3편(2,302자)에서는 2번 검출됐습니다.
- "방식을 수정했습니다"처럼 바꾼 내용을 밝히지 않고 바꿨다고만 쓴 문장과 "수정한 내용 세 가지는"처럼 항목 없이 개수만 쓴 문장은 판정하지 않고 다시 읽을 후보로 출력합니다. 논문 초록 1,206편에서는 바꿨다고만 쓴 문장이 3번, 개수만 쓴 문장이 1번 검출됐고, 0.5.0의 brief가 쓴 요약 3편에서도 3번과 1번 검출됐습니다. 짧은 글 기준에서는 부정 대구가 한 번이면 불합격으로 판정하지 않고 그 문장을 후보로 출력합니다.

항목의 정의는 [`rubric.md`](references/rubric.md)에 있고, 초록을 측정한 방법과 결과는 저장소의 `dev/baseline/brief/README.md`에 있습니다.

## 한계

한 문단의 분량 범위(150~300자)는 논문 초록 1,206편의 문장 길이와 대조했습니다. 초록의 문장은 공백 제외 글자 수의 중앙값이 59자여서 3~5문장이면 177~295자입니다. 대조한 것은 문장 길이뿐이고, 초록 한 편은 중앙값이 512자, 8문장으로 한 문단 요약보다 깁니다. 한 줄 요약과 자세한 요약의 분량 범위, 결론을 첫 문장에 쓰는 구성은 K-Writer 개발자가 정했고 사람이 작성한 요약과 대조하지 않았습니다. 표현의 빈도를 판정하는 기준치는 기술 블로그 글에서 측정한 값입니다. 회의록이나 개발 기록을 사람이 요약한 글은 아직 측정하지 않았습니다.

요약은 자료를 줄인 글이라 조건이나 예외가 빠지면 결론의 범위가 달라집니다. brief는 요약의 문장을 fact sheet와 대조하지만 자료와 다른 내용이 없다고 보장하지는 못합니다. 요약을 근거로 결정하기 전에 수치와 조건을 자료 원문에서 확인해야 합니다.
