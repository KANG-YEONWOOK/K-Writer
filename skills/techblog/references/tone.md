# 어투 규칙: Default(합니다체), Casual(해요체), Plain(해라체)

## 원칙

- 어투는 Default(합니다체), Casual(해요체), Plain(해라체) 세 가지이고 스킬의 settings.md가 이 중 사용할 어투와 기본값을 정한다. settings.md가 허용하면 사용자가 직접 정한 어투(반말, 개조식 등)도 사용한다.
- 내용은 Default 초안에서 정한다. Casual, Plain, 사용자가 직접 정한 어투의 글은 그 초안의 문장마다 종결부(마지막 1~2 어절)만 바꾼 결과다. 어투 선택이 내용 결정에 영향을 주지 않게 하려는 순서다. 아래에서 Casual을 예로 든 원칙은 Plain과 직접 정한 어투에도 똑같이 적용한다.
- 변환하는 Default 초안은 독립 점검(독자 점검, 후처리, 한국어 문장 점검, 수정 후 검토)을 모두 마친 글이다. 독립 점검은 어투 변환 전에 끝내므로 같은 실행에서 나온 Default 글과 Casual 글은 독립 점검에서 수정한 내용까지 같다.
- 문장을 나누거나 합치지 않는다. 문장 순서, 수치, 고유명사, 영문 토큰, 인용, 괄호 내용, 부정 표현은 그대로 유지한다.
- 종결부는 문장마다 읽고 바꾼다. 정규식이나 스크립트로 한꺼번에 치환하지 않는다. 어간에 따라 바뀌는 형태(씁니다 → 써요, 줍니다 → 줘요)와 숫자, 영어, 기호 뒤의 "~이에요"와 "~예요"는 문장마다 정해야 한다. Skill-Techblog 0.9.0의 Codex 테스트 실행에서는 "합니다 → 해요" 정규식 스크립트로 207문장을 바꾸려다 실패하고 원문을 그대로 남겼다.
- 변환한 뒤 `scripts/tone_check.py <draft> <output>`으로 확인한다. Plain 글은 `--tone plain`, 직접 정한 어투의 글은 `--tone free`를 붙인다. 변환 뒤에 수정할 내용이 생기면 종결부만 수정한다. 종결부 밖의 문제는 Default 초안을 수정하고 그 문장을 다시 변환한다.

## 모든 어투에서 똑같이 유지하는 부분

- 헤딩: 명사구("측정 방법"), "~하기"("반복 표현 찾기"), 해라체 질문("반복 표현은 어디서 생길까"), 조건이나 때를 밝힌 구("한국어 서비스에 적용한다면")로 쓴다. 헤딩에는 합니다체나 해요체 종결을 쓰지 않는다.
- 코드 블록, 인라인 코드, 표, 출처의 문장을 그대로 옮긴 인용(blockquote), 링크 텍스트
- 명사구 목록 항목("비교 기준: Reddit 창작 글"). 한 목록은 전부 명사구로 쓰거나 전부 문장으로 쓴다.
- "~할까요?" 질문. 기준 기간(2018~2022년) 합니다체 사람 글 130편의 서술 문장에서도 1.1%(카카오 글 0.7%)를 차지해서 Default와 Casual 모두 허용한다. Plain에서는 "~할까?"로 쓴다.
- 본문에는 "~함", "~음" 같은 개조식 종결을 쓰지 않는다. 사용자가 개조식을 직접 정한 글만 예외다.

## Default 종결(합니다체)

사람 글 baseline(기준 기간 2018-01~2022-11의 합니다체 글 130편, 서술 문장 10,925개)의 분포: ㅂ니다 현재형(합니다, 됩니다) 33%, ~었/했습니다 24%, ~입니다 11%, ~있습니다와 ~없습니다 11%, ~ㄹ 수 있습니다 9%, ~습니다 현재형(같습니다) 6%, ~겠습니다 4%, ~것입니다 2%, "~할까요?" 1%.

쓰지 않는 표현: ~하는 바입니다, ~하고자 합니다(사람 글 0.1%), ~라 할 수 있겠습니다, ~것으로 사료됩니다, 해라체(~다), 개조식(~함, ~음). 이 표현들은 해요체로 자연스럽게 옮길 형태가 없다.

독자에게 하는 요청 "~해 주세요"와 질문 "~인가요?"는 해요체 종결이다. 스킬의 genre.md가 독자에게 직접 말하는 글을 허용할 때만 Default 글에 사용하고, 그 스킬의 thresholds.json이 lint에서 두 형태를 허용한다(`allow_imperative`, `allow_inga_question`). 그 밖의 스킬에서는 Default 글에 사용하지 않는다.

## Casual 종결(해요체)

사람 글 baseline(기준 기간 해요체 글 15편, 서술 문장 920개, 모두 당근)의 분포: ~었/했어요 30%, 현재형 ~해요/~어요 25%, ~있어요와 ~없어요 13%, ~수 있어요 8%, ~이에요/예요 8%, ~ㄹ게요 2.7%, ~죠 2.7%, ~는데요 2.7%, ~세요 2.1%, ~고요 2.1%, ~거예요 1.7%, "~할까요?" 0.7%, ~나요 0.5%, ~거든요 0.3%. 중간 기간(2022-12~2024-12) 해요체 글을 추가한 35편(서술 문장 2,723개)에서는 ~죠 5.0%, ~는데요 3.9%였다. 2026년 토스 순수 해요체 글에서는 ~거든요가 1.7%였다.

### 숫자, 영어, 기호 뒤 조사

"~이에요/예요", "~이었어요/였어요", "~이다/다"와 이/가, 을/를, 은/는, 과/와, 으로/로는 앞말을 한국어로 읽은 소리의 받침에 따라 선택한다. 모든 어투에 적용하는 규칙이다. 앞말이 숫자, 영어, 기호면 글자만 보고 받침을 판단해서 틀리기 쉽다. 사용자 검토에서는 계산한 값 뒤의 조사를 고정해 "최댓값은 0.7717예요", "상관은 0.512이에요"를 출력한 사례가 있었다.

- 숫자는 마지막 숫자를 읽는 소리로 받침을 정한다. 받침이 있는 숫자는 0(영, 십, 백, 천, 만), 1(일), 3(삼), 6(육), 7(칠), 8(팔)이고, 받침이 없는 숫자는 2(이), 4(사), 5(오), 9(구)다.
- "으로/로"는 받침이 ㄹ이면 "로"다. 1, 7, 8 뒤에는 "로", 0, 3, 6 뒤에는 "으로", 2, 4, 5, 9 뒤에는 "로"를 쓴다.
- 숫자 뒤에 단위가 오면 단위를 읽는 소리로 받침을 정한다. 예: 0.8초예요, 15%예요(퍼센트), 120 ms예요(밀리초), 3건이에요, 2명이에요.
- 영어는 한국어로 읽는 소리로 받침을 정한다. 예: API예요(에이피아이), GPU예요(지피유), token이에요(토큰), reporter가(리포터), membrane potential이(포텐셜). 자음 다음에 le로 끝나는 단어는 ㄹ 받침으로 읽는다: Oracle이에요(오라클), Google로(구글). 글자를 하나씩 읽는 약어는 마지막 글자로 정한다. L(엘), M(엠), N(엔), R(알)은 받침이 있고 L과 R은 ㄹ이다: SQL이에요, LLM이에요, SQL로.
- 괄호를 붙인 단어 뒤의 조사는 괄호 앞 단어에 맞춘다. 예: 내부 단편화(internal fragmentation)예요.
- 영어로 읽는 모델 이름과 버전 번호(GPT-3, Llama 2)는 이 규칙에서 제외한다.

lint의 G10.num_particle은 숫자, %, %p 바로 뒤의 조사만 센다. 영어와 단위 뒤의 조사는 이 규칙에 따라 직접 선택한다.

## Plain 종결(해라체)

Plain은 문장을 "~다"로 끝내는 어투다. 보고서, 설명문, 칼럼, 기사처럼 독자를 직접 부르지 않는 글에 사용한다. Default 초안의 종결부를 아래 표대로 바꾼다. Plain 종결의 분포는 사람 글에서 측정한 값이 아직 없어서 비율 기준을 두지 않는다.

| Default | Plain | 예 |
|---|---|---|
| ~했습니다, ~었습니다, ~았습니다 | ~했다, ~었다, ~았다 | 측정했습니다 → 측정했다, 줄었습니다 → 줄었다 |
| ~합니다(동사) | ~한다 | 사용합니다 → 사용한다 |
| ~습니다(받침 있는 동사) | ~는다 | 읽습니다 → 읽는다, 줄지 않습니다 → 줄지 않는다 |
| ~합니다, ~습니다(형용사) | ~하다, ~다 | 필요합니다 → 필요하다, 가능합니다 → 가능하다, 같습니다 → 같다, 짧지 않습니다 → 짧지 않다 |
| ~됩니다 | ~된다 | 저장됩니다 → 저장된다 |
| ~입니다(앞말을 읽은 소리에 받침 있음) | ~이다 | 방식입니다 → 방식이다, 0.7717입니다 → 0.7717이다, token입니다 → token이다 |
| ~입니다(앞말을 읽은 소리에 받침 없음) | ~다 | 서버입니다 → 서버다, 0.512입니다 → 0.512다, 15%입니다 → 15%다 |
| ~였습니다, ~이었습니다 | ~였다, ~이었다 | 0.512였습니다 → 0.512였다 |
| ~것입니다 | ~것이다 | 늘어난 것입니다 → 늘어난 것이다 |
| ~있습니다, ~없습니다 | ~있다, ~없다 | |
| ~ㄹ 수 있습니다 | ~ㄹ 수 있다 | |
| ~겠습니다 | ~겠다 | 정리하겠습니다 → 정리하겠다 |
| ~기 때문입니다 | ~기 때문이다 | |
| ~습니까?, ~할까요?, ~인가요? | ~는가?, ~할까?, ~인가? | 다릅니까? → 다른가?, 줄였을까요? → 줄였을까?, 무엇인가요? → 무엇인가? |
| ~하십시오, ~해 주세요 | ~하기 바란다(요청), ~한다(절차를 적는 지침) | 제출해 주세요 → 제출하기 바란다 |

- 동사는 "~ㄴ다"나 "~는다"로, 형용사와 "이다", "있다", "없다"는 "~다"로 끝낸다. 형용사에 "~ㄴ다"를 붙이지 않는다(필요하다, 중요하다, 가능하다, 다르다, 같다, 크다, 많다). "~지 않습니다"는 앞말이 동사면 "~지 않는다", 형용사면 "~지 않다"로 쓴다.
- 불규칙 활용: 줍니다 → 준다, 봅니다 → 본다, 나옵니다 → 나온다, 씁니다 → 쓴다, 부릅니다 → 부른다, 만듭니다 → 만든다, 압니다(알다) → 안다, 듭니다(들다) → 든다, 깁니다(길다) → 길다, 다릅니다 → 다르다, 빠릅니다 → 빠르다, 쉽습니다 → 쉽다, 어렵습니다 → 어렵다, 돕습니다 → 돕는다, 듣습니다 → 듣는다, 짓습니다 → 짓는다.
- "~이다"와 "~다", 숫자와 영어 뒤의 조사는 위 "숫자, 영어, 기호 뒤 조사"에 따라 앞말을 읽은 소리로 정한다.
- 해라체 문장에는 독자를 높이는 "저", "저희"를 쓰지 않고 "나", "우리"나 조직의 이름을 쓴다. 변환은 종결부만 바꾸므로 Plain으로 낼 글은 Default 초안에서부터 "우리 팀은"이나 조직의 이름을 주어로 쓴다.
- "~하는 바이다", "~라 하겠다", "~것으로 사료된다" 같은 공문 투의 종결과 "~함", "~음" 종결은 쓰지 않는다. "~더라", "~구나", "~네"는 글쓴이가 직접 겪거나 보고 놀랐다는 의미가 되므로 쓰지 않는다.

## 사용자가 직접 정한 어투

스킬의 settings.md가 어투의 "직접 입력"을 허용하면 사용자가 적은 어투(반말, 개조식, 하십시오체 등)로 쓴다. 이 어투도 Default 초안을 독립 점검까지 마친 뒤 종결부만 바꿔서 만든다.

- 사용자가 적은 설명과 예문에서 평서문, 질문, 요청의 종결을 먼저 정하고 글 전체에 같은 종결을 사용한다. 사용자가 예문이나 이전 글을 주었으면 그 글의 종결을 따른다.
- 종결부 밖은 바꾸지 않는다. 주어, 목적어, 조사, 수치, 조건을 그대로 유지한다. 개조식으로 바꿀 때도 조사를 생략하거나 명사만 이어 붙이지 않는다. 예: "배치 크기를 10으로 줄이면 p99 지연이 0.8초로 줄었습니다"는 "배치 크기를 10으로 줄이면 p99 지연이 0.8초로 줄어듦"으로 바꾼다.
- 반말로 바꿀 때도 사실을 전하는 문장의 단어와 수치는 그대로 유지한다. 구어 강조어("완전", "진짜", "엄청")와 느낌표, 이모지는 사용자가 요청한 경우에만 쓴다.
- lint는 이 어투의 종결을 판정하지 않으므로(`--tone free`) 변환한 문장을 모두 읽어 종결이 섞이지 않았는지 확인한다. 어투 검사(`tone_check.py --tone free`)는 종결부 밖이 Default 초안과 같은지만 확인한다.

## 종결이 한쪽으로 몰리지 않게 하기

Casual은 Default 초안의 종결부만 바꾸므로 Casual 글의 종결 다양성은 초안에서 정해진다. 초안의 종결이 "~합니다/~됩니다"에 몰려 있으면 Casual 글도 "~해요/~돼요"만 이어진다. 사람이 쓴 해요체 글은 과거형 30%, 현재형 25%, ~있어요 13%, ~수 있어요 8%, ~이에요 8%로 섞여 있고, 가장 많은 종결이 서술 문장의 52%를 넘는 글은 5% 미만이다(lint A8.ending_top_share).

- 상태, 존재, 가능성, 과거를 나타내는 종결은 자료의 의미와 시제에 맞을 때 사용한다. 분포를 맞추려고 의미를 바꾸지 않는다. `A8.ending_run4`는 서로 다른 현재형 동사도 함께 세는 분포 참고값이며, 실제 인접한 서술어 반복은 `A8.same_predicate_adjacent` 후보를 문맥과 함께 읽어 판단한다.
- 변환할 때 "~해요"가 이어지는 구간에서는 아래 허용 변형의 조건에 맞는 문장을 찾아 ~죠, ~거든요, ~는데요를 사용한다. 변형은 각 4% 이하, 합쳐서 10% 안팎이다. 조건에 맞지 않는 문장에 억지로 사용하지 않는다.

## 허용 변형

해요체 글이 ~어요로만 끝나면 단조롭다. 아래 변형은 측정한 비율(각 4% 이하) 안에서만 사용한다. lint의 T.jyo_ratio, T.geudeun_ratio, T.neundeyo_ratio가 비율을 계산한다.

- ~거든요: Default 문장에 원인 표현(때문, ~므로, ~어서, ~니까)가 있을 때만 사용한다. 원인 표현이 없는 문장에 사용하면 자료에 없는 인과 관계가 생긴다. "이유는 ~때문입니다"처럼 주어가 이미 이유를 말하는 문장에는 사용하지 않는다.
  - D: 쓰기 비율이 높은 서비스에서는 처리량이 15% 떨어졌습니다. 메시지를 더 자주 보내기 때문입니다.
  - C: 쓰기 비율이 높은 서비스에서는 처리량이 15% 떨어졌어요. 메시지를 더 자주 보내거든요.
- ~죠: 앞 문장의 내용에서 바로 나오는 귀결을 다시 말할 때만 사용한다. 새 사실에 사용하면 독자가 이미 안다고 전제하게 된다.
  - D: 배치가 작을수록 보내는 메시지 수도 늘어납니다.
  - C: 배치가 작을수록 보내는 메시지 수도 늘어나죠.
- ~는데요: 다음 문장이 대조나 보충을 이어 갈 때만 사용한다. 문장의 내용은 바뀌지 않는다.
  - D: 배치 크기를 줄이면 지연이 줄어듭니다. 쓰기 비율이 높은 서비스에서는 처리량이 15% 떨어졌습니다.
  - C: 배치 크기를 줄이면 지연이 줄어드는데요. 쓰기 비율이 높은 서비스에서는 처리량이 15% 떨어졌어요.
- 축약: 것은 → 건, 것이 → 게, 것을 → 걸, 이것은 → 이건. tone_check는 같은 어절로 간주한다.

## 사용하지 않는 Casual 표현

- ~더라고요, ~더군요, ~네요: 글쓴이가 직접 겪거나 보고 놀랐다는 의미가 된다. 자료를 정리하는 글에서는 지어낸 경험이 된다(rubric G2).
- ~잖아요: 독자가 이미 안다고 전제한다.
- ~답니다, 반말(~해, ~야), 이모지, 느낌표, "완전", "진짜", "엄청" 같은 구어 강조어
