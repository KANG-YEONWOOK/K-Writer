# write 평가 rubric

write가 쓴 글을 점검하는 기준이다. 검사 항목의 정의와 Gate, policy, 고정 기준은 core에서 복사한 `scripts/rules.json`에 있고 이 스킬이 바꾼 값은 `scripts/thresholds.json`에 있다. lint는 두 파일의 값을 합쳐 판정한다. 항목을 수정하는 방법은 [ai-patterns.md](ai-patterns.md)에 있다.

- 항목 종류
  - **Gate (G)**: 위반 1건이면 불합격이다.
  - **자동 측정 (A, T)**: `scripts/lint_ko.py`가 세고 PASS, WARN, FAIL로 판정한다.
  - **참고 지표 (INFO)**: 값만 보고하고 판정에 반영하지 않는다.
  - **점검 후보 (CHECK)**: 판정에 반영하지 않고 검출된 문장을 "단독 읽기 점검 후보", "서술어 반복 점검 후보", "한국어 점검 후보", "용어 설명 점검 후보", "자료 대조 후보"로 출력한다. 5단계에서 이 문장들을 먼저 읽는다.
  - **판정 (J)**: 글을 읽고 0~2점으로 매긴다.

## 판정 방식

- 합격 조건은 초안과 최종 글에 따로 정한다. 점검 후보(CHECK)는 두 조건 어디에도 포함하지 않는다.
  - 초안([validation.md](validation.md) 5단계): Gate 위반 0, 자동 측정 FAIL 0, WARN 3개 이하(짧은 글 기준에서는 2개 이하), 판정 항목(J1~J10) 평균 1.6 이상이고 0점 없음.
  - 최종 글(6단계 독립 점검 뒤): Gate 위반 0, 자동 측정 FAIL 0, 독립 점검으로 나빠진 AI 문체 항목(G, A1~A7, A10~A15, T) 0. 문장과 문단의 분포 항목(A8, A9, A16, A17)의 WARN은 독립 점검에서 이 글의 독자에게 더 읽기 쉬운 형태를 선택한 결과면 유지하고 이유를 보고한다.
- write에는 기준 글 표본이 아직 없다. 그래서 기준치를 항목의 종류에 따라 다르게 정했다.
  - Gate, policy 항목, 고정 기준(fixed) 항목은 core의 값으로 판정한다.
  - 특정 표현의 빈도를 세는 항목 15개는 techblog가 사람이 쓴 기술 블로그 글로 보정한 기준치를 가져와 판정한다. 부정 대구(A1.np, A1.np_same_para), 연결어미 뒤 쉼표 비율(A2.connective_comma_ratio), 강조 문장(A3.salience), 요약 표현과 문단 끝 요약 문장(A4.gyeolguk, A4.para_end, A4.summary_opener), 과사용 어휘(A5.style_words_per_1k), Claude 번역 표현(A6.calque), 추정 표현 중첩(A7.hedge_boimnida, A7.hedge_stack, A7.see_as), "~되고 있다"(A12), 지시어로 시작하는 문장(A13), 번역투(A14.translationese_per_1k)다. 이런 표현의 빈도는 글의 종류와 관계가 적다고 가정한 임시 기준이다. 가져온 항목의 목록은 `scripts/thresholds.json`의 `borrowed`에 있다.
  - 문장 길이, 문단, 문장당 쉼표 수, 목록과 굵은 글씨의 비중, 세 항목 나열, 질문 비율, 문단 끝 당위문처럼 글의 종류에 따라 달라지는 지표는 판정하지 않고 값만 보고한다(INFO).
  - 목적마다 사람이 쓴 글을 모아 보정하는 방법은 저장소의 `dev/baseline/README.md`에 있다.
- 본문이 공백 제외 1,500자 미만인 글은 짧은 글 기준(`lint_ko.py --short`)으로 검사한다. 이 기준은 1,000자당 비율 항목 중 일부(번역투, 지시어로 시작하는 문장, "~되고 있다", 과사용 어휘)를 개수로 판정하고, 드문 표현은 한 번까지 허용하며, 문장 수가 적으면 값이 크게 달라지는 분포 항목을 제외한다.
- 수정 원칙
  - 기준치를 넘은 항목만 수정하고 기준치 안으로 들어오면 멈춘다. 빈도를 0으로 만드는 것이 목표가 아니다.
  - 검출된 표현을 수사 기법이 같은 다른 표현으로 바꾸지 않는다.
  - 수정한 뒤 다시 검사해서 다른 항목의 값이 늘지 않았는지 확인한다.
  - 수치, 날짜, 고유명사, 인용은 수정 과정에서 바꾸지 않는다.

## write가 core와 다르게 판정하는 항목

write는 사용자가 자기 일을 담은 자료로 공지, 보고, 회고를 쓰는 경우가 있고 독자에게 직접 말하는 글도 쓴다. 그래서 `scripts/thresholds.json`에서 아래 항목을 바꿨다.

| 항목 | core | write | 이유 |
|---|---|---|---|
| G2.experience, G2.exp_ending(직접 겪은 일처럼 말하는 표현) | Gate | 자료 대조 후보(CHECK) | 화자가 사용자나 그 조직이면 자료에 있는 경험은 사실이다. 검출된 문장을 fact sheet와 대조해 자료에 없는 경험만 삭제한다. "~더라고요", "~네요"는 Default와 Casual 어느 쪽의 종결도 아니어서 어투 항목(G4)은 그대로 Gate로 판정한다 |
| G3.chatbot 중 "궁금한 점이 있으면", "원하시면", "추가로 필요하시면" 형태 | Gate | 검사하지 않음 | 안내 글과 메일에서 독자에게 하는 말이다. "물론입니다"와 "요청하신 글" 같은 형태는 그대로 Gate다 |
| G4.off_tone의 Default 글 요청문("~해 주세요")과 질문("~인가요?") | Gate | 어투에 맞는 것으로 판정 | 안내 글에서 독자가 할 일을 알릴 때 사용하는 표현이다 |

## 판정 (J, 0~2점)

5단계에서 글을 직접 읽고 항목마다 점수와 근거 문장을 적는다.

| ID | 항목 | 2점 | 1점 | 0점 |
|---|---|---|---|---|
| J1 | 목적 달성 | 독자가 이 글만 읽고 목적을 이루는 데 필요한 내용이 모두 있다. 선택한 구성에서 자료에 있는 부분이 빠지지 않았다 | 한 가지가 빠졌다 | 둘 이상 빠졌거나 글의 핵심(독자가 할 일, 제안, 결과)이 없다 |
| J2 | 구체성 | 주장과 요청마다 자료의 수치, 날짜, 이름, 방법이 함께 있다 | 평가어만 있는 문장이 1~2개 | 3개 이상 |
| J3 | deletion test | 삭제해도 정보(사실, 수치, 독자가 할 일)가 줄지 않는 문장이 없다. 주어, 목적어, 조건, 수치가 가리키는 대상은 정보로 간주한다 | 1~2개 | 3개 이상 |
| J4 | 구조와 주제 | 제목이 내용을 특정하고, 첫 문단에 글의 핵심이 있고, 본문이 목적에 맞는 순서를 따르고, 마지막 문단이 구체적인 사실이나 독자가 할 일로 끝난다 | 한 가지가 어긋난다 | 두 가지 이상 |
| J5 | 한국어 자연스러움 | korean-review.md의 유형에 해당하는 어색한 문장이 없다 | 1~2개 | 3개 이상 |
| J6 | 어투 품질 | 글 전체가 정한 어투의 종결로 이어지고 공문 투의 종결이나 정하지 않은 구어 표현이 없다 | 어색한 종결이 1~2개 | 3개 이상이거나 어투가 섞였다 |
| J7 | AI처럼 읽히는 문장 | 상투적인 도입과 마무리, 평가만 하는 문장, 같은 문형의 반복이 없다 | 1~2개 | 3개 이상 |
| J8 | 과교정 없음 | 자연스러운 대조, 단서("다만", "정확히는"), 명확성에 필요한 주어와 목적어의 반복이 남아 있다 | 문장이 다소 단조롭다 | 표현을 삭제하느라 내용이나 흐름이 손상됐다 |
| J9 | 문장 완결성 | 문단의 첫 문장과 수치가 있는 문장을 바로 앞 문장과 함께 읽으면 무엇에 대한 내용인지 모두 알 수 있다 | 알 수 없는 문장이 1~2개 | 3개 이상 |
| J10 | 용어 설명 | 독자가 모를 용어와 조직 안에서만 통하는 이름을 처음 나올 때 모두 무엇인지 설명했다 | 설명이 빠졌거나 이름을 번역한 표현뿐인 용어가 1~2개 | 3개 이상이거나 중심 대상의 정의가 없다 |

- J4 구조의 세부 기준은 `genre.md`를 따른다.
- J5는 5단계에서 lint의 한국어 점검 후보와 눈에 띄는 문장으로 판정하고 6단계의 한국어 문장 점검에서 독립 subagent가 문장마다 다시 확인한다.

## 감점하지 않는 표현

사람이 쓴 글에 흔한 표현이다. 이 표현을 삭제하는 것은 과교정이다. 전체 목록은 ai-patterns.md의 "과교정하지 않기"에 있다.

- "~를 통해", "~에 대해", "~을 위해", 진행하다, 수행하다
- "다만", "사실", "정확히는" 같은 단서
- 줄다, 늘다, 만들다 같은 고유어 동사와 사용하다, 측정하다, 설정하다 같은 한자어 동사
- 자료가 그 문장에서 하는 일에 맞춰 선택한 인용 동사(주장합니다, 보고했습니다, 추정합니다)
- 안내 글에서 독자에게 하는 요청과 질문, 맺음말의 문의 안내
